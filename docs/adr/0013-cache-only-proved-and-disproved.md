# The verdict cache stores only Proved and Disproved

Amends ADR 0005. The in-memory cache is keyed by the CheckKey, a hash of the canonical encoding of the flattened net plus the canonical property (IDs, capacities, `when_full`, arc weights, initial marking and final predicate; never layout or display names), computed by the worker from the net it actually explored. Only Proved and Disproved are stored under their key, because they are facts about that net. An Unknown depends on the budget, the cancel flag or a bug, so it is kept per property for display only and is never served from the cache; a key whose last verdict was Unknown is checked again. The cache holds the net-level verdict, not rendered replay frames, so a cached Disproved shown after a rename or an undo uses current names; it is bounded as an LRU by bytes. A fitness test asserts that every semantic mutation of a net or property changes the key, and an invariance test asserts that a model built in another insertion order, rebuilt from its files, or taken through an undo-redo cycle gives the same key, so staleness is never spurious. A running check is still cancelled only when the key of its property disappears from the current set and no queued request needs it; a key restored by undo with no cached verdict is resubmitted.

Amended by ADR 0018.
