# B1 — Design A: Snapshot core

Author: senior backend developer. Style: Functional core + imperative shell (hexagonal ports for IO in the small).

> Rust owns an immutable, structurally shared Model; gestures are pure Commands producing a new snapshot plus before/after images. A thin Session shell holds the undo stack of snapshots, the verdict cache, the job registry and IO ports. The UI holds a patch-fed mirror of the open view.


## 1. Idea
The Rust core owns the model as an immutable, structurally shared value. A gesture is a `Command`; a pure function turns `(Model, Command)` into a new `Model` plus a `Change` (before/after images of the touched entities). Lowering, CheckKey, scan, file rendering and replay are all pure functions of a `Model` value. A thin imperative shell (`engine::Session`) holds the current snapshot, the undo stack of snapshots, the verdict cache, the job registry and the IO ports (files, journal, watcher, clock).
**Style:** functional core + imperative shell; the shell's IO sits behind small ports (hexagonal in the small).

## 2. Structure
ADR 0004 unchanged. Arrows mean "depends on".
```
app/ui ──IPC──> app/src-tauri ──> engine ──> model, format, verify, scan
                                  format ──> model        scan ──> model
                                  verify ──> (nothing)    model ──> (nothing)
```
- `model`: domain types on persistent maps (`rpds`/`imbl`), `Command`, `apply`, `validate`. No IO.
- `format`: TOML directory <-> `Model` (canonical writer on `toml_edit`), migrations, journal record codec.
- `verify`: `Net`, net-level `Property`, main explorer, second explorer (own module, shares only `Net`), certificate checker, `replay_net`.
- `scan`: `Rule` trait plus the rule set over `&Model`.
- `engine`: `lower`, `check_key`, `replay_unflattened`, `Session`, `JobRegistry`, watcher. The only crate that does IO.
- `app/src-tauri`: commands -> `Session`; one `Channel<EngineEvent>`; implements engine's `EventSink`.
- `app/ui`: `ipc/` (ts-rs types + hand-written wrappers), `store/` (mirror of the open view), `canvas/` (React Flow), `panels/` (verdicts, findings, inspector), `layout.worker.ts` (elkjs).
Rule: only `engine` and `src-tauri` do IO; only `src-tauri` knows Tauri or tokio. CI enforces this with a `cargo metadata` check.

## 3. Core types and seams
```rust
// model
pub struct Model { elements: HashTrieMapSync<ElementId, Arc<Element>>, relationships: .., layouts: ..<ViewId, Arc<Layout>>, suppressions: .., version: FormatVersion }
pub enum Command { AddElement{..}, SetElement{id, element}, DeleteElement{id}, AddRelationship{..},
                   BindPorts{relationship, from: PortRef, to: PortRef, binding: Binding}, MoveElements{view, positions}, .. }
pub struct EntityChange { key: EntityKey, before: Option<Entity>, after: Option<Entity> } // state-based, idempotent
pub fn apply(m: &Model, c: &Command) -> Result<(Model, Vec<EntityChange>), Rejected>;
// engine
pub fn lower(m: &Model, scope: ElementId) -> Result<Lowered, LowerError>; // Lowered { net: verify::Net, origin: OriginMap }
pub fn check_key(net: &verify::Net, p: &verify::Property) -> CheckKey;     // blake3 over canonical IDs, no names or layout
pub fn replay_unflattened(m: &Model, scope: ElementId, cx: &Counterexample) -> Result<(), ReplayError>; // never calls lower
pub trait ProjectStore { fn read_all(&self) -> io::Result<RawProject>; fn write_atomic(&self, f: &[FileWrite]) -> io::Result<()>; }
pub trait Journal { fn append(&mut self, r: &JournalRecord) -> io::Result<()>; fn reset(&mut self, base: Fingerprint) -> io::Result<()>; }
pub trait EventSink: Send + Sync { fn emit(&self, e: EngineEvent); }
// verify
pub struct Budget { pub deadline: Instant, pub max_bytes: usize, pub cancel: Arc<AtomicBool> }
pub fn check(n: &Net, p: &Property, b: &Budget) -> NetVerdict;          // portfolio: certificates later, then exploration
pub fn explore_simple(n: &Net, p: &Property, b: &Budget) -> NetVerdict; // ADR 0008 second explorer, plain BFS
```
```ts
type Applied = { revision: number; patch: ViewPatch; dirty: boolean };
type EngineEvent = { kind: "checkQueued" | "checkProgress"; property: PropertyId; key: CheckKey; markings?: number; elapsedMs?: number }
  | { kind: "verdict"; property: PropertyId; key: CheckKey; verdict: VerdictDto }
  | { kind: "currentKeys"; keys: Record<PropertyId, CheckKey> } | { kind: "diskChanged"; conflicts: Conflict[] };
type VerdictDto = { kind: "proved"; technique: string; markings: number } | { kind: "disproved"; counterexample: StepDto[] }
  | { kind: "unknown"; reason: string };
```

## 4. Main flows
- **Open project:** `format::load` parses all files and reports dangling references. Then: look up the journal for this project (keyed by canonical path); offer restore if it holds records past the base fingerprint; set `Session { current, saved, undo: [], redo: [] }`; start the watcher; queue checks for every property (ADR 0005). Returns the top view snapshot and the load report.
- **Edit and undo:** a gesture ends in the UI (drag end, not drag move) -> `apply(cmd)`. Lock the session, `model::apply`, push the old `Arc<Model>` on the undo stack, append the change to the journal (fsync). Then recompute CheckKeys only for affected scopes (the element's own scope and its parent view's scope), cancel running checks whose key is gone, unlock, return a `ViewPatch`. Undo swaps snapshots, journals the inverse change and recomputes keys. A cache hit brings the earlier verdicts back as current.
- **Save:** diff `saved` against `current` (`Arc::ptr_eq` per entity), render the changed files, journal `SaveBegin{paths, hashes}`, temp + fsync + rename each, fsync the directory, journal `SaveDone`, reset the journal to the new base. Journal records are after-images, so replaying them on a torn save (some files new, some old) converges.
- **Run a check:** `run_checks(scope)` -> for each property: lower, key, cache lookup; on a miss `registry.submit(key, Arc<Net>, property, origin, budget)`. The worker is a named std thread (`check-<property>`), at most `available_parallelism - 1` at once, FIFO. Its order: `verify::check`; if Proved by exhaustion, `explore_simple` against the same deadline (shared budget). Disagreement gives Unknown "internal disagreement" (logged). Budget out gives Unknown "budget exhausted", never Proved. For Disproved: `replay_net` on the flattened net, then `replay_unflattened` on the model; a failure gives Unknown "internal error". A monitor thread joins the handle; a panic gives Unknown "internal error" (ADR 0006). The monitor then locks the session, inserts into the cache and emits. Cancel sets the flag; the explorer polls it every 1,024 expansions, well inside 1 s.
- **Replay:** a Disproved `VerdictDto` carries the steps in model terms (fired element/transition, marking per element place, elements and relationships involved). The UI steps through them locally with no IPC. If the verdict is stale, steps that refer to deleted elements are dimmed.
- **Scan:** clone the `Arc<Model>` into a worker; `scan::run(&model, &rules)` -> findings tagged with the model's structural hash (stale works like verdicts). Suppressions are model data matched by fingerprint (rule + sorted element IDs).
- **File changed on disk:** notify-debouncer (500 ms, `PollWatcher` fallback) -> `Session::reconcile(paths)`. Files whose content hash equals what we last read or wrote are ignored. A clean entity adopts the disk version as one undoable change (a `git checkout` becomes one entry). A dirty entity that differs on disk becomes a conflict (keep mine / take disk). A parse error is reported, and the in-memory model is kept.

## 5. Concurrency and IPC
- Threads: the Tauri main thread; Tauri's tokio runtime for command dispatch only; `Mutex<Session>` in managed state, held only for apply + journal + key recompute (target < 10 ms at 300 elements; measure) and never during a check or Save rendering; check workers plus one monitor per check; the watcher thread.
- Commands: `open_project`, `apply`, `undo`, `redo`, `save`, `view(id)`, `run_checks`, `cancel_check`, `run_scan`, `subscribe(Channel<EngineEvent>)`. Errors are one tagged enum `{ kind, message }`.
- Memory budget: Rust cannot cap a thread's allocations, so the explorer counts its stored markings itself, and the registry keeps the sum of running budgets under a configured share of RAM. A real OOM aborts the whole app; the journal limits the loss.
- UI store (Zustand): the current view mirror keyed by ID plus its `revision`; `verdicts: Map<PropertyId, {key, verdict}>`; `currentKeys`; `findings`; `dirty`; `replay: {property, step}`; drag state stays in React Flow until the gesture ends. A revision gap triggers a refetch of the view.

## 6. How it grows
- **State machines:** a new `BehaviorModel` variant; `lower` compiles it to a 1-safe net; `OriginMap` gains `Origin::State`, so replay shows state changes. `verify` is untouched.
- **Cross-level composition:** `lower` recurses or abstracts per level; the origin map carries the level path. Same seam.
- **Code import:** a new `import` crate emits `Vec<Command>`, applied as one gesture. Undo and journal come for free.
- **Code proofs (Kani/Verus):** external processes behind a `ProofRunner` port in `engine`; the job registry generalizes to "external run"; outcomes are keyed by an input hash like verdicts.
- **More scan rules:** another `impl Rule` in `scan`. **CLI:** `crates/cli` on `engine` without `Session` (load, lower, check, scan).

## 7. Testing
- `model`: proptest that `apply` then the inverse change gives the original model, and that replaying after-images twice equals replaying them once.
- `format`: round-trip and golden files per format version, plus a migration test per version bump.
- `verify`: the E1 examples; proptest over random bounded nets checking that the main and simple explorers agree; the TAPAAL corpus in CI.
- `engine`: lower and replay against the slice-0 acceptance cases; `Session` on a real temp directory; a kill test (child process killed after N gestures, then restore).
- UI: Vitest on store patch application with `mockIPC`; WebdriverIO smoke test on Linux.

## 8. Trade-offs
- **Strengths:** one source of truth, in Rust; the core is pure and trivially testable; persistent maps make undo nearly free, and the undo stack lines up with the ADR 0005 cache; ADR 0004 is kept as written; the smallest of the three designs.
- **Weaknesses:** the UI holds a mirror of the open view, fed by patches, so there are two copies and patch bugs are possible. Every gesture is an IPC round trip (about a few ms), so drag needs a local optimistic state. The session mutex is coarse. A persistent-map crate is needed (`im` is unmaintained; use `imbl` or `rpds`).
- **Cost for one developer:** slice 0 roughly 6-8 weeks; the lowest total cost across slices 0-5.
- **Main risk:** lowering plus hashing on every edit at 300 elements exceeds the lock budget, or the mirror drifts. Mitigate with a debug-mode full-view comparison after each patch.

## 9. ADR conflicts
None. One clarification for ADR 0004's text: ADR 0008 requires replay on the *unflattened* model, which `verify` cannot see, because it knows nothing of elements. So `verify` keeps plain-net replay, and `engine::replay_unflattened` replays per element through the bindings without calling `lower`.


## Reviews

### By the software architect: 8/10, adopt

- Strengths: One source of truth in Rust. Every domain rule (slug IDs, collision suffix, binding validity, capacity > 0) exists once, and the net that is checked is lowered from the same Model value that Save renders. This is the structural guarantee that 'what was proved' equals 'what is saved'.; State-based EntityChange (before/after images) gives a generic inverse with no hand-written inverse per Command, and an idempotent journal: replaying after-images on a torn Save converges. This is the most robust journal shape of the six designs.; Undo by swapping persistent-map snapshots lines up with ADR 0005: the old snapshot lowers to the old key, so the cache returns the earlier verdict with no extra code. Dirty tracking via Arc::ptr_eq per entity against `saved` is cheap and correct.; replay_unflattened 'never calls lower' is the right instinct for ADR 0008. A Disproved is confirmed by code that does not share the lowering path that produced the net.; The worker pipeline is correct-first: an exhaustive Proved runs explore_simple inside the same budget, disagreement gives Unknown 'internal disagreement', budget out gives Unknown 'budget exhausted', and a panic at join gives Unknown 'internal error'. Proved is never a default path.; Smallest design that meets slice 0. It keeps ADR 0004, the test plan maps onto the slice acceptance criteria (kill test, E1 corpus, TAPAAL), and the CLI drops out of engine without Session.; The memory budget is honest: the explorer counts its own markings and the registry caps the sum, because Rust cannot cap a thread's allocations.
- Risks: Lowering is a single point of failure for wrong Proved. explore_simple runs on the same flattened net, so a flattening bug (for example a dropped fused transition) yields Proved from both explorers. Add independence on the Proved side too: either the simple explorer runs directly on per-element nets plus bindings (no flatten), or a property test checks that the flattened net is behaviorally equal to the composition of OpenNets on random small models.; CheckKey is described as 'blake3 over canonical IDs'. If the key covers only IDs and not arc weights, capacities, the initial marking and the property's full predicate, a cache hit can bring back a Proved for a different net. That is a wrong Proved through the cache. The key must be a hash of the full canonical Net plus Property (IDs instead of names, but every semantic field). Add a fitness test that any semantic mutation changes the key.; Incremental key recompute 'only for affected scopes' can miss a scope. A missed scope shows a stale verdict as current. At 300 elements, recomputing every open property's key per gesture is probably cheap. Start there, or add a debug assertion that the incremental result equals the full recompute.; replay_unflattened sits in engine next to lower, so the two can drift into sharing helpers and lose independence. ADR 0004 also lists 'independent replay' under verify. Put replay on a plain-net OpenNets structure in a crate that cannot import the lowering code.; The watcher, conflict reconcile and journal are described as if they were in slice 0. Slice 0 has a manual Reload and no journal, so build them in slice 1, as C1 does.; The fsync inside Mutex<Session> on every gesture is fine on ext4. Measure it on WSL2 and Windows in the E4 spike before calling it under 10 ms.; Patch-fed view mirror: a revision gap triggers a refetch, which is good. Keep the debug full-view comparison as a permanent dev-build check, not a temporary one.
- ADR fit: Fits ADR 0001 (explicit Save, temp+rename, a journal of after-images, a loader that reports dangling references), ADR 0004 (crate layout unchanged, IO only in engine and src-tauri, tokio only in src-tauri), ADR 0005 (an in-memory cache keyed by CheckKey, undo restores verdicts, only a key change cancels a check), ADR 0006 (named check-<property> threads, join error gives Unknown 'internal error') and ADR 0008 (a second explorer within the shared budget, Disproved replayed unflattened). One divergence goes unflagged: ADR 0004 places 'independent replay' in verify, and B1 splits it into verify (flat) and engine (unflattened). That is acceptable if made explicit in a small ADR 0004 amendment. The glossary is used correctly (verdict, check, budget, stale, finding, suppression). The check_key wording should match ADR 0005's 'hash of the flattened net and the property'.
- Worth keeping: Command -> (Model, Vec<EntityChange>) with state-based before/after images as the one write path. A generic inverse, an idempotent journal, and code import as Vec<Command> applied as one gesture.; Persistent maps (imbl or rpds) as snapshots: O(1) undo, ptr_eq dirty tracking, and Arc<Model> handed to check and scan workers, which satisfies ADR 0006's immutable snapshot.; replay_unflattened must never call lower.; A cargo-metadata CI check that only engine and src-tauri do IO, and only src-tauri knows Tauri or tokio.; Journal SaveBegin{paths,hashes} / SaveDone around the rename sequence, so a torn Save is recoverable.; A kill test: a child process is killed after N gestures, then restored.; Findings tagged with the model's structural hash, so stale works for findings as it does for verdicts.; A ProofRunner port in engine for Kani and Verus, keyed by an input hash like verdicts.
