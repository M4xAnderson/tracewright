# C2 — B: UI-owned document, Rust as a compute service

Author: senior frontend developer. Style: UI-owned model with Rust compute service; unidirectional Flux store in React; pipes and filters for the check pipeline in Rust.

> The Zustand store owns the model and its undo stack. Rust loads, saves, journals, lowers, checks, replays and scans the snapshots it is sent, keeping only the verdict cache and running checks.


## 1. Idea
During a session the model lives in the React app. A Zustand + Immer store holds it, every gesture is a pure TypeScript producer, and undo is Immer inverse patches. Rust is a set of mostly stateless services: load and save TOML, append to the journal, lower and hash, check, replay, scan and watch the disk. The only state Rust keeps is the verdict cache and the running checks.
Style: **UI-owned model with Rust compute service**, a **unidirectional Flux store** in React, and **pipes and filters** for the check pipeline (snapshot → lower → flatten → explore → recheck → report).

## 2. Structure
```
app/ui (owns Model, history, dirty set) ──invoke(snapshot)──> app/src-tauri ──> engine (services)
engine ──> model, format, verify, scan          verify ──> ∅      scan ──> model
```
- UI `app/ui/src/doc/`:
  - `model.ts`: ts-rs types generated from `crates/model`.
  - `gestures.ts`: `(draft, args) => void` for every edit.
  - `ids.ts`: slug plus collision suffix.
  - `rules.ts`: port binding validity and capacity > 0.
  - `history.ts`: inverse-patch stacks.
  - `dirty.ts`: patch path to file key.
- UI `sync/`: journal flushing, check-key refresh, disk-change merge. `features/canvas`, `features/verify`, `features/scan` and `features/inspector` as usual.
- Rust: `model` (types, load/save validation, lowering input), `format`, `verify`, `scan`. `engine` becomes pure services plus `VerdictCache` and `JobRegistry`: no session model and no undo.
- Dependency rule: components read and write `doc` only through `gestures`. Only `sync/` and `ipc/` talk to Rust, and Rust never pushes model state except disk changes.

## 3. Core types and seams
```ts
type Gesture<A> = (d: Draft<Model>, a: A) => void;               // e.g. moveElements, bindPorts, setCapacity
type HistoryEntry = { label: string; redo: Patch[]; undo: Patch[] };
type ScopeSnapshot = { scope: ElementId; elements: Element[]; relationships: Relationship[] }; // scope + children
type CheckKey = { property: PropertyId; hash: string };
type VerdictState = { key: CheckKey; status: "pending" | "current" | "stale"; report?: VerdictReport };
```
```rust
#[command] fn open_project(path: PathBuf) -> Result<Opened /* model, load_report, recovery: Option<Vec<JournalEntry>> */>;
#[command] fn save(files: Vec<FileWrite> /* {key, Element | Layout} */) -> Result<SaveReport>;
#[command] fn journal_append(e: JournalEntry /* seq, label, patches: serde_json::Value */) -> Result<()>;
#[command] fn check_keys(s: ScopeSnapshot) -> Result<Vec<CheckKey>>;
#[command] fn start_check(s: ScopeSnapshot, p: PropertyId, b: Budget, ch: Channel<CheckEvent>) -> Result<RunId>;
#[command] fn cancel(run: RunId);   #[command] fn scan(m: Model) -> Vec<Finding>;
// engine (pure): pub fn lower(s: &ScopeSnapshot) -> Result<(FlatNet, Provenance, OpenNets), LowerError>;
```

## 4. Main flows
- **Open project:** `open_project` returns the whole model (about 2,000 elements, roughly 1–3 MB of JSON, measure in E4). The store hydrates. If the journal has entries, the user is offered recovery, which the UI applies as stored Immer patches.
- **Edit with undo:** a gesture calls `produceWithPatches` and pushes `{redo, undo}`. Dirty file keys are derived from the patch paths, and `journal_append` is called fire-and-forget but strictly ordered. There is no IPC before the canvas updates. Drag stays inside React Flow and one `moveElements` commits on drag stop. Undo applies the inverse patches locally.
- **Staleness:** any non-layout patch synchronously marks the affected scope's verdicts `pending`, so the UI never shows a possibly stale verdict as current. 100 ms later a debounced `check_keys(snapshot)` resolves each to `current` (hash equal, including after undo, from the Rust cache) or `stale`. A running check whose key changed gets `cancel(run)` (ADR 0005).
- **Save:** the dirty file keys are serialized from the store into `save(files)`. Rust validates them with `model` and writes them canonically with temp + rename. Files that succeed leave the dirty set, then `journal_checkpoint`. If validation fails, Save is refused and the user sees the reason (this guards against TS/Rust drift).
- **Check:** `start_check(snapshot, property, budget, channel)` → `lower` → hash → cache hit, or a worker thread `check-<hash8>` that owns the snapshot. The main explorer runs within the budget. An exhaustive Proved is followed by the simple BFS with the remaining budget (they agree: Proved; they disagree: Unknown "internal disagreement"; budget runs out: Unknown "budget exhausted"). A Disproved counterexample is replayed on `OpenNets`; if that fails the verdict is Unknown "internal error". A panic is caught at join and becomes Unknown "internal error". Progress and the verdict arrive over the Channel.
- **Replay:** frames are mapped to element IDs in Rust and stored in `verdicts[p].report.replay`. Stepping is local, highlights use per-element boolean selectors, and an `aria-live` region announces each step. Because the UI owns the model, it can also draw token counts inside the element's Petri net editor without another call.
- **Scan:** `scan(model)` sends the full model (cheap enough for 5 rules). Findings are tagged with the store revision and become stale when it moves. Suppress is a gesture, so it can be undone.
- **File changed on disk:** the Rust watcher re-reads the files and emits `disk-changed {elements, layouts, removed}`. Clean keys are replaced as one gesture that can be undone. Dirty keys open a conflict dialog (keep mine, take disk).

## 5. Concurrency and IPC
- Rust has no session lock: `Mutex<VerdictCache>` (LRU by hash) and `Mutex<HashMap<RunId, Arc<AtomicBool>>>`. Checks run on std threads. tokio exists only in `src-tauri`, and commands are `async` so large snapshots never block the main thread.
- IPC volume moves from gestures to checks: each `check_keys` and `start_check` serializes a scope snapshot (300 children with nets is an estimated 100–500 KB). If profiling shows JSON cost, use `tauri::ipc::Request` raw bodies with MessagePack.
- The UI store holds everything: `doc` (normalized Maps, structural sharing via Immer, so element components subscribe by ID), `history`, `dirty`, `ephemeral`, `verdicts`, `runs`, `findings`, `replay`.
- Crash policy adaptation: an exception inside a gesture is caught by an error boundary, shown as a bug, and the model is rebuilt from the files plus the journal.

## 6. How it grows
- **State machines:** a TS editor and types. Compilation stays in Rust `lower`.
- **Cross-level composition:** `ScopeSnapshot` becomes a subtree, so payloads and the `check_keys` cost grow with depth.
- **Code import:** Rust parses the code and returns a proposed model delta. The UI applies it as one gesture (can be undone, shown as a diff first).
- **Code proofs:** new run kinds in `JobRegistry` (Kani or Verus processes). The proof chain UI reads their reports.
- **Scan rules:** Rust only.
- **CLI:** works for load, check, scan and export. Any headless *editing* (import with `--write`, refactorings, agent edits) has no home in Rust and must be written a second time.
- What stays: Rust as stateless compute, and the UI as owner.

## 7. Testing
- TS: Vitest + fast-check checks that random gesture sequences followed by their inverses restore the original, and that `rules.ts`, `ids.ts` and `dirty.ts` behave. Component tests by role and label.
- Rust: `format` golden files and round trip, `lower`/`verify`/`scan` pure tests, simple-BFS differential, and the TAPAAL corpus.
- Cross-language contract (needed in CI): a TS run applies scripted gestures to fixture projects and emits `save` payloads. A Rust test loads them through `format` and `model` validation and compares them with expected TOML.

## 8. Trade-offs
- **Strengths:**
  - Zero-latency gestures.
  - Idiomatic React Flow (a controlled store).
  - The simplest Tauri layer.
  - Undo covers layout and model uniformly.
  - Fastest route to slice 0.
- **Weaknesses:**
  - Domain rules exist twice (ID allocation, binding validity, capacity) or need a round trip.
  - The journal stores Immer patch paths, so the recovery format depends on the TS store shape as well as the file format version.
  - Snapshots are re-sent per check and key refresh.
  - The CLI and agents cannot edit.
  - Staleness is resolved asynchronously (the `pending` state).
- **Cost:** about 0.8x to slice 1, then about 1.2x by slice 3 as the duplication tax and subtree snapshots grow.
- **Main risk:** the TS document and the Rust `model`/`format` drift, so that what was checked and shown differs from what is saved and loaded. Mitigated by validation on save plus the contract test, never eliminated.

## 9. ADR conflicts
- **ADR 0004 changes:** the undo history leaves `engine` for the UI, and `engine` becomes stateless services plus the verdict cache and job registry. The reason is zero-IPC gestures and the simplest shell.
- **ADR 0006 is restated:** "panic on the main thread while editing" becomes an uncaught exception in a gesture, handled by reloading from the files plus the journal. The loss is still limited to the last gesture.
- **ADR 0001:** the journal contents become UI patches and need their own version.


## Reviews

### By the software architect: 3/10, reject

- Strengths: Zero-IPC gestures, idiomatic controlled React Flow, and the thinnest Tauri layer.; The synchronous 'pending' state is a good rule: any non-layout patch marks the affected verdicts immediately, so a possibly stale verdict is never shown as current while keys resolve.; Save is refused if Rust validation fails, which turns TS/Rust drift into a visible error instead of a silent one.; Replay detail (local stepping, per-element selectors, aria-live) is as good as C1's.
- Risks: The journal stores Immer patch paths, so the recovery format is coupled to the TS store shape as well as the file format version. Any store refactor can break crash recovery. This directly undermines ADR 0001's 'format outlives a release'.; Correctness: the UI builds the ScopeSnapshot that Rust lowers. A UI bug that omits a child or relationship yields a Proved for something that is not the model, and Rust cannot tell. The same defect as B3.; Domain rules exist twice (ids.ts, rules.ts), and dirty.ts derives file keys from patch paths, which is a third place where the file layout is encoded.; The CLI, code import with --write, refactorings and agents cannot edit without rewriting the logic in Rust, which blocks the growth path to code import and conformance.; Scope snapshots are re-sent on every key refresh and check, and grow with subtree depth in slice 3.; Glossary drift: VerdictState.status (the glossary avoids 'status' for verdicts) and RunId/'runs' for checks.
- ADR fit: Changes ADR 0004 (undo and session move to the UI) without a measured driver. It restates ADR 0006 as an error-boundary reload, and changes ADR 0001 by giving the journal its own UI-shape version. That makes three ADRs bent to buy a latency gain no one has measured. ADR 0005 and 0008 hold mechanically, but the 'what was checked is what is saved' guarantee depends on a contract test, not on structure.
- Worth keeping: Mark affected verdicts pending synchronously on any non-layout change. In a core-owned design this falls out of returning the current keys in the apply response, but the UI rule 'never render a verdict as current unless its key equals the current key' should be explicit.; A pipes-and-filters description of the check pipeline (snapshot -> lower -> flatten -> explore -> recheck -> report) as the internal shape of the check worker.; Save-time validation that refuses to write an invalid model.

### By the senior backend developer: 2/10, reject

- Strengths: Gestures have zero latency, and React Flow is driven from a controlled store in the usual way.; Any non-layout patch synchronously marks the affected verdicts as pending, so a possibly stale verdict is never shown as current. That is the right UI rule.; Rust validates on Save and refuses invalid files, which is an explicit trust boundary.; The check path itself (main explorer, then simple BFS within the remaining budget, replay on OpenNets, join error becomes Unknown) matches ADR 0008.
- Risks: Each check lowers a ScopeSnapshot that TypeScript assembles. If the snapshot builder leaves out a bound sibling, a relationship, a port binding or the property's inputs, Rust proves a different net from the model the user sees. This is a direct path to a wrong Proved, and it grows with drill-down because snapshots become subtrees.; The journal stores Immer patch paths, so crash recovery depends on the TS store shape as well as on the file format. A store refactor or an app upgrade after a crash can make the journal unreadable or, worse, apply it to the wrong paths.; Staleness depends on a 100 ms debounced check_keys round trip, so verdict status is eventually consistent by design.; Domain rules (ID allocation, binding validity, capacity) exist twice and drift, and the cost grows from slice 2 (state machines) onwards.; An exception in a gesture is handled by rebuilding from files plus the journal. That restates ADR 0006 for a runtime with no ownership guarantees.; A headless CLI, agents and code import cannot edit, which blocks the code import and code proof growth path.; Large snapshots are re-sent for every check and key refresh.
- ADR fit: Changes ADR 0004 (engine becomes stateless services, undo moves to the UI), changes ADR 0001 (the journal becomes UI patches with their own version) and restates ADR 0006. Each change trades a correctness or durability property for gesture latency that has not been measured. 0005 and 0008 are kept only in the Rust check path.
- Worth keeping: Mark verdicts as pending synchronously in the UI on any non-layout edit, before the authoritative stale or current status arrives.; Rust validates on Save and refuses invalid files as a hard trust boundary.; Raw tauri::ipc::Request bodies with MessagePack if JSON cost shows up in profiling.; Code import returns a proposed delta that is shown as a diff and applied as one undoable gesture.
