# A1 — A: Rust-owned session, hexagonal core

Author: software architect. Style: Hexagonal (ports and adapters) with a functional core and imperative shell; persistent (structurally shared) model snapshots.

> The engine owns the one authoritative model as an immutable value, every gesture is a pure function, side effects sit behind small ports, and the UI only renders the deltas it receives.


## 1. Idea
The Rust `engine` owns the single authoritative model as an immutable value. Every gesture is a pure function `(Model, Gesture) -> Model`, and undo history is a stack of earlier values. Everything with side effects (disk, recovery journal, watcher, threads, Tauri) sits at the edge behind three small ports. The UI is a projection: it renders the view deltas the engine sends and holds no domain rules. Style: **hexagonal (ports and adapters)** with a **functional core and imperative shell**. Model maps are persistent (`im::OrdMap`), so a snapshot costs O(1) and diffs are cheap. This is ADR 0004 taken literally.

## 2. Structure
```
app/ui ──invoke / Channel<UiEvent>──▶ app/src-tauri   (adapter: commands, Mutex<Session>, TauriSink; tokio only here)
                                          │
                                          ▼
            crates/engine  (Session, lowering, JobRegistry, VerdictCache; ports Disk, Sink, Clock)
              │        │          │           │
         crates/format  crates/scan   crates/verify  (verify: no workspace deps)
              │        │
              └──▶ crates/model ◀─┘
```
Dependency rule: `engine` → {model, format, scan, verify}; `format` → model; `scan` → model; `verify` → nothing. `format` is pure (bytes ⇄ documents, migrations, journal record codec); file IO goes through `engine::Disk`. Adapters: `StdDisk` (engine, behind a feature), `MemDisk` (tests), `TauriSink` (src-tauri). UI modules are `ipc/` (hand-written wrappers over ts-rs types; the only module that calls `invoke`), `store/` (Zustand slices), `canvas/` (React Flow custom renderers, elkjs Web Worker), `panels/` (verdicts, findings, inspector) and `netview/`. CI checks crate edges from `cargo metadata` and UI imports with dependency-cruiser.

## 3. Core types and seams
```rust
// model: pure, no IO
pub struct Model { elements: OrdMap<ElementId, Element>, relationships: OrdMap<RelationshipId, Relationship>,
                   layouts: OrdMap<ViewId, Layout> }
pub enum Behavior { PetriNet(NetDef), StateMachine(MachineDef) }      // ADR 0002
pub struct Property { id: PropertyId, scope: ElementId, over: Own | Children, kind: PropertyKind } // ADR 0003
pub enum Gesture { AddElement{..}, Move{view, element, at}, SetCapacity{place: QualifiedPlace, cap: u32},
                   BindPorts{relationship, caller: PortRef, callee: PortRef, mode: Sync | Async{cap}}, Batch(Vec<Gesture>) }
pub fn apply(m: &Model, g: &Gesture) -> Result<(Model, Touched), GestureError>;  // Touched = files and views
// verify: plain nets, no C4
pub struct Net { places: Vec<Place /*cap*/>, transitions: Vec<Transition /*pre, post*/>, initial: Marking }
pub struct Composite { parts: Vec<Net>, fusions: Vec<Fusion>, channels: Vec<AsyncPlace> } // unflattened
pub fn check(n: &Net, q: &Query, b: &Budget, c: &dyn Cancel) -> Outcome;   // Proved{technique}, Disproved{steps}, Unknown{reason}
pub fn explore_simple(c: &Composite, q: &Query, b: &Budget, k: &dyn Cancel) -> Outcome; // second explorer, plain BFS
pub fn replay(c: &Composite, steps: &[CompositeStep], q: &Query) -> Result<Violation, ReplayError>;
// engine ports
pub trait Disk  { fn read_tree(&self) -> io::Result<Vec<(RelPath, Bytes)>>; fn write_atomic(&self, p: &RelPath, b: &[u8]) -> io::Result<()>;
                  fn journal_append(&self, rec: &[u8]) -> io::Result<()>; fn journal_reset(&self) -> io::Result<()>; }
pub trait Sink  { fn send(&self, e: UiEvent); }    // ViewDelta | Verdict | Findings | DiskChanged | Dirty
pub trait Clock { fn now(&self) -> Instant; }
```
```ts
type ViewDelta = { view: ViewId; upsert: ElementDto[]; remove: ElementId[]; rels: RelationshipDto[]; layout: LayoutPatch };
type VerdictDto = { property: PropertyId; scope: ElementId; verdict: "Proved" | "Disproved" | "Unknown";
                    reason?: string; evidence: Evidence; replay?: ReplayStep[]; stale: boolean };
```

## 4. Main flows
- **Open:** `open(path)`: `Disk::read_tree`, `format::load` (migrations, dangling references reported, not fatal), then `Session{cur, saved: cur}`. If the journal has entries after the last `Saved` marker, the UI offers to restore them. All checks are queued again (ADR 0005), then the session sends the first `ViewDelta`.
- **Edit and undo:** the UI sends `apply_gesture(g)`. The session runs `model::apply`, pushes the old `Arc<Model>` onto `undo` and appends a journal record, then diffs old and new for the open view and sends a `ViewDelta`. It recomputes the hashes of affected properties: cached verdicts with a different hash are marked stale, and a running check whose hash changed is cancelled. Undo swaps snapshots and sends the delta, and a verdict cached under the restored hash comes back as current. During a drag the UI moves locally and sends one `Move` on drop.
- **Save with the recovery journal:** each journal record holds the post-gesture contents of the touched files (state-based, so applying it twice is harmless). Save writes every file that differs from `saved` with `write_atomic` (temp file, fsync, rename), then appends `Saved`, resets the journal and sets `saved = cur`. A crash halfway through Save is safe because recovery overlays the journaled contents again.
- **Check:** `run_check(property)` → `engine::lower(&cur, scope)` gives `(Composite, Provenance)` → flatten to `Net` → blake3 hash of canonical net and property (IDs only). A cache hit returns at once. Otherwise the job registry spawns the named thread `check-<hash8>` with owned data and an `Arc<AtomicBool>`. The thread runs `check`. An exhaustive Proved then runs `explore_simple` on the **Composite**, not the flattened net, within the remaining budget, so the second explorer also cross-checks flattening. A disagreement gives Unknown "internal disagreement", and running out of budget gives Unknown "budget exhausted". A Disproved is replayed on the Composite, and a failed replay gives Unknown "internal error". A reaper thread joins the worker; a join error (panic) gives Unknown "internal error" (ADR 0006). The result goes into the cache and through `Sink` to the UI.
- **Replay:** the engine maps each step through `Provenance` to `ReplayStep{fired: [(ElementId, local transition)], delta: [(QualifiedPlace, i32)], highlight: [ElementId | RelationshipId]}`. The UI steps through the list locally, with no IPC per step.
- **Scan:** `run_scan()` runs `scan::run(&Model, &Rules)` on a worker thread and returns findings with `NotCheckable` entries. Suppressions are model data. Findings are keyed by a model hash and marked stale the same way verdicts are.
- **File changed on disk:** a `notify` debouncer (with `PollWatcher` under `/mnt`) in src-tauri calls `session.disk_changed(paths)`. Own-save echoes are dropped by content hash. A file without unsaved changes reloads, and **the undo history is cleared**, because older snapshots would silently revert the external change. Overlapping unsaved changes raise a banner: Reload those files or Keep mine (overwrite on Save).

## 5. Concurrency and IPC
Tauri managed state holds `Mutex<Session>`. Commands are sync `#[tauri::command(async)]`, run on the Tauri pool and hold the lock for under 5 ms, because a gesture is a map insert. Each check has its own named std thread and a reaper thread that joins it and locks the session only to insert the verdict. There is only one lock, so lock ordering cannot go wrong. The UI subscribes once to a long-lived `Channel<UiEvent>` and uses Tauri events only for window-level notices. The Zustand store holds the open view's React Flow nodes and edges built from deltas, `verdicts: Map<PropertyId, VerdictDto>`, `findings`, `replay {steps, cursor}`, `dirty` and transient drag state. It never holds other views.

## 6. How it grows
- **State machines:** a new `Behavior` variant, `Gesture` variants, a compiler in `engine::lower`, and a replay mapping to the active state. `verify` is untouched.
- **Cross-level composition:** `lower` walks a scope tree, and `Composite` gains nesting. Contract refinement checks become a new technique in `verify`.
- **Code import:** a new `crates/import` produces a `Gesture::Batch`, so an import is one undoable step.
- **Code proofs:** a new kind in the job registry that runs Kani or Verus as a child process (cancel kills it); a port gives a proof obligation.
- **Scan rules:** more `Rule` impls in `scan`.
- **CLI:** `crates/cli` builds a `Session` with `StdDisk` and a stdout `Sink`, so the whole engine is reused.

What stays the same: the ports, `verify`'s API and the UI's role as a projection.

## 7. Testing
- `model`: proptest that `apply` keeps invariants (unique IDs, ports exist), and golden tests for slug collisions.
- `format`: round trip, every migration against stored old projects, and a journal truncated at every byte offset.
- `verify`: a hand-made corpus, the differential corpus against TAPAAL in CI, and both explorers compared on random bounded nets.
- `engine`: flows run against `MemDisk`, a recording `Sink` and a fake `Clock`, including stale, undo-restore and cancel-on-hash-change cases.
- UI: Vitest for store reducers, `mockIPC` for `ipc/`, and one WebdriverIO smoke test per slice.

## 8. Trade-offs
- **Strengths:** one source of truth, the smallest design, the domain fully headless, a CLI for free, and undo plus the ADR 0005 restore that follow directly from snapshots. It matches all ADRs.
- **Weaknesses:** every gesture makes an IPC round trip, which is fine at a few ms but makes the canvas feel remote if a delta is slow. Undo history is lost on external file changes. Snapshot diffing per view must stay O(changed), not O(view).
- **Cost (my estimate, full-time solo):** slice 0 in about 6 weeks, slices 0–5 in about 6 months.
- **Main risk:** the UI round trip for gestures on 300-element views under WebKitGTK; test it in the React Flow spike.

## 9. ADR conflicts
None. `verify` gains a `Composite` type, which still knows nothing about C4. Running the second explorer on the Composite is a sharpening of ADR 0008 worth recording.


## Reviews

### By the senior backend developer: 8/10, adapt

- Strengths: One authoritative model in Rust, and every domain rule exists once. apply(&Model,&Gesture) is pure, so proptest can test invariants headless and a CLI or code import reuses the same write path.; Undo keeps whole snapshots (Arc<Model> over im::OrdMap) instead of hand-written inverses. That removes the largest class of undo bugs and gives ADR 0005's 'undo restores the cached verdict' with no extra code.; The second explorer runs on the unflattened Composite, not the flattened Net. This is the strongest wrong-Proved defense in all six designs. A deterministic flattening bug (a missing fused transition or a wrong async-place capacity) would make two explorers on the same flat net agree on a false Proved. An independent interpretation of the port bindings catches it.; The journal is state-based (post-gesture file contents) and reuses the versioned file format and migrations, so the journal adds no second persistent vocabulary. It is idempotent on replay, and a crash in the middle of Save is safe by construction.; One Mutex, short critical sections, checks on owned data with an AtomicBool, and a join-based panic-to-Unknown path follow ADR 0006 exactly. Lock ordering cannot go wrong.; The Disk, Sink and Clock ports with MemDisk and a recording Sink make engine flows (stale, undo restore, cancel on hash change, crash recovery) deterministic tests without Tauri.; Replay steps are mapped through Provenance once and stepped in the UI, so there is no IPC per step.
- Risks: Journal restore does not check base file hashes. If the user runs git checkout while the app is closed, 'overlay the journaled contents' silently reverts the checkout on the next Save. Each journal segment needs the hashes of the files it was based on (C1 has this, A2 goes further), and recovery must refuse or flag a mismatch.; The design does not say what the journal does when a clean file is reloaded after an external change. A crash after the reload could later overlay old journaled contents onto the new disk state. Reset the journal or write a marker on reload.; It does not say what happens when a Tauri command panics while holding Mutex<Session>. The lock is poisoned and the app limps on. Add C1's panic hook: abort on any thread other than check-*, which matches ADR 0006 ('a panic while editing ends the app').; Save holds the session lock during fsync and rename. That is slow on /mnt under WSL and blocks gestures. Instead, take an Arc snapshot, release the lock, write, then set saved = that snapshot, not cur.; Hashes of affected properties are recomputed on every gesture under the lock (lowering plus blake3). That is cheap for one slice 0 scope but grows with drill-down. Compute them lazily or from Touched, not by diffing whole views. Use Touched for the ViewDelta too, because im::OrdMap::diff is not guaranteed O(changed).; The VerdictCache is keyed by net and property only. A cached Unknown 'budget exhausted' or 'cancelled' would be served after the user raises the budget. Cache only Proved and Disproved by hash, and key or drop Unknowns. This applies to every design.; ViewDelta has no sequence number, while invoke replies and Channel messages can interleave. Add a rev and refetch on a gap, as C1 and A2 do.; Undo history is cleared on an external change. That is a defensible, simple choice, but it should be shown to the user.
- ADR fit: Follows ADR 0004 as written (undo in engine, verify depends on nothing, tokio only in src-tauri), ADR 0001 (atomic Save plus journal, dangling references reported), 0005 (hash cache, undo restore, cancel only on a hash change), 0006 (join error becomes Unknown 'internal error'; the editing-panic case still needs the abort hook) and 0008. Running the second explorer on the Composite sharpens ADR 0008 and should be recorded as an amendment. Glossary terms are used correctly (Verdict, Unknown with a reason, Stale, Replay, Finding, Not checkable).
- Worth keeping: Second explorer on the unflattened Composite, so it also cross-checks flattening. Amend ADR 0008.; Snapshot undo over persistent maps instead of hand-written inverses.; A state-based, idempotent journal of post-gesture file contents in the existing format, plus base file hashes taken from C1/A2.; Disk, Sink and Clock ports with MemDisk and a recording Sink for headless engine tests, and a CLI as Session plus StdDisk plus a stdout Sink.; Own-save echoes dropped by content hash, with PollWatcher under /mnt.

### By the senior frontend developer: 7/10, adapt

- Strengths: One authoritative model in Rust with a thin UI projection. A wrong Proved can only come from Rust code, so the evidence path (lower -> hash -> check -> second explorer -> replay) has a single trusted input.; Persistent snapshots make undo and the ADR 0005 'undo brings the verdict back' a lookup instead of a mechanism. The slice 1 acceptance criterion (change capacity -> stale, undo -> current) falls out directly.; Drag is local and only one Move goes to Rust on drop. That keeps per-frame work in the webview and IPC at one call per gesture. At 300 elements a small JSON delta over Tauri IPC is a few ms, which nobody notices for discrete gestures.; Replay is precomputed into ReplayStep[] with element/relationship highlights and per-place deltas, and the UI steps through it locally with no IPC per step. That is the right shape for a scrubber with keyboard step/back.; Running the second explorer on the unflattened Composite also cross-checks flattening, which closes one route to a wrong Proved (a lowering/flatten bug the two explorers would otherwise share).; The Zustand store holds only the open view, verdicts, findings, replay cursor and transient drag state. That is a small, correct split between server state and UI state.
- Risks: No revision/sequence number on ViewDelta. The delta arrives on the Channel, while apply_gesture resolves over invoke, and the two are not ordered relative to each other. A fast double gesture (drop, then Delete) can be applied against a stale mirror with no gap detection or refetch path. Add a revision and a view(id) refetch like B1.; Staleness is pushed as a `stale: boolean` inside each VerdictDto. Every edit then has to re-send verdict DTOs, and the UI duplicates derived state. Sending the current key per property and deriving stale in render is simpler and cannot drift.; The VerdictDto is a flat record with a string verdict and optional reason/replay. The type allows nonsense such as Proved with a replay or Unknown without a reason. A discriminated union (as in B1) makes 'Unknown never looks like success' a compile-time property of the panel.; Clearing the undo history on an external file change is a real UX loss (a `git checkout` of one file wipes an hour of undo). B1's approach is better: a clean entity adopts the disk version as one undoable entry.; im::OrdMap: `im` is unmaintained. Use imbl or rpds (B1 points this out).; ReplayStep carries only deltas, so scrubbing backwards or jumping to step N means cumulative recomputation in the UI. Small nets make a full marking per step cheap, and that gives random access.; Diffing the old and new snapshot per view must stay O(changed). With persistent maps, Arc::ptr_eq per entity makes this cheap, but it should be stated and tested at 300 elements. The UI patch application also has to keep object identity for unchanged nodes, or React Flow re-renders all 300 on every gesture.
- ADR fit: Fits ADR 0004 literally (undo history in engine, verify headless, tokio only in src-tauri) and ADR 0001/0005/0006/0008. Adding a Composite type to verify is a mild extension of ADR 0004's 'verify takes a plain Petri net'. It is still C4-free, so it is acceptable, but it should be recorded as an amendment together with the sharpened ADR 0008 (second explorer on the Composite). Uses GLOSSARY terms correctly (verdict, replay, stale, finding).
- Worth keeping: verify::Composite (unflattened parts + fusions + async places), with explore_simple and replay running on it, so the second explorer also cross-checks flattening; Touched = files and views returned from apply, used to scope the delta and the save set; Gesture::Batch so auto-layout results (elkjs) and code import are one undoable step; CLI that builds a Session with StdDisk and a stdout Sink; CI boundary checks: cargo metadata for crates, dependency-cruiser for UI module imports (only ipc/ calls invoke)
