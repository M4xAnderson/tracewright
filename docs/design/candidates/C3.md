# C3 — C: Versioned tables with incremental queries

Author: senior frontend developer. Style: Data-oriented relational store + incremental computation (salsa-style memoized queries with early cutoff) + reactive query subscriptions (CQRS read side); actor-style db thread.

> The core holds persistent, versioned input tables. Everything derived (view projection, lowering, check keys, staleness, findings, dangling references) is a memoized query, and the UI subscribes to queries instead of mirroring the model.


## 1. Idea
The Rust core holds the model as **persistent, versioned input tables**: rows behind `Arc` in `imbl` maps, one row per file-level thing. Each gesture writes rows and creates a new revision. Everything else is a **pure, memoized query over a revision**: view projection, lowering, check key, verdict status, findings, dangling references, dirty files. Undo, staleness, dirty tracking, journal deltas and verdict restore are therefore one mechanism.
The UI does not mirror the model. Each panel subscribes to the queries it shows, and the core pushes a new value only when that query's output actually changed.
Style: **data-oriented relational store + incremental computation** (salsa-style memoization with early cutoff), **reactive subscriptions** (CQRS read side), and an **actor-style db thread**.

## 2. Structure
```
app/ui: queries/ (useQuery) + store/ (UI-only) ──write/subscribe──> src-tauri ──msg──> engine db thread
engine ──> model, format, scan, net, verify, recheck
verify ──> net      recheck ──> net  (recheck -/-> verify, enforced in CI)      scan ──> model
```
- `model`: row types and `Tx` integrity rules, no IO.
- `net` (**new**): `Net`, `NetProperty`, `Counterexample`, no dependencies.
- `verify`: main explorer and structural methods.
- `recheck` (**new**): simple BFS, certificate checker, replay on `OpenNets`.
- `format`: rows to TOML files, migrations, journal of row deltas.
- `engine`: `Db` (inputs, revisions, memo, history), queries, `VerdictCache`, `JobRegistry`, watcher port.
- UI:
  - `queries/`: a subscription cache, `useQuery(key)` over `useSyncExternalStore`, with row-diff application for projections.
  - `store/`: Zustand for UI-only state: current view, selection, drag overlay, replay step, open panels.
  - `features/*` components.
- Dependency rule: components read domain data only through `useQuery` and write only through `actions.write(gesture)`.

## 3. Core types and seams
```rust
pub struct Inputs { elements: OrdMap<ElementId, Arc<ElementRow>>, relationships: OrdMap<RelationshipId, Arc<RelRow>>,
  behaviors: OrdMap<ElementId, Arc<BehaviorModel>>, properties: OrdMap<PropertyId, Arc<PropertyRow>>,
  layouts: OrdMap<ViewId, Arc<LayoutRow>>, suppressions: OrdMap<FindingKey, Arc<Suppression>> }   // clone = O(1)
pub struct Db { current: Inputs, rev: Revision, saved: Inputs, history: Vec<(Label, Inputs)>, cursor: usize,
                memo: Memo, verdicts: VerdictCache, jobs: JobRegistry }
pub trait Query: 'static { type Key: Hash + Eq; type Out: PartialEq + Serialize;
                           fn compute(db: &QueryCtx, k: &Self::Key) -> Arc<Self::Out>; } // ctx records row reads
impl Db { pub fn write(&mut self, l: Label, f: impl FnOnce(&mut Tx) -> Result<(), EditError>) -> Result<Revision, EditError>;
          pub fn undo(&mut self) -> Revision; pub fn get<Q: Query>(&mut self, k: &Q::Key) -> Arc<Q::Out>;
          pub fn dirty_files(&self) -> Vec<FileKey>; /* rows where !Arc::ptr_eq(current, saved) */ }
// queries: ViewProjection(ViewId), ScopeNet(ElementId), CheckKey(PropertyId), Verdicts(ElementId),
//          Replay(PropertyId), Findings, DocStatus, LoadReport, Conflicts
```
```ts
type QueryKey = { kind: "viewProjection"; view: ViewId } | { kind: "verdicts"; scope: ElementId }
  | { kind: "replay"; property: PropertyId } | { kind: "findings" } | { kind: "docStatus" } | { kind: "conflicts" };
type QueryUpdate = { sub: SubId; rev: number } & ({ value: unknown } | { rowDiff: RowDiff });
declare function useQuery<K extends QueryKey>(key: K): QueryValue<K> | undefined;
declare function write(g: Gesture): Promise<number>;   // returns the new revision; values arrive via subscriptions
```

## 4. Main flows
- **Open project:** `format` reads the files into `Inputs`, with `saved = current` and rev 0. Pending journal deltas after the last checkpoint are offered for restore and applied as one `write`. The UI subscribes `viewProjection(top)`, `docStatus` and `loadReport` (dangling references are a query, not a loader special case).
- **Edit with undo:** on drag stop the UI calls `write(Move)`. The `Tx` validates and commits as a new revision. The journal appends `OrdMap::diff(prev, current)`, so the delta is generic and no per-gesture inverse code is needed. Subscribed queries re-run lazily: unchanged row pointers hit the memo, and equal outputs are cut off without a message. The projection is sent as a row diff. The drag overlay stays until an update with `rev ≥` the returned revision arrives.
- **Undo:** `cursor -= 1` and `current = history[cursor]`. Queries see old row pointers, so the memo returns old outputs, `CheckKey` matches and the cached verdict is current again (ADR 0005 with no extra code).
- **Save:** `dirty_files()` compares row pointers against `saved`. Those files are written temp + rename, then `saved = current` and the journal is checkpointed. `docStatus` flips and the unsaved marker clears.
- **Check:** `run_check(p)` computes `CheckKey(p)` from the memoized `ScopeNet`, then either hits the cache or hands an `Arc<Lowered>` snapshot to worker thread `check-<hash8>`. In the worker:
  - `verify` explores within the budget.
  - After an exhaustive Proved, `recheck::simple_bfs` runs with the remaining budget. Agreement gives Proved, disagreement gives Unknown "internal disagreement", and a budget overrun gives Unknown "budget exhausted".
  - A Disproved counterexample goes through `recheck::replay` on `OpenNets`; if replay fails the verdict is Unknown "internal error".
  - A join error gives Unknown "internal error". The verdict lands in the cache, which invalidates `Verdicts(scope)`, and subscribers get it.
  - After each revision the db thread compares the keys of running checks with the current `CheckKey` and cancels any mismatch. Progress is a `RunProgress(run)` query throttled to 4 Hz.
- **Replay:** `Replay(p)` derives element-level frames from the counterexample plus provenance. The UI holds only `replay.step`. Highlights are per-element boolean selectors, and an `aria-live` region announces each step.
- **Scan:** `Findings` is a query with a memo per rule. It is computed only while the findings panel subscribes, so the displayed findings are never stale. Suppress is a write, so it can be undone.
- **File changed on disk:** the watcher re-reads the file into rows.
  - If the current row is pointer-equal to the saved row, it runs `write("External change")`, which can be undone.
  - Otherwise the row goes into the `Conflicts` input, and the UI dialog subscribes to `conflicts`.

## 5. Concurrency and IPC
- A single **db thread** owns `Db`. Tauri commands send messages and get a oneshot reply, which gives a total order for free. Query evaluation, which can take ms when lowering a 300-element scope, never runs on the main thread or the tokio pool.
- One `Channel<QueryUpdate>` carries every subscription, in order. Check workers and the watcher are std threads that post results to the db thread. The memo is evicted by revision distance, keeping the undo-reachable window.
- Panic hook: `check-*` threads unwind to join. A panic on the db thread aborts the app (journal limits the loss, ADR 0006).
- The UI store holds UI state only. Domain data lives in the query cache keyed by `QueryKey`, so a panel unmount unsubscribes and stops the computation.

## 6. How it grows
- **Cross-level composition:** `ScopeNet(e)` calls `ScopeNet(child)`. Per-child memo reuse is the incremental re-verification and cached per-component certificates of verification.md R4 stage 3. This is where C pays off.
- **State machines:** a `CompiledSm(element)` query.
- **Code import:** a `code_facts` input table, with **conformance** as a live query comparing model rows with code facts.
- **Code proofs:** a contracts table and `ProofStatus(contract)` keyed by contract hash and code file hash. Kani and Verus runs go through `JobRegistry`.
- **Scan rules:** one memoized query each.
- **CLI:** `Db` without subscriptions (`open`, `get::<Verdicts>`, synchronous checks).
- What stays: inputs are tables, everything else is a query.

## 7. Testing
- The key oracle (proptest): for random write and undo sequences, every query computed incrementally equals the same query on a fresh `Db` built from the final `Inputs`. This tests the memo, early cutoff and undo together.
- `format`: golden files and round trip. `Tx` integrity tests.
- `verify` versus `recheck` differential tests, plus the TAPAAL corpus.
- UI: the query cache tested with a scripted `QueryUpdate` stream, and components rendered from fixture values (by role and label). A few wdio e2e tests.

## 8. Trade-offs
- **Strengths:**
  - One mechanism replaces hand-written inverses, dirty tracking, staleness bookkeeping and journal formats.
  - Live findings and live conformance.
  - Scales naturally to cross-level composition and incremental verification.
  - The UI has no model mirror.
- **Weaknesses:**
  - Most concepts up front, for little visible gain in slice 0.
  - A memo bug could show a stale verdict as current. Mitigations: verdict status always compares hashes, and debug builds re-compute and assert on a sample.
  - Hand-rolling the memo (about 10 queries; the `salsa` crate is the alternative, but its API is not 1.0, version UNVERIFIED).
  - `imbl` ergonomics and its constant-factor cost.
- **Cost:** about 1.4x to slice 1, approaching 1.0x by slice 3 and below it afterwards. Slice 0 can start as "recompute every query per revision, no memo", which is cheap at 300 elements, and add memoization when a profile demands it.
- **Main risk:** over-engineering before the basic loop is proven, and one developer debugging invalidation instead of finding deadlocks.

## 9. ADR conflicts
- **ADR 0004 changes:** add `crates/net` (plain net types) and `crates/recheck` (simple BFS, certificate checker, replay), with a CI rule that `recheck` must not depend on `verify`. The reason is that ADR 0008's "no shared code beyond the net types" is then enforced by the dependency check instead of by discipline.
- `engine` gains the query layer and still owns undo and the job registry. Other ADRs are unchanged.
- Findings shown live narrows when "stale" applies to findings, but it does not contradict the glossary.

### By the software architect: 6/10, adapt

- Strengths: Adds crates/net and crates/recheck, with a CI rule that recheck must not depend on verify. ADR 0008's 'no shared code beyond the net types' becomes a dependency-graph fact instead of discipline. This is the best enforcement idea of the six designs.; Inputs as persistent tables with ptr_eq dirty tracking, snapshot-cursor undo and OrdMap::diff journal deltas: one generic mechanism with no hand-written inverses.; The key oracle test (every incrementally computed query equals the same query on a fresh Db built from the final Inputs) is an excellent fitness function. It applies even with no memo at all.; It grows best toward slice 3+ and R4 stage 3: per-child ScopeNet reuse is incremental re-verification and per-component certificate caching, and conformance becomes a query over a code_facts table.; Honest escape hatch: slice 0 can recompute every query per revision with no memo, which is cheap at 300 elements.; A db thread gives total order, and the panic policy matches ADR 0006.
- Risks: A memo bug can produce a wrong Proved on screen. If ScopeNet returns a stale memoized net, CheckKey matches the old key and the old Proved appears as current for a changed model. The stated mitigation (verdict status compares hashes) does not help, because the hash itself comes from the memo. Workers should lower from the raw Inputs snapshot, not from the memoized ScopeNet, or the memo should stay off until cross-level composition needs it.; Most concepts up front: query trait, subscription protocol, row diffs, memo eviction by revision distance. That is surprising if the user expects a scan to be an explicit act.; The behaviors table is separate from elements, while ADR 0001 stores the behavior model inline in the element's file. The row-to-file mapping for dirty_files and Save must merge them, which is a source of subtle Save bugs.; Hand-rolled memo against a pre-1.0 salsa: either choice spends an innovation token.

ADR 0005 holds as long as the check key is computed from unmemoized lowering or the memo is proven by the oracle. ADR 0006 holds. ADR 0001 holds if the row-to-file mapping keeps one file per element. ### By the senior backend developer: 5/10, reject

- Strengths: The crate split crates/net plus crates/recheck (simple BFS, certificate checker, replay), with a CI rule that recheck must not depend on verify, turns ADR 0008's independence from discipline into a compile-time boundary. That is a change to ADR 0004 I would support.; Undo is a cursor over history snapshots, with no inverse code. dirty_files compares Arc pointers against saved, so it is cheap, and a false positive only rewrites an identical file, which is harmless.; The proptest oracle is excellent: queries computed incrementally after random writes and undos must equal the same queries on a fresh Db built from the final Inputs.; A single db thread gives a total order, and query evaluation never runs on the Tauri main thread or the tokio pool.; It grows naturally into slice 3 and R4 stage 3 (memo reuse per child is incremental re-verification and cached per-component certificates), and into code import as a code_facts table with conformance as a query.; It includes an honest fallback: slice 0 can recompute every query per revision without a memo.

A stale ScopeNet memo produces a stale hash that matches the stale verdict, and an old Proved is shown as current. The check worker must hash the net it actually explores, and current status must come from a hash computed outside the memo (or be re-verified in debug and in tests).; It is the most concepts up front (revisions, memo, early cutoff, subscriptions, eviction by revision distance) for no visible gain in slices 0 to 2. One developer would be debugging invalidation instead of shipping the walking skeleton.; The salsa crate is not 1.0 and the alternative is a hand-rolled memo. Both carry maintenance risk.; Journaling OrdMap::diff row deltas makes the row schema a second persisted format next to the TOML files.; Live findings change the glossary meaning of a stale finding. - ADR fit: It changes ADR 0004 explicitly and with a good reason (net and recheck crates, CI-enforced). Undo and the job registry stay in engine. Consistent with 0001, 0005 (with the circular-hash caveat above), 0006 (the db thread panic aborts, check threads unwind to join) and 0008, which it strengthens. As a foundation it is premature, but its ADR 0004 amendment is worth adopting on its own.
- Worth keeping: Amend ADR 0004 to add crates/net (plain net types) and crates/recheck (simple explorer, certificate checker, replayer), with CI forbidding recheck → verify.; Snapshot history with a cursor for undo, and dirty files by Arc::ptr_eq against the saved snapshot.; The 'incremental equals fresh' proptest oracle, usable for any caching of hashes or projections.; The worker computes the cache key from the net it actually explores.; Revisit salsa-style queries at slice 3 or R4 stage 3, when per-child certificate reuse needs them, starting from 'recompute everything per revision'.; A code_facts input table with conformance as a derived query, for the code import era.
