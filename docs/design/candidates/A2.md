# A2 — B: Op log as truth, single-writer actor

Author: software architect. Style: Event-sourced command log (op log) with actor / message passing (single-writer model actor).

> A per-project log of invertible ops is the source of truth: undo, recovery journal, Save, UI sync, staleness and external file changes are all derived from it, and one actor thread owns it.


## 1. Idea
The session's source of truth is an append-only log of invertible ops over the last saved files. The current model is a fold over that log. Undo, the recovery journal, Save, UI sync (sequence-numbered patches), staleness and external file changes are all entries in the same log rather than separate mechanisms. One actor thread owns the log and model, and everything else talks to it by message. Style: **event-sourced command log** plus **actor / message passing**.

## 2. Structure
```
app/ui  store: per-view projection + lastSeq ──Intent──▶ app/src-tauri ──Msg──▶ ModelActor (engine)
        ◀──Channel<Committed{seq, ViewPatch}>───────────────────────────────── Outbox ◀┘
                                       ModelActor ──spawn──▶ CheckActor(s), ScanActor
                                       WatcherActor ──Msg::DiskChanged──▶ ModelActor
crates: model (Model, Op, apply/invert)  format (TOML codec, journal codec, migrations)
        engine (actor, log, fold, materialize, jobs, cache, lowering)  scan → model  verify → nothing
```
Dependency rule: the same crate edges as ADR 0004. Only `ModelActor` mutates the model, and other actors get `Arc<Model>` snapshots. UI modules are `ipc/`, `store/` (applies patches in `seq` order and refetches the view on a gap), `canvas/`, `panels/` and `netview/`.

## 3. Core types and seams
```rust
// model: an Op carries old and new values, so it inverts without state
pub enum Op { AddElement{id, data: ElementData}, RemoveElement{id, data: ElementData},
              SetCapacity{place: QualifiedPlace, from: u32, to: u32}, Bind{rel, binding}, Unbind{rel, binding},
              SetLayout{view, element, from: Pos, to: Pos}, .. }
pub fn apply(m: &Model, op: &Op) -> Result<Model, Precondition>;    // fails if the model does not match `from`
impl Op { pub fn inverse(&self) -> Op; pub fn touches(&self) -> Touch /*elements, files, views*/ }
// engine
pub enum Entry { Gesture{seq, ops: Vec<Op>}, Undo{seq, of: Seq}, Redo{seq, of: Seq},
                 External{seq, ops: Vec<Op>, files: Vec<(RelPath, Hash)>}, SaveBegin{targets: Vec<(RelPath, Hash)>}, SaveDone }
pub struct Log { base: Vec<(RelPath, Hash)>, entries: Vec<Entry>, cursor: Seq }
pub enum Msg { Intent(Intent, Reply<Result<Seq>>), Undo, Redo, Save(Reply<..>), Open(PathBuf, Reply<..>),
               DiskChanged(Vec<RelPath>), RunCheck(PropertyId), CheckDone(JobId, thread::Result<Outcome>), RunScan, GetView(ViewId, Reply<ViewDto>) }
pub trait Outbox { fn send(&self, e: UiEvent); }   // Committed{seq, patch} | Verdict | Findings | Conflict | Restored
// verify: as in ADR 0004 plus Composite (unflattened) for replay and the second explorer
```
```ts
type Committed = { seq: number; view: ViewId; patch: ViewPatch; dirty: boolean; stale: PropertyId[] };
type Intent = { kind: "move"; element: ElementId; to: Pos } | { kind: "setCapacity"; place: string; cap: number } | ...;
```

## 4. Main flows
- **Open:** the actor reads files, `base` = their hashes, and folds the empty log. If the journal for this project exists: when the disk matches its `base`, the UI offers to restore N gestures; when the journal ends with `SaveBegin` and no `SaveDone`, the actor finishes the Save from the replayed model; when the disk differs (git checkout while the app was closed), the ops are rebased by preconditions and failing ones are listed as conflicts. Checks are queued again.
- **Edit and undo:** an `Intent` becomes `ops`, the actor applies them, appends the `Gesture` to the log and to the journal (append and fsync, **after** a successful apply, so an op that panics is never journaled), then emits `Committed` with a patch derived from `op.touches()`, without diffing. Undo appends the inverse ops as `Undo{of}`. Stale detection uses `touches()` to rehash only properties whose scope contains a touched element (ADR 0005 hashing, narrowed).
- **Save:** the actor materializes the touched files, appends `SaveBegin{targets}`, writes each file atomically, appends `SaveDone`, then compacts the journal (new `base`, entries dropped).
- **Check:** as in ADR 0005: lower, flatten, hash and look up the cache. A `CheckActor` thread owns the snapshot. The main explorer and the second explorer (plain BFS on the unflattened Composite, ADR 0008) run **in parallel** on two named threads and share one budget (a shared deadline and an `AtomicUsize` count of stored markings), so wall time is about max(a, b) on multicore. Both must agree. A Disproved is replayed on the Composite. A panic (join error) gives Unknown "internal error". The actor receives `CheckDone`, caches the verdict and emits it. An entry that changes a running check's hash sets its cancel flag.
- **Replay:** the `Provenance` mapping turns the counterexample into `ReplayStep[]` once, and the UI steps through it locally.
- **Scan:** a `ScanActor` gets a snapshot and replies with findings tagged with the `seq` they were computed at. A later `seq` that touches affected elements marks them stale.
- **File changed on disk:** `WatcherActor` (notify debouncer, `PollWatcher` fallback) sends `DiskChanged`. The actor decodes the file, drops it if its hash equals the last written one, diffs old against new documents into ops and appends `External{ops}`. If those ops touch fields that unsaved gestures changed, a `Conflict` offers Take disk or Keep mine (keep re-applies my values as a new gesture). Undo still works across `External`: an inverse whose precondition fails is reported, never applied blindly.

## 5. Concurrency and IPC
The threads are the main and Tauri threads, `ModelActor` (crossbeam channel mailbox), `WatcherActor`, one `CheckActor` with two explorer threads per running check, and `ScanActor`. No locks are shared; snapshots are `Arc<Model>` (im maps). Tauri commands are thin: build a `Msg` with a oneshot reply and await it with `spawn_blocking`. One long-lived `Channel<UiEvent>` comes from `subscribe(channel)` at startup. The job registry lives inside the actor (JobId → cancel flag, hash). The UI store holds the projection of the open view with `lastSeq`, verdicts, findings, the replay cursor and dirty state. If the actor panics, a supervisor in src-tauri joins it, shows an internal error and rebuilds the model from disk and journal (a proposal, see section 9).

## 6. How it grows
- **State machines:** new `Op` variants and a compiler in lowering.
- **Cross-level composition:** a lowering change only.
- **Code import:** emits an `External`-like pending changeset that the user reviews and accepts as one gesture; the log makes import preview and undo natural.
- **Code proofs:** a new actor kind that wraps Kani or Verus processes.
- **Scan rules:** added in `scan`.
- **CLI:** reuses `engine` without Tauri, and can even apply scripted ops (`petrinet apply ops.json`).
- **Later:** a local check log for I1/I2 is another log consumer, and three-way merge help after `git pull` reuses rebase-by-precondition.

What stays the same: the op vocabulary is the one seam every feature extends.

## 7. Testing
- `model`: proptest that `apply(apply(m, op), op.inverse()) == m` for every op, and that `fold(log) == fold(compact(log))`.
- `format`: TOML round trip, migrations, and journal records truncated at every byte offset recover a prefix of gestures.
- `engine`: the actor is driven synchronously by feeding `Msg`s in tests, with fault injection between `SaveBegin` and `SaveDone`, an external change during unsaved edits, and undo across `External`.
- `verify`: as in ADR 0008 (TAPAAL corpus, explorer against explorer).
- UI: Vitest for patch application and gap refetch with `mockIPC`, plus a WebdriverIO smoke test.

## 8. Trade-offs
- **Strengths:** the most robust story for the hardest parts of ADR 0001 (partial Save, crash, git checkout under unsaved edits). Undo survives external changes. UI patches are exact and cheap. No locks.
- **Weaknesses:** every edit needs a hand-written invertible op, and external changes need a document differ that produces ops. Actor plumbing (mailboxes, replies, supervision) is code that does not show up in a demo. Log semantics are subtle (undo of undo, rebase), and the journal format becomes data that must survive an upgrade after a crash.
- **Cost (my estimate):** slice 0 in about 7–8 weeks (the log can be minimal there), slices 0–5 in about 6.5 months; slice 1 (undo, journal, stale) becomes cheaper.
- **Main risk:** over-engineering before slice 0 proves the product; the log must be kept minimal until slice 1.

## 9. ADR conflicts
No hard conflicts. ADR 0001's journal becomes the op log (its codec stays in `format`, its semantics move into `engine`), consistent with ADR 0004's split. Rebuilding the model actor from the journal after a panic **extends ADR 0006** (which ends the app on an editing panic) and needs an amendment if adopted. A new ADR, "The session is an op log", would record the decision.


## Reviews

### By the senior backend developer: 5/10, reject

- Strengths: It handles the hardest cases of ADR 0001 best: SaveBegin/SaveDone finishes an interrupted Save, base hashes detect a git checkout made while the app was closed, and rebase by precondition lists conflicts instead of silently overwriting.; Journaling after a successful apply, with fsync, means a gesture that panics is never written to the journal.; Patches come from op.touches() without diffing, and Committed carries a seq so the UI refetches on a gap. The UI protocol is exact and cheap.; Stale detection narrowed by touches() is cheaper than rehashing every scope.; Running both explorers in parallel under one shared deadline and marking counter keeps ADR 0008's 'shares the check's budget' and roughly halves wall time on multicore.
- Risks: Every edit needs a hand-written invertible Op with from/to preconditions, and every document type needs a differ that turns external changes into ops. For one developer that is a large, permanent cost that delivers nothing visible in slices 0 to 2.; The op vocabulary becomes a second persistent format next to the TOML format. A journal written before a crash must be readable after an upgrade, so Op needs versioning and migrations too.; Log semantics (Undo{of}, redo, undo across External, rebase) are subtle, and bugs there corrupt the model, not just the history.; The supervisor that rebuilds the actor after a panic contradicts ADR 0006 ('a panic while editing ends the app'). Recovering in-process after an unknown invariant break is the state recovery ADR 0006 deliberately avoids.; Parallel explorers roughly double peak memory, and a shared marking counter lets the main explorer starve the second one. That is still safe (Unknown), but it makes Unknown 'budget exhausted' more frequent. On a Disproved, the second explorer must be cancelled at once.; Actor mailboxes, oneshot replies and spawn_blocking add plumbing and latency, while a short Mutex gives the same total order for one user.
- ADR fit: Keeps ADR 0004's crate edges but moves journal semantics into engine (consistent with 0004). Conflicts with ADR 0006 by supervising and rebuilding after an editing panic, which needs an amendment I would not support. Consistent with 0001, 0005 and 0008. It needs a new ADR ('the session is an op log') for a decision that slice 0 cannot yet justify.
- Worth keeping: SaveBegin{targets}/SaveDone markers in the journal so recovery can finish or roll forward a partial Save.; Base file hashes in the journal header, and refusing to restore blindly when the disk differs.; A seq on every UI update, with a view refetch on a gap.; Journal only after a successful apply.; Narrowing rehash to properties whose scope contains a touched element.; Later: rebase by precondition as a 'merge help after git pull' feature, built on snapshots plus a document diff and not as the core model.

### By the senior frontend developer: 4/10, reject

- Strengths: Committed{seq, patch} derived from op.touches() gives exact, cheap UI patches with no diffing, plus seq-gap refetch. That is the most precise sync contract of the six.; Undo survives external changes, and inverses whose preconditions fail are reported rather than applied blindly. That is the most careful handling of git checkout under unsaved edits.; Findings tagged with the seq they were computed at, and staleness narrowed via touches(), fit the GLOSSARY's stale semantics.; Importing code as a reviewable pending changeset is a good UX shape for the later code-import feature.
- Risks: Every edit needs a hand-written invertible Op with from/to values, plus a document differ that turns external file changes into ops. That is a large, subtle surface for one developer, and none of it shows in slice 0, which has no undo or journal.; Rebuilding the model actor from disk and journal after a panic contradicts ADR 0006 (an editing panic ends the app) and recovers state after a bug, which is exactly what the crash policy rules out. For a correctness-first tool, continuing on a possibly corrupt model is the wrong default.; fsync of the journal on every gesture sits in the gesture's critical path before Committed is emitted. On WSL2 or slow disks that can add tens of ms to every canvas gesture. ADR 0001 allows losing the last gesture, so the UI reply does not need to wait for fsync.; Running the two explorers in parallel with a shared budget halves wall time but doubles peak memory and CPU per check. With several properties queued it competes with other checks and with the UI thread on a mid-range laptop. It also complicates the 'budget exhausted -> Unknown' accounting.; Log semantics (undo of undo, rebase by precondition, compaction) and a journal format that must survive upgrades after a crash all add persistent-format risk on top of the TOML format.; The actor plumbing (mailboxes, replies, supervisor) is cost before E5 has validated the product. The design admits it should stay minimal until slice 1, but then most of its benefits are deferred too.
- ADR fit: Keeps ADR 0004's crate edges, but the proposed supervisor-rebuild directly conflicts with ADR 0006 and would need an amendment that I would argue against. It stretches ADR 0001: the journal becomes the op log. Sequencing conflicts with v1-slices (slice 0 excludes undo and journal, but this design builds them as its backbone). Terms are used correctly.
- Worth keeping: Sequence-numbered patches with gap detection and a view refetch command; Patch derived from what an operation touched rather than from a full view diff; Undo across external changes, with precondition checks that report instead of silently reverting; Code import as a reviewable pending changeset accepted as one gesture; proptest laws: apply then inverse is identity, and fold(log) == fold(compact(log))
