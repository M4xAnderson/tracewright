# B2 — Design B: Session actor over a gesture log

Author: senior backend developer. Style: Event-sourced command log + actor/message passing (single writer), UI as read projection (CQRS-like).

> An append-only log of gesture entries with before/after TOML-fragment images is the source of truth and the recovery journal. One session actor thread owns log, folded model, verdict cache and job registry, and serializes every input (gestures, undo, save, disk changes, check completions) through one inbox.


## 1. Idea
The source of truth is an append-only log of gesture entries. Each entry carries before/after images of the touched entities as canonical TOML fragments. The current model is a fold of that log over the last saved base. One session actor thread owns the log, the folded model, the verdict cache and the job registry. Everything that happens is a message in its inbox: a gesture, undo, Save, a file changed on disk, a check finished, a scan finished. Everything the UI sees is an event out of it. The recovery journal (ADR 0001) is the log itself, fsynced before the gesture takes effect.
**Style:** event-sourced command log + actor/message passing (single writer), with the UI as a read projection (CQRS-like).

## 2. Structure
Crates as in ADR 0004; the actor is the module `engine::session`.
```
 UI gesture ─┐                         ┌─> SessionEvent ─> Channel ─> UI projection (reducer)
 watcher ────┤   inbox (mpsc<Msg>)     │
 monitors ───┼──────────────> [ session actor thread ] ──> log file (app data, fsync)
 Tauri cmds ─┘                         └─> spawns check/scan workers (Arc snapshots)
```
- `model`: types plus the pure pair `decide(&Model, &Command) -> Result<Vec<EntityChange>, Rejected>` and `evolve(Model, &EntityChange) -> Model`.
- `format`: TOML directory; log codec (JSON lines whose images are TOML fragments, so format migrations also migrate old logs).
- `verify`, `scan`: as in ADR 0004. `engine`: `lower`, `check_key`, `replay_unflattened`, workers, `session`.
- `app/src-tauri`: holds a `Sender<Msg>`; each command sends a message (with a reply channel where needed). One `Channel<SessionEvent>`.
- `app/ui`: `ipc/`, `projection/` (a pure reducer `(State, SessionEvent) -> State` in Zustand), `canvas/`, `panels/`, `layout.worker.ts`.
Rule: only the actor mutates session state; workers and watcher only send messages; no `Mutex` in `engine`.

## 3. Core types and seams

## 4. Main flows
- **Open project:** `Msg::Open` -> load files, compute the base fingerprint. If a log for this project exists and its base matches (or ends in an unfinished `SaveBegin`), the `opened` event carries a restore offer; accepting it folds the entries. Then start the watcher and send `RunChecks` for every scope with properties (ADR 0005).
- **Edit and undo:** `Msg::Gesture` -> `decide` -> append the `LogEntry` and fsync -> `evolve` -> recompute keys of affected scopes -> cancel workers whose key vanished -> emit `applied` and `keys`. Undo appends a compensating entry (before and after swapped, `Undo { of }`), so the log stays linear and append-only; redo is a cursor. Earlier verdicts come back from the cache when the keys match again.
- **Save:** the actor renders the changed files from its snapshot and appends `SaveBegin` with their hashes. A writer thread does temp + fsync + rename and replies with a message; gestures arriving meanwhile queue in the inbox. Then append `SaveDone` and compact: start a new log at the new base by rename, then delete the old one. On recovery, idempotent after-images converge on a torn save.
- **Run a check:** the actor lowers, keys and looks up the cache; on a miss it spawns a named worker owning `Arc<Net>`. The worker order is the same as in Design A (main explorer, then `explore_simple` on the same deadline for an exhaustive Proved, then flat + unflattened replay for Disproved). The monitor joins the handle and sends `CheckDone`; a panic becomes `Err(InternalError)` -> Unknown "internal error". The actor stores the verdict under its key and emits it, stale or not. Ordering is the point: a verdict for an outdated key can never overwrite a current one, because only the actor decides.
- **Replay:** the `verdict` event carries the steps in model terms; the UI projection steps locally.
- **Scan:** `RunScan` -> a worker on an `Arc<Model>` -> `ScanDone { model_hash }`; the findings are stale if the hash differs from the current one. Suppressions are model data and so are logged gestures.
- **File changed on disk:** the watcher sends `DiskChanged`. For each entity the actor compares the disk fragment with its images. Equal to our last write: ignore. Entity clean: append `EntryKind::Disk` (undoable). Entity dirty and different: emit `conflict`; the user's choice comes back as a `Gesture`.

## 5. Concurrency and IPC
- Threads: the `session` actor; the watcher; the save writer; one named worker plus one monitor per running check (at most cores - 1, a FIFO queue in the actor); a scan worker. Inbox `std::sync::mpsc`; workers throttle progress messages to 4/s.
- Tauri: async commands `send` and then wait for the reply in `spawn_blocking`; fire-and-forget messages (undo, cancel) return at once. One `Channel<SessionEvent>`, ordered. Events (`emit`) are not used.
- Heavy work stays off the actor: rendering files for Save and lowering a scope are the largest steps on it (measure at 300 elements; move lowering to a worker if > 20 ms).
- A panic in the actor thread is treated like a main-thread panic (ADR 0006): the app exits. The fsynced log means no gesture is lost.
- UI store: a projection only; it never mutates on its own except ephemeral drag and replay-cursor state.

## 6. How it grows
- **State machines and cross-level composition:** only `lower` and `OriginMap` change (as in Design A); the actor is unaffected.
- **Code import:** an `import` crate produces `EntityChange`s, appended as one `EntryKind::Import` entry that can be reviewed and undone.
- **Code proofs:** a `ProofRunner` spawned like a check; outcomes arrive as messages, keyed by input hash.
- **More scan rules:** `impl Rule`. **CLI:** uses the pure functions directly (`format::load`, `lower`, `verify::check`, `scan::run`), or runs the actor headless with a stdout `EventSink`.
- **Free later:** "what changed since this verdict was Proved" (log diff), an edit history panel, multi-window views on one session.

## 7. Testing
- The actor in Given/When/Then form: `given(entries).when(msgs).then(events)` with an inline `Spawner` and a fake clock. Deterministic, no sleeps, no threads.
- Laws (proptest): `fold(log) == apply sequence`; undo entry ∘ entry = identity; replaying a log twice from the base equals replaying it once; old-version logs migrate through `format`.
- `verify`, `format`, `scan`: as in Design A (explorer agreement, TAPAAL corpus, round-trips).
- Crash tests: a child process killed during Save and after N gestures; restore gives the same model hash.
- UI: the reducer is pure, so Vitest feeds recorded `SessionEvent` sequences.

## 8. Trade-offs
- **Strengths:** one ordering point removes the races between an edit, a check finishing, a cancel and a disk change. Journal, undo, disk reconciliation and import share one mechanism. Tests are deterministic. The log is a durable "since last save" history that later features can use.
- **Weaknesses:** more machinery. The `Msg` enum grows with every feature; request/reply over channels; stack traces stop at the inbox. The log is a second persistent format (mitigated by TOML-fragment images that reuse format migrations). One slow message stalls everything. The UI projection still mirrors the view, as in A.
- **Cost for one developer:** about 2-3 weeks more than A before slice 0 can be shown, because slice 0 has no undo or journal but this design builds its backbone anyway. Slice 1 (undo, journal, stale, cancel) then gets cheaper.
- **Main risk:** building infrastructure before E5 has validated the bet; the actor turning into a god object. Keep `decide`/`evolve` pure and the actor a thin dispatcher.

## 9. ADR conflicts
No ADR conflict. ADR 0001's journal is read in its strongest form: it *is* the session log, written before the gesture applies. ADR 0004 holds: the undo history is a log cursor in `engine`, and the log codec is in `format`. It shares Design A's clarification that unflattened replay lives in `engine`. It does conflict with the slice order in `v1-slices.md` (journal and undo are out of slice 0), which is a sequencing question for the product owner, not an ADR.

This is the strongest testing story among the core-owned designs.; Journal images are TOML fragments, so format migrations also migrate old journals. That honors ADR 0001's 'format outlives a release' for the journal too.; The decide/evolve split keeps the domain pure. Undo, disk adoption and import all become log entries, so they share one mechanism.; Workers and the watcher only send messages and engine has no Mutex, so lock-ordering bugs are impossible by construction.; The log enables later features: 'what changed since this verdict was Proved', and an edit history panel.
- Risks: It conflicts with the v1 slice order. It builds the journal, undo cursor and reconcile backbone before slice 0, which excludes all three, at a cost of about 2-3 weeks before E5 has validated the product bet. For one developer that is the wrong place to spend.; The headline benefit is overstated. 'A verdict for an outdated key can never overwrite a current one' already holds in B1 and C1, because verdicts are stored under their CheckKey and current-ness is a key comparison. Correctness does not need the actor.; The log becomes a second persistent format with compaction, rename-based rotation and compensating undo entries plus a redo cursor. That is more recovery code to get right, and recovery code is rarely exercised.; Every synchronous command does a request/reply over a channel inside spawn_blocking. Stack traces stop at the inbox. The Msg enum grows with every feature and tends toward a god object.; Head-of-line blocking: lowering and Save rendering run on the actor, so one slow message stalls every gesture. The design acknowledges this and defers it to measurement.; It inherits B1's lowering-as-single-point-of-failure and key-coverage risks unchanged.
- ADR fit: No ADR conflict. It reads ADR 0001's journal in its strongest form (written before the gesture applies) and keeps ADR 0004's crate layout with the log codec in format. - Strengths: One ordering point: edits, check completions, cancels and disk changes are serialized, so a verdict for an outdated key can never overwrite a current one.
