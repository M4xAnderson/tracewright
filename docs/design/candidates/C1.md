# C1 — A: Core-owned model, UI as a view projection

Author: senior frontend developer. Style: Functional core + imperative shell (Rust), hexagonal ports for IO, thin projection client (React).

> The engine owns the one live model, undo history, verdict cache and checks. The UI sends typed Edits and receives small per-view patches, so it never holds the model.


## 1. Idea
The `engine` owns the one live model, its undo history, the verdict cache and every running check. The UI never holds the model. It holds a **projection of the current view** plus ephemeral UI state (selection, drag overlay, replay step). Every gesture becomes a typed `Edit`. Rust applies it with a pure function, appends it to the journal and returns a small `Change` (view patch, dirty flag, verdict summaries).
Style: **functional core + imperative shell** (`model::apply` is pure, `engine::Session` is the shell), **hexagonal ports** for file system, journal, clock and watcher, and a **thin projection client** in React.

## 2. Structure
```
app/ui ──invoke + Channel──> app/src-tauri (tokio) ──> engine (std threads)
engine ──> model, format, verify, scan     format ──> model   scan ──> model   verify ──> ∅
```
- `model`: element, relationship, behavior model, property and layout types. Also `apply(&Model,&Edit) -> Applied`, validation and slug ID allocation. No IO.
- `format`: TOML directory read and write, canonical writer, migrations, journal codec.
- `verify`: `Net`, main explorer, `simple_bfs` (separate module, whose `use` list is lint-checked to contain only net types), P-invariant checker, `replay`.
- `scan`: the `Rule` trait and rules. `engine`: `Session`, lowering and flattening with provenance, `VerdictCache`, `JobRegistry`, projection builder, disk reconciliation.
- `app/src-tauri`: about 15 commands, the `notify` and real-fs adapters, one panic hook.
- UI `app/ui/src`: `ipc/` (ts-rs types plus hand-written wrappers, the only place that calls `invoke`), `store/` (Zustand slices), `features/canvas` (React Flow, element and relationship components, `layout.worker.ts` with elkjs), `features/verify`, `features/scan`, `features/inspector`.
- Dependency rule: components read `store` through selectors. Only `store/actions.ts` calls `ipc`. ADR 0004 stays unchanged.

## 4. Main flows
- **Open project:** `open_project(path)` → `format` reads the files and the loader reports dangling references → `Session` is created. If `JournalStore` has entries after the last checkpoint and their base file hashes match, the UI offers restore and the engine re-applies those Edits. The UI then calls `get_view(top)` and receives the full projection (300 elements is roughly 100–300 KB of JSON, to be measured in E4).
- **Edit with undo:** dragging stays local (React Flow plus a `dragOverlay` map, so only the dragged components re-render). On drag stop the UI sends `apply(Move{..})`. The engine calls `model::apply`, journals the Edit, pushes the inverse onto history, recomputes the check hashes of affected properties (lowering takes a few ms at this size) and returns a `Change`. The UI applies the patch and clears the overlay. Undo sends `undo()`, which applies the inverse. When the hash matches again, the cached verdict comes back as current (ADR 0005).
- **Save:** `save()` → the files touched since the last save are written temp + rename. On success the journal is checkpointed and `dirty=false`. A partial failure reports the files that were not written and keeps the journal.
- **Check:** `start_check(property, budget, channel)` → lower the scope into a `FlatNet` with provenance → hash. On a cache hit the cached verdict is returned. Otherwise a worker thread `check-<hash8>` starts with an immutable `Model` snapshot and an `AtomicBool`. The main explorer runs within the budget. An exhaustive Proved is followed by `simple_bfs` with the remaining budget: if they agree the verdict is Proved; if they disagree it is Unknown "internal disagreement"; if the budget runs out it is Unknown "budget exhausted". A Disproved counterexample is replayed on the unflattened `OpenNets`; if replay fails the verdict is Unknown "internal error". A supervisor joins the worker, and a join error becomes Unknown "internal error". An edit that changes the hash sets the cancel flag. Cancel produces Unknown "cancelled".
- **Replay:** `VerdictReport.replay` carries every frame, already mapped to elements in the engine through provenance. Stepping happens only in the UI (`replay.step`, arrow keys), with no IPC per step. Each element component subscribes to the boolean `isHighlighted(id)`, so a step re-renders only the elements that change. An `aria-live="polite"` region announces "Step 3 of 7: Billing fires take_lock". If the scope is in another view, the UI navigates there first.
- **Scan:** `run_scan()` runs `scan::run(&snapshot, &rules)` on a worker and returns findings tagged with `rev`. A newer `rev` marks them stale. Suppress is an `Edit`, so it can be undone.
- **File changed on disk:** the watcher thread (debounced) ignores the engine's own writes, which it recognizes by content hash, and re-reads the changed files. If they are clean in memory, a `Reload` Batch Edit is applied (it can be undone). If they are dirty, a conflict is reported. Both reach the UI through the `project-changed` event. Slice 0 uses a manual Reload command instead.

## 5. Concurrency and IPC
- `Mutex<Session>` lives in Tauri managed state, and commands are `#[tauri::command(async)]` with short critical sections. Check workers, the scan worker and the watcher are std threads. tokio exists only in `src-tauri`.
- Ordering: `store/actions.ts` serializes calls through one promise queue. A `Change` with `rev != local+1` triggers `get_view` to refetch.
- Panic hook: on `check-*` threads it logs and lets the panic unwind (handled by join, ADR 0006). On any other thread it flushes the log and calls `abort()`, so a poisoned session can never keep serving a half-applied model.
- The UI store holds `projection` (Maps by ID plus `rev`), `ephemeral` (selection, overlay, inline edit), `doc` (dirty, canUndo), `checks` (by PropertyId: verdict, progress, running), `replay` and `findings`. It never holds the model.

## 6. How it grows
- **State machines:** a `BehaviorModel::StateMachine` variant, a compile step in lowering and `ReplayFrame.activeState`. No new seam.
- **Cross-level composition:** lowering recurses over children. The `Session` API is unchanged.
- **Code import:** returns `Edit::Batch`, so it can be undone and is journaled like any gesture.
- **Code proofs:** a `trait Prover` runs Kani or Verus as child processes under the same `JobRegistry`, with contract statuses as a new report type.
- **Scan rules:** added to the `scan` registry. **CLI:** a binary over `engine::Session` with an `Fs` adapter, reusing everything.
- What stays: `Edit` as the only write path, and the UI as a projection.

## 7. Testing
- `model`: proptest checks that `apply(apply(m,e).inverse) == m` and that random Edit sequences keep the model valid.
- `format`: golden files, round trip and migration fixtures.
- `engine`: `Session` tests with in-memory `ProjectFs`/`JournalStore`, a fake clock and a scripted watcher, covering crash and restore, conflicts and cancel.
- `verify`: unit tests, `simple_bfs` versus `explore` differential, and the TAPAAL corpus in CI.
- Contract: a Rust test writes `Change` and `VerdictReport` JSON fixtures, and Vitest feeds them to the store (`mockIPC`).
- UI: Testing Library by role and label, a keyboard-only canvas pass and axe. A few wdio e2e tests.

## 8. Trade-offs
- **Strengths:**
  - One source of truth, and every domain rule lives once, in Rust.
  - Undo, journal and staleness all hang off one `Edit` stream.
  - The CLI and future agents get editing for free.
  - Small IPC payloads per gesture.
- **Weaknesses:**
  - Every committed gesture costs an IPC round trip (expected to be a few ms, unmeasured on WebKitGTK), and inline edits need a pending state.
  - Each `Edit` variant needs a hand-written inverse and a projection patch.
  - Two mirrors of view data (projection DTO versus React Flow nodes).
- **Cost:** baseline (1.0x). Slice 0 needs `Session` without history or journal, about 15 commands and the store.
- **Main risk:** round-trip latency on drag stop and text edits making the editor feel sluggish on WebKitGTK. Measure it in the E4 spike.

## 9. ADR conflicts
None. The design follows ADR 0004 as written. The panic hook extends ADR 0006: a panic on the session thread aborts the app like a panic on the main thread does.

This is the cleanest reading of ADR 0004 together with ADR 0008 among the six designs.; simple_bfs is a separate module whose use list is lint-checked to contain only net types. Independence is enforced, not left to discipline.; The panic hook aborts on any non-check thread, so a poisoned session can never keep serving a half-applied model. This is a sound extension of ADR 0006.; Strong slice discipline: slice 0 Session has no history or journal and uses a manual Reload command, matching v1-slices.md.; Thoughtful UI work: replay frames are mapped to elements in the engine, stepping is local, each element subscribes to a per-element isHighlighted boolean, aria-live announces steps, and replay navigates to the scope's view. - Risks: Edit carries a hand-written inverse per variant, and the journal stores Edits (commands), not after-images. Recovery then depends on apply staying deterministic across releases, and every new Edit variant brings a new inverse to get wrong. It extends ADR 0006 with abort on non-check threads, which is consistent. ADR 0005: the key is computed on the flattened net and only a key change cancels a check. ADR 0008 is satisfied. ADR 0001 is satisfied in outline but weak on torn-Save recovery. Glossary use is correct (verdict, counterexample, replay, stale, suppression).

### By the senior backend developer: 7/10, adapt

- Strengths: Like A1: a single Rust-owned model, a pure model::apply, the Edit enum as the only write path, ports for fs, journal and sink, and a CLI or code import that gets editing for free.; A panic hook that aborts on every thread except check-* closes the gap where a poisoned Mutex<Session> could serve a half-applied model. It is the correct reading of ADR 0006.; Journal restore checks base file hashes before re-applying, which avoids silently reverting a git checkout.; rev on every Change, and refetch on a gap, give the UI a clear consistency rule. - Risks: simple_bfs runs on the same flattened Net as the main explorer. A deterministic flattening or lowering bug then produces two agreeing Proveds about the wrong net, which is the one failure the project must never have. Only Disproved is cross-checked against OpenNets. Adopt A1's 'second explorer on the Composite'.; Undo through hand-written inverse Edits adds code that must be correct for every Edit variant, while snapshot undo over imbl gives the same result for free, and the design already uses imbl.; The journal stores Edits, so the Edit enum becomes a persisted format that needs versioning across upgrades. A state-based journal of file contents reuses the existing format and migrations.; Reload is an undoable Batch Edit, so undoing it reverts an external change in memory, and the next Save overwrites the checked-out files. Either accept this explicitly in the UI or clear the history, as A1 does.; Each Edit variant also needs a hand-written ViewPatch. A diff over Touched would avoid two parallel per-variant code paths.; Keeping simple_bfs independent through a lint-checked use list is weaker than a crate boundary (see C3's recheck crate).; The cache has the same issue as the other designs: do not serve cached 'budget exhausted' or 'cancelled' Unknowns once the budget changes.

ADR 0008 is met in letter but only weakly in spirit, because the Proved cross-check does not cover flattening. Glossary terms are used correctly, including Unknown 'cancelled' and Suppression as an undoable edit.
