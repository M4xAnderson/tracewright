# Software design

As of 2026-11-02. Synthesized by the software architect (Fable) from nine candidates (combine, based on B1, A1, C1, C3, B2, A2, C2, B3) and revised after the panel review in `final-reviews.md`. Every must-fix item is resolved in the text below; the disposition of the should-fix items and lost ideas is the last section. Candidates and their reviews are in `candidates/`.

## Rationale

Backbone: B1 (snapshot core, functional core + imperative shell). It scored highest with both reviewers, keeps ADR 0004 as written, is the smallest design that meets slice 0, and its single Rust-owned Model gives the one structural guarantee that matters most: the net that is checked is lowered from the same value that Save renders. Persistent-map snapshots make undo and the ADR 0005 "undo restores the verdict" rule a lookup, and state-based after-images give an idempotent journal with no hand-written inverses.

Taken from A1: the second explorer never sees the engine's flattened net; it composes the `OpenNets` itself and checks every piece of evidence (exploration, certificate, counterexample) against its own composition, so it also cross-checks composition. Also A1's Disk/Sink/Clock ports with MemDisk and a recording Sink, the CLI as Session + std adapters + stdout Sink, Command::Batch for layout and import, own-save echoes dropped by content hash, PollWatcher under /mnt.

Taken from C3: crates/net and crates/recheck with CI rules on the dependency graph, which turns ADR 0008's "no shared code" into a fact (now sharpened: `net` holds data and canonical encoding only, no semantics); the "derived equals fresh rebuild" proptest oracle; the worker hashes the net it actually explores; dangling references as a derived function. C3's memo/query layer is rejected (a memo in the trust path can show an old Proved as current); the useful core of its subscription protocol, a `sync()` call that returns a consistent snapshot of derived state, is kept.

Taken from C1: replay on plain nets (now in recheck, on its own composition), the panic hook, strict slice discipline (slice 0 Session without history or journal, manual Reload), one ordered promise queue in store/actions.ts for mutating commands, Rust-written JSON fixtures consumed by Vitest, per-element highlight selectors, aria-live step announcements, replay navigates to the scope's view. C1's hand-written inverse Edits and command-journal are rejected in favor of B1's snapshots and after-images.

Taken from B2/A2 (the actor/op-log designs, rejected as backbones): the single-writer ordering guarantee, kept without the actor as one ordered derive thread per Session that owns all post-apply work (journal append, lowering, CheckKeys, cancel decisions, currentKeys) in revision order; SaveBegin/SaveDone brackets and base file hashes in the journal; journal records as TOML fragments so format migrations cover the journal; revision on every projection update with `sync()` on a gap; split applied/keys events so the canvas never waits for lowering; progress throttled to 4/s; Given/When/Then session tests with an injectable Spawner and Clock; kill-the-process crash tests; code import as one reviewable Batch. Wrapping the whole Session in one thread stays a two-way door. A2's supervisor-rebuild of the Session after a panic is rejected (ADR 0006: no state is recovered); A2's parallel explorers are rejected in favor of sequential explorers on one split budget.

Taken from C2/B3 (UI-owned designs, rejected): the UI rule "never render a verdict as current unless the keys are fresh for the displayed revision and match", lowering validates its input as untrusted, raw ipc::Response for the one-time load if it exceeds ~50 ms, the check registry indexed by scope, and the overlay-until-Applied rule for drag and rename. A3/B3/C2 are rejected as a whole: the UI would assemble the scope that Rust proves, so a UI bug yields a Proved about a model the user is not looking at. Reviewer fixes applied across the board: cache only Proved and Disproved by key, Save renders and writes outside the lock and never over a file that changed on disk, CheckKey hashes the canonical encoding of the net plus property, a discriminated-union VerdictDto so Unknown can never look like success, and a typed Unknown reason.

## ADRs written with this revision

- ADR 0009 (amends 0004): `crates/net` (data, constructors, structural validation, canonical encoding; no firing rule, no predicate evaluation, no composition) and `crates/recheck` (own composition, plain BFS, replay, certificate check); `crates/interop` (PNML, dev-only for now); std adapters in `engine::adapters`; CI rules on crate edges and on `net` having no semantics.
- ADR 0010 (amends 0008): the second explorer composes `OpenNets` itself and checks exploration, certificates and counterexamples against its own composition; the normative net semantics; evidence per property kind; the budget split.
- ADR 0011 (new): Rust-owned Model snapshots, the UI as a revisioned projection, and the journal as a revision-ordered log of after-images with base hashes and SaveBegin/SaveDone, written by one ordered writer.
- ADR 0012 (amends 0006): supervised threads (`check-*`, `lower-*`, `derive-*`, `scan-*`, `save-*`) unwind to join and their failure becomes Unknown "internal error" or a failed Save/scan; a panic under the Session lock or on the main thread aborts.
- ADR 0013 (amends 0005): the cache stores only Proved and Disproved under their CheckKey; a key covers the canonical encoding of the net plus property; invariance and fitness tests.
- ADR 0014 (new): every place declares what happens when it is full: `block`, `drop` or `overflow`; generated places default to `overflow`, places inside a behavior model must choose; an overflow marking is a violation state that is not expanded.

Revised 2026-11-02 after the Track A consistency review (`docs/specs/decisions.md`, D-37). ADRs written with that revision:

- ADR 0015 (amends 0002, 0003): a combined-scope property names place ports and generated places; a state machine's events are transition ports, its states place ports, its internal events no ports; integer weights, negative allowed.
- ADR 0016 (amends 0002, 0010): binding pairs with their own direction (a call and its reply on one relationship), bare-name fused IDs, set-valued `AsyncLink`, at most one asynchronous binding per port, children = elements whose parent is the scope element, `NothingToCheck`.
- ADR 0017 (amends 0008, 0010, 0014): "never p" evaluated on overflow markings, the `NoOverflowPlace` certificate, "capacity exceeded first" payload, the per-property overflow readings, the closed list of seven Unknown reasons, a failed replay is "internal error".
- ADR 0018 (amends 0010, 0013): the final predicate is a parameter of `DeadlockFree`, arrives in slice 1 in a minimal form; slice 0 keeps predicate strings opaque.
- ADR 0019 (new): templates stored by kind, version and parameters and expanded at lowering; predicates hashed as parsed; vacuity guard; built-ins seeded explicitly.
- ADR 0020 (amends 0001): lowercase slug IDs, `suppressions.toml`, per-file format version, read-only second window, unknown kind per file, name clashes as model problems.
- ADR 0021 (amends 0012): stated scan attributes, suppression dispositions, one supervised thread per rule, `cancel_scan`.

# Design: Rust-owned snapshot session, projection UI, independent recheck

## 1. Idea
The Rust `engine` owns the one authoritative Model as an immutable, structurally shared value. A gesture arrives as a typed `Command`; `model::apply` is a pure function that returns a new Model plus state-based before/after images of the touched entities. Lowering, CheckKey, scan, file rendering and projection are pure functions of a Model value. A thin imperative shell, `engine::Session`, holds the current snapshot, the saved snapshot, the undo stack, the kept TOML documents, the verdict cache and the check registry, and talks to the world through small ports (Disk, Journal, Sink, Clock, Spawner). Everything that follows an apply (journal, lowering, keys, cancel, events) runs on one derive thread in revision order. The UI never holds the Model: it holds a revisioned projection of the open view plus ephemeral state (selection, drag overlay, replay step).
Evidence for a verdict is produced by code that cannot share a bug with the code that built the net: `verify` explores the engine's flattened net; `recheck` (a crate that CI forbids from depending on `verify` or `engine`) composes the `OpenNets` itself, compares its composition with the engine's, re-explores it with a plain BFS, replays every counterexample on it and checks every certificate against it. Style: functional core, imperative shell, hexagonal ports in the small, UI as a projection.

## 2. Structure
```
app/ui ──invoke + one Channel<EngineEvent>──> app/src-tauri (async commands, Mutex<Session>, TauriSink; tokio only here)
                                                    │
                                                    ▼
            crates/engine  Session, lower (Model -> OpenNets -> Net), check_key, CheckRegistry, VerdictCache,
                           reconcile, derive thread; ports Disk/Journal/Sink/Clock/Spawner; adapters (std only)
              │        │        │         │        │
          format     scan    verify    recheck    net ◄── interop (PNML, dev-only)
              │        │        │         │        ▲
              └──> model ◄──┘   └──> net ◄┘────────┘   CI: recheck -/-> verify, recheck -/-> engine, verify -/-> recheck
```
- `model`: Element, Relationship, Behavior model (PetriNet | StateMachine), Port, Property, Layout, Suppression on persistent maps (`imbl`); `Command`, `apply`, `validate`, slug IDs with collision suffix. No IO.
- `net`: `Net`, `OpenNets`, `NetProperty`, `Marking`, `Counterexample`, `Evidence`, `Budget`, `NetVerdict`, and `net::encode::canonical`. Data, constructors, structural validation and canonical encoding only: no `enabled`, no `fire`, no predicate evaluation, no composition. A CI check fails if `net` has an `impl` block outside `encode.rs`, `validate.rs` and derives.
- `verify`: main explorer (later stubborn sets, P-invariants, ILP) with its own firing rule, capacity rule and predicate evaluation. Depends only on `net`.
- `recheck`: `compose`, `explore` (plain BFS, no reductions), `replay`, `check_certificate`, each with its own firing rule, capacity rule and predicate evaluation written from the spec in ADR 0010 and 0014. Depends only on `net`.
- `format`: TOML directory read/write on `toml_edit` (kept `DocumentMut` per file, edited in place on Save), migrations, journal record codec (TOML fragments).
- `scan`: `Rule` trait and the rule set over `&Model`. Depends only on `model`.
- `engine`: `lower`, `flatten`, `check_key`, `check` (the worker pipeline and the checked `Verdict`, D-53), `Session` (internally `Document`, `Verification`, `DiskSync`, `Derive`), `CheckRegistry`, `VerdictCache`, projection, reconcile; `engine::adapters` with `StdDisk`, `FileJournal`, the notify watcher (std only). The only core crate with IO, behind ports.
- `interop`: PNML writer for `net::Net` (dev-only, for the TAPAAL corpus); later Structurizr, LikeC4 and counterexample export (ITF).
- `app/src-tauri`: about 15 `async` commands, `TauriSink`, the panic hook. `app/ui/src`: `ipc/` (ts-rs types + wrappers; the only module that imports `invoke`), `store/` (Zustand; `store/actions.ts` is the only caller of `ipc/`), `features/canvas` (React Flow, `layout.worker.ts` with elkjs), `features/verify`, `features/scan`, `features/inspector`.
Rules checked in CI: crate edges from `cargo metadata` (`recheck -/-> verify`, `recheck -/-> engine`, `verify -/-> recheck`, `verify -/-> model`, tokio and tauri only in src-tauri); the `net` rule above; UI imports with dependency-cruiser; `git diff --exit-code` after `cargo test` for ts-rs bindings and JSON fixtures.

## 4. Main flows
- **Open (slice 0):** `Disk::read_tree` → `format::load` (migrations; the parsed `DocumentMut` of every file is kept) → `validate` into the load report → `Session { current, saved: current, rev: 0, last_seen }`. From slice 1, journal restore runs first: records past the base are offered only if every file named in the base matches its base hash, or, for a journal ending in `SaveBegin` without `SaveDone`, matches either its base hash or the hash recorded in `SaveBegin`; otherwise the journal is set aside with a message, never overlaid. The offer has "restore N gestures" and "open without restoring" (set aside). Restore renames the journal to `.restoring` before applying, so an app that dies during restore offers only "open without restoring" next time: no crash loop. Then the derive thread derives rev 0 (keys for every property), every property is queued for a check (ADR 0005) and the UI calls `sync()`.
- **Edit (slice 0) and undo (slice 1):** drag, rename and inspector edits keep an ephemeral overlay until an `Applied` with `rev >= request.rev` arrives (`Rejected` clears it and announces the reason). Under the lock: `model::apply`, push the old `Arc<Model>` onto `undo`, `rev += 1`, `project(current, view)`, enqueue `DeriveItem { rev, model, changes }`, unlock, reply `Applied`. The derive thread (one per Session, `derive-<n>`) takes items strictly in rev order: (1) append the after-images as one `JournalRecord { rev, images }` (slice 1); (2) for every scope that contains a touched element, on a child thread `lower-<rev>` that is joined: `lower` once per scope, then per property of that scope `lower_property` (D-64) and, on `Ok((p, expansion))`, `check_key(flat, p)`; the `(p, expansion)` pair travels with the key into any later `CheckRequest`; then (slice 2) `check_lowering` for a scope with a state machine; a failure or a panic there gives `KeyState::Unknown(InternalError)` for those properties, logged, and the app goes on; a scope with nothing to check gives `KeyState::NothingToCheck`; `lower_property` returning `Err(diags)` gives that property alone `KeyState::Unknown(PropertyNotCheckable(lines))` with the lines in property-language §10.1 order; (3) under the lock, only if `rev > verification.keys.rev`: store the complete key set with its rev, cancel running checks whose key is not in the set and not needed by a queued request, attach cached verdicts to keys that have one, and emit `currentKeys { rev, complete set }`. Items older than the stored rev make no cancel decision and emit nothing (a newer item follows). The canvas never waits on lowering. Undo pops a snapshot and goes through the same path (the restored images are journaled with the new rev); a key restored with a cached verdict is current again; a restored key with no cached verdict and no running check is resubmitted.
- **Current, pending, stale (UI):** `keysFresh = currentKeys.rev === projection.rev`. A verdict renders as current only if `keysFresh` and `currentKeys[p].key === verdict.key`. While keys are not fresh every verdict renders as "pending re-evaluation" (neither current nor success); with fresh keys a non-matching verdict renders stale (slice 1) or is dropped (slice 0). `currentKeys` with a rev lower than the last applied is dropped. A `{ unknown }` key renders as Unknown with its reason without a check.
- **Save (slice 0):** `save` returns at once; completion is the `saved` event. Under the lock: if a Save is in flight, mark "save again after" and return; otherwise take `Arc` snapshots of `current` and `saved` and `rev`, diff by `Arc::ptr_eq` per entity into `FileWrite`s (Put and Delete, each with `expected = last_seen[path]`, `None` for a new file), register the new hashes in `pending_writes` (echo filter), enqueue `SaveBegin { rev, files, hashes }`, unlock. On `save-<rev>` (via `spawn_blocking`): wait until the derive thread has appended every record with rev ≤ snapshot rev; render each file (an existing file by editing its kept `DocumentMut` in place, replacing only the tables that changed and removing deleted keys, so comments and formatting outside the edited values survive; a new file canonically); `write_atomic` writes temp + fsync + rename per file and fsyncs the directory, but first re-hashes each target: a file whose hash differs from `expected` is skipped and reported as a conflict "changed on disk since load; Reload first". Then enqueue `SaveDone { rev, written }`, which the derive thread turns into `Journal::rebase(base = written hashes, keep_after_rev = rev)`: records newer than the snapshot are never dropped. Lock briefly: `saved = snapshot` for written entities (skipped entities keep their old saved image), update `last_seen` and the kept documents, release the guard, run the queued Save if any, emit `saved { savedRev, conflicts, failed }`. UI: `dirty = savedRev !== rev`. A partial failure keeps the journal; after-images are idempotent, so recovery on a torn Save converges.
- **Check (slice 0):** `run_checks(scope)` waits until keys for the current rev exist (condvar on the derive thread), then per property: `KeyState::Unknown` → emit that Unknown; `KeyState::NothingToCheck` → nothing runs and the panel shows the key state; cache hit → emit Proved/Disproved (after `sm_replay` for a scope with a state machine, slice 2; a failure evicts the entry and resubmits); a request with a running key attaches to it; otherwise `CheckRegistry::submit(CheckRequest)` (FIFO, at most `available_parallelism - 1` running, indexed by scope). The worker is a named std thread `check-<key8>` owning `Arc<Lowered>` and the cancel flag. Pipeline: (0) `own = recheck::compose(open)`; if `encode::canonical(own) != encode::canonical(flat)` → Unknown "internal disagreement" (logged; cheap and property-independent). (1) `verify::check(flat, p)` with at most half of the markings and half of the time; verify's visited set is dropped before step 2. (2) Proved by exhaustion → `recheck::explore(own, p)` on the rest of the budget (the remaining markings and the remaining wall clock): agreement gives Proved, disagreement Unknown "internal disagreement", budget out Unknown "budget exhausted while re-checking", never Proved; Proved by certificate (`NoOverflowPlace` in slice 0, emitted by `verify` without exploring) → `recheck::check_certificate(own, p, cert)` on recheck's composition; a rejection gives Unknown "internal disagreement". (3) Disproved with `Evidence::Counterexample` → `recheck::replay(own, cx, p)`; a failed replay gives Unknown "internal error". `Evidence::Exhaustive` and the exhaustive part of `CounterexampleThenExhaustive` are confirmed exactly like a Proved by exhaustion: `recheck::explore` (from the initial marking, or from the counterexample's last marking after replaying it) must agree; budget out gives Unknown, never Disproved. An Unknown "capacity exceeded first" has its run replayed the same way. (3b, slice 2) for a scope with a state machine, `engine::sm_replay` then checks every counterexample and the "capacity exceeded first" run in state machine terms (SM §7.4); a failure gives Unknown "internal error". (4) the worker recomputes the key from the `flat` it explored and returns `(CheckKey, Verdict)`, the `Verdict` carrying the request's `Expansion`; the `NetVerdict` candidates of step 1 and 2 never leave the pipeline (D-53). For a Disproved `never p` or always reachable p, the predicate values shown are computed by `engine` from the last marking of the counterexample that `recheck::replay` accepted, one per atom; `Violation::Predicate.value` from `verify` is never displayed (D-64). A monitor thread joins the worker; a join error (panic) gives Unknown "internal error" (ADR 0006). The monitor locks the Session only to store Proved/Disproved in the cache under that key, record the Unknown for display, build `ReplayFrame`s through the current `OriginMap`, and emit `verdict`. Progress is throttled to 4/s per check. Cancel (slice 1) sets the flag; explorers poll it every 1,024 expansions; the result is Unknown "cancelled".
- **Replay (slice 0):** the cache holds the `Verdict`; frames are rendered through the scope's current `OriginMap` whenever a verdict is emitted or attached to `currentKeys`, and names are resolved from the projection at render time, so a rename never shows old labels. The UI steps locally (arrow keys, scrubber, random access through full markings), navigates to the scope's view first, each element subscribes to its own `isHighlighted(id)` boolean, and an `aria-live="polite"` region announces the step text of the flows spec (`R-STEP-*`, for example "Step 3 of 7: Billing: take_lock"). The last frame carries `violation` (slice 0 criterion: the generated place and its capacity; a deadlock names which transitions wait for which tokens). On a stale verdict, frames that refer to deleted elements are dimmed.
- **Scan (slice 5):** `run_scan` (explicit in slice 5) clones `Arc<Model>` and runs **one supervised thread per rule**, `scan-<n>-<rule-id>` (ADR 0021); a monitor joins them and emits `findings` with the `NotCheckable` entries, tagged with the **scan input hash** of scan-rules §3.9 (`scanHash`; a different hash renders them stale). A panic in one rule becomes a finding entry "internal error" for that rule and the other rules' findings stand, without `catch_unwind` (ADR 0012). `cancel_scan` sets a shared flag that every rule polls; the event then carries `cancelled: true` and no findings. Suppress is a Command with `disposition`, `reason` and `date` (the engine fills `date` from `Clock::today()`), so it is undoable and journaled; editing a suppression issues `Suppress` again and `DeleteSuppression { key }` removes one; suppressions without a finding are listed at display time (D-52).
- **Reload (slice 0) and file changed on disk (slice 1):** both call `Session::reconcile(paths)` under the lock; slice 1 adds the notify debouncer (500 ms; `PollWatcher` under `/mnt`). A file whose hash equals `last_seen` or `pending_writes` is our own write and is ignored; a file whose content equals `render(current)` is a no-op that updates `last_seen`. A clean entity adopts the disk version through `Command::AdoptFromDisk` (one undoable entry, so a `git checkout` is one step; it also updates `saved`, `last_seen` and the kept document; undoing it does not restore `saved`). A dirty entity whose file changed is a conflict with "keep mine" / "take disk"; in slice 0 this is a confirm dialog over all conflicts. Nothing is overwritten silently in either direction. A parse error is reported and the in-memory Model is kept. Adoption goes through the derive thread like any gesture.

## 5. Concurrency and IPC
- Threads: Tauri main thread; Tauri's tokio runtime for `async` command dispatch (every command is `async`; Save, Reload and journal IO run through `spawn_blocking`); `Mutex<Session>` in managed state, held for apply + projection (target < 10 ms at 300 elements; measure in E4), never during lowering, journal IO, rendering or a check; one `derive-*` thread per Session with `lower-<rev>` children; one worker plus one monitor per running check; one `scan-<n>-<rule-id>` per rule plus a monitor per scan; `save-<rev>`; the watcher thread. There is one lock, so lock ordering cannot go wrong.
- Ordering (the invariant that replaces the actor): `rev` is assigned under the lock; the derive queue is filled under the lock in rev order and drained by one thread, so it is the only writer of the journal and the only producer of keys; a key result or cancel decision for a rev lower than the stored one is ignored under the lock; `SaveBegin`/`SaveDone` travel through the same queue, so the journal is totally ordered per revision. The loss window on a crash is the gestures still in the derive queue (ADR 0001 tolerates the last gesture); E4 measures fsync on WSL2 and Windows.
- Commands: `open_project`, `sync` (registers or replaces the Channel and returns `Sync` under the lock), `view(id)`, `apply`, `undo`, `redo`, `save`, `reload`, `run_checks`, `cancel_check`, `run_scan`, `cancel_scan`, `resolve_conflict`. A read-only session (the journal lock is held by another window, ADR 0020) rejects `apply`, `undo`, `redo`, `save` and `resolve_conflict` with one reason. Errors are one tagged enum `{ kind, message }`. The one-time load uses raw `ipc::Response` only if E4 measures JSON above ~50 ms.
- UI ordering: `store/actions.ts` serializes only model-mutating commands (`apply`, `undo`, `redo`, `reload`, `resolve_conflict`) through one promise queue; `save`, `run_checks`, `cancel_check`, `run_scan` and `cancel_scan` bypass it. The projection rev advances only through `Applied`, `diskChanged` and `Sync`; `rev != local + 1` calls `sync()`. `currentKeys` is latest-wins by rev; verdicts are matched by key. A webview reload or HMR calls `sync()` again, which replaces the Channel.
- Panic hook (ADR 0012): threads named `check-*`, `lower-*`, `derive-*`, `scan-*`, `save-*` (later `import-*`, `proof-*`) unwind to join; the joiner maps the error to Unknown "internal error", a failed Save or scan, or an `internalError` event. Any other thread (main, a command thread under the lock in `apply` or projection) logs, flushes and `abort()`s, so a poisoned Session never serves a half-applied Model. The derive thread owns no state (its inbox belongs to the Session), so after it dies the Session re-spawns it on the next command and reports the record that was lost.
- Memory: explorers count stored markings against `Budget::max_markings`, with bytes estimated as markings × places × 4; the registry keeps the sum of running budgets under a configured share of RAM. The cache is an LRU by bytes; the undo stack has a configurable depth.
- UI store: `projection` (Maps by ID + `rev`; the reducer keeps object identity for structurally equal nodes), `ephemeral` (overlays, selection), `doc` (savedRev, canUndo, canRedo), `currentKeys` (with rev), `verdicts: Map<PropertyId, {key, verdict}>` with current/pending/stale derived in render as in section 4, `findings`, `replay`. Highlights live in a separate set driven by selectors. Dangling relationship ends are explicit in the projection (`danglingEnd`) and listed in a problems panel; port changes call `useUpdateNodeInternals`. Global Ctrl+Z is ignored while focus is in a text input.

## 6. Net semantics (normative summary; full text in `docs/specs/net-semantics.md` revision 3 and ADR 0010, 0014, 0016, 0017, 0018)
- **Lowering is total or fails.** `lower(m, scope)` returns `LowerError::ModelIncomplete(details)` for any dangling element or port reference in a relationship of the scope, any transition port of a child in a combined scope that no contributing relationship binds, any child in a combined scope without a behavior model (or with one that did not load), any place without `when_full`, any name clash inside an element, and any structural failure of a part or of the flattened net. It never produces a smaller net. The error surfaces as `KeyState::Unknown(ModelIncomplete)` with a line per cause ("billing/take_lock not found", "shipping has no behavior model"). A **child** of a combined scope is an element whose `parent` is the scope element; a scope with no child that has a behavior model is `KeyState::NothingToCheck` and gets no verdict (ADR 0016). A relationship that binds no ports, or whose two elements are not both children, contributes nothing and is listed as an assumption in the verdict. In an element's own scope, its ports are closed: a transition port fires on its own and a place port is a plain place; the verdict carries the closed-port note. A property of a combined scope names only place ports of children (states included) and generated places; in an own scope any place (ADR 0015). A dangling or non-port reference in a property or in the final predicate never fails lowering: it ends only that property (for the final predicate: the deadlock-free and T7 "done" properties of that behavior) as `KeyState::Unknown(PropertyNotCheckable)` with the PL E2xx line (ADR 0017, D-47).
- **Qualified IDs.** Own place, transition or state: `element/name`; fused transition: `relationship/caller+callee` with the bare transition names; generated place: `relationship`. Both compositions use this rule, so their canonical encodings are comparable byte for byte.
- **Firing rule.** `t` is enabled in `M` iff `M` is not an overflow marking, every pre place holds at least the arc weight and, for every post place with `block`, the count after firing is at most its capacity. Firing removes and adds the weights; a `drop` place keeps at most its capacity (surplus discarded); an `overflow` place may exceed its capacity, and the resulting marking is an **overflow marking**.
- **Overflow marking.** A violation of "no capacity exceeded" (Disproved with the counterexample leading to it); not expanded further; not a deadlock; not final. "Never p" is evaluated on it, so a p-marking reached as an overflow marking is Disproved by its run (ADR 0017). For every other property: a violation found without passing through an overflow marking is Disproved; Proved requires that no overflow marking is reachable; if one is reachable and no violation was found, the verdict is Unknown "capacity exceeded first", naming the smallest-ID exceeded place of the first overflow marking with the run to it and suggesting `block`, `drop` or a larger capacity; "no dead transitions" is Unknown whenever one is reachable. "No capacity exceeded" on a net without an `overflow` place is Proved by the `NoOverflowPlace` certificate, which `recheck` checks on its own composition and whose verdict names the drop places.
- **Bindings (ADR 0002, 0016).** A relationship holds binding pairs, each with its own direction, so a call and its reply sit on one relationship. Sync: one fused transition per (relationship, caller transition, callee transition), pre and post the union of both; a bound port transition does not fire on its own. Async: one generated place per relationship with its capacity and `when_full` (default `overflow`); every transition of the sending port puts one message into it and every transition of the receiving port takes one (set-valued `AsyncLink`; a Petri net port is a one-element set). A transition port is in at most one asynchronous binding and is never both fused and asynchronously bound. Places inside a behavior model declare `when_full` explicitly; state places of a compiled state machine are `overflow`.
- **Properties.** Deadlock: no transition enabled and the marking is not final. The final predicate is a parameter of `DeadlockFree`, copied by lowering from the scope element's `[final]` for that behavior (slice 1, minimal form; slice 0 lowers `final none`), so editing it stales only deadlock-free and, from slice 4, a "can always get back to" template with the done preset, whose expansion is the final predicate (ADR 0018, ADR 0022). No dead transitions: Disproved with the set of transitions enabled in no reachable marking (exhaustive evidence). Always reachable p: from every reachable marking some p-marking is reachable; Disproved by a counterexample to a marking from which neither a p-marking nor an overflow marking is reachable (counterexample, then exhaustive evidence). Never p: Disproved by a counterexample whose last marking satisfies p, which may be an overflow marking.
- Golden tests in E1 cover every rule above; both explorers are written from the spec text, not from each other.

## 7. How it grows
- **Net editor (slice 1):** a `BehaviorView` projection (places, transitions, arcs, ports, initial marking) and a `BehaviorLayout` entity in the element's own layout file `layouts/<id>.toml` (ADR 0001, ADR 0024), with replay highlights inside the editor. Also in slice 1: `model::property` (the one lexer, parser, normalization and resolution of net-semantics §5.3) and `Pred` evaluation in both explorers, used only by the final predicate; the "done when" editor offers the minimal form (a conjunction of `place = n`, or the sum atom over a state machine's final states) and `Command::SetFinal` (ADR 0018).
- **State machines (slice 2):** `BehaviorModel::StateMachine` variant and Commands; `lower` compiles to a 1-safe part of `OpenNets` (state places `overflow`; an event's transitions form the sets of an `AsyncLink`); `OriginMap` gains `Origin::State` and `Origin::SmTransition`, so `ReplayFrame.activeState` is filled; `Lowered.snapshot` feeds `check_lowering` (run by the derive thread after lowering) and `engine::sm_replay` (SM §7.4), which checks every counterexample at model level before frames reach the UI; a failure is Unknown "internal error". `net`, `verify` and `recheck` are untouched, because set-valued `AsyncLink` (ADR 0016) landed with slice 0.
- **Drill-down (slice 3):** `lower` walks a scope subtree; `OpenNets` stays flat (slice 3 excludes composition across levels). Contract refinement, when scheduled, becomes a technique in `verify` with its certificate checked in `recheck` against `recheck`'s composition. Per-child reuse (R4 stage 3) would memoize `lower` per child behind the oracle test of section 8; the worker still hashes the net it explores.
- **User properties (slice 4):** `NetProperty::Never/AlwaysReachable` and `Pred` already exist and `model::property` parses since slice 1; templates are stored by kind, version and parameters and expanded at lowering into one `NetProperty` (ADR 0019); the vacuity guard runs "no dead transitions" next to user properties. Before slice 4 such entries are `KeyState::Unknown(PropertyNotCheckable)`. Once `verify` gains stubborn sets, `recheck`'s BFS supplies the shortest counterexample for display.
- **Code import:** `crates/import` produces `Command::Batch`, previewed as a diff; the UI runs ELK on the preview in `layout.worker.ts` and applies `Batch(import ++ MoveElements)` as one undoable, journaled gesture; `position` is optional in the projection ("unplaced"), so the CLI can import without layout. `code_facts` and conformance are derived functions.
- **Code proofs:** a `ProofRunner` port in `engine` runs Kani or Verus as child processes under the same registry (cancel kills the process); outcomes live in memory keyed by an input hash like verdicts (ADR 0005) and go stale the same way.
- **Scan rules:** another `impl Rule`. **CLI:** `crates/cli` builds a `Session` with `engine::adapters` (StdDisk, FileJournal or a no-op Journal, the watcher for a `watch` mode) and a stdout `Sink`, so load, apply, check, scan and export all reuse `engine`.
- **If races remain** after the derive thread: wrap the whole `Session` in one thread with an inbox (B2) without changing its API. Two-way door.
What stays the same: `Command` as the only write path, the ports, `net` as the only vocabulary shared by `verify` and `recheck`, the derive thread as the only writer of derived state, and the UI as a projection.

## 8. Testing
- `model`: proptest that `apply` keeps invariants (unique IDs, ports exist, capacities > 0, `when_full` present); applying before-images after after-images restores the original; applying after-images twice equals once; golden tests for slug collisions.
- `net`/`verify`/`recheck`: the E1 golden examples, one per rule of section 6 (block, drop, overflow, overflow and deadlock-free, never p at an overflow marking, fusion per caller, call and reply on one relationship, set-valued asynchronous binding, unbound port, `NoOverflowPlace` accepted and rejected, final predicate in the property line) and the conformance vectors of net-semantics §14; proptest on random bounded `OpenNets` that `verify::check(engine::flatten(o))` and `recheck::explore(recheck::compose(o))` agree and that the two canonical encodings are equal; the TAPAAL differential corpus through `interop`'s PNML writer in CI (dev-only); `check_key` fitness: every semantic mutation changes the key, no layout or name change does; invariance: a model built in another insertion order, rebuilt from files, or after an undo-redo cycle gives the same key.
- `engine`: Given/When/Then Session tests with `MemDisk`, an in-memory `Journal`, a recording `Sink`, a fake `Clock` (`now` and `today`) and an inline `Spawner` (no threads, no sleeps): stale, undo restores the verdict, cancel only on a key change, torn Save recovery, journal base-hash mismatch, conflict on a dirty entity, Save skips a file changed on disk, concurrent Save requests coalesce, the verdict for an old key arrives before `currentKeys` and is not current, an apply and an `AdoptFromDisk` on the same entity journal in rev order, a lowering panic yields Unknown "internal error" and the Session keeps working, every `validate` problem makes lowering fail for the scopes it touches. Oracle proptest: after random apply/undo sequences, every derived value (projection, CheckKeys, dirty files, dangling references) equals the same function on a fresh Model built from the final files.
- `format`: round trip, golden files per version, a migration test per version bump, a journal truncated at every byte offset recovers a prefix of gestures, and comment round trip: comment, edit, save, the comment is still there.
- Crash test: a child process killed after N gestures, during Save, and while edits land during a Save; restore gives the same model hash and loses nothing newer than the saved snapshot.
- UI: Vitest on the reducer, `sync()` on a gap and the keysFresh rule (apply, hold back `currentKeys`, assert no verdict renders as current) with `mockIPC`, fed with Rust-written JSON fixtures of `Applied`, `Sync`, `EngineEvent` and `VerdictDto` (the IPC contract test); Testing Library by role and label, keyboard-only canvas pass, axe; one WebdriverIO smoke test per slice on Linux.

## 9. Trade-offs
- **Strengths:** one source of truth in Rust, every domain rule once; what is proved is what is saved by construction; wrong-Proved defenses are structural (`net` has no semantics, `recheck` cannot import `verify` or `engine`, the second explorer only ever sees its own composition, the key comes from the explored net, Unknown is never cached, lowering is total or fails); the derive thread makes journal, keys and cancel totally ordered per revision; Save can never overwrite a hand edit; undo and verdict restore fall out of snapshots; slice 0 needs no history, journal or watcher; the CLI and code import get editing for free.
- **What we give up:** every committed gesture is an IPC round trip (a few ms; drag is local); an exhaustive Proved costs about twice the exploration time and is limited by what a plain BFS can explore within half the budget; the session mutex is coarse; a second composition implementation to keep in step with the spec; three new crates and a persistent-map dependency (`imbl`).
- **Slice 0 cut list:** full projection per apply (no patch, no gap refetch beyond `sync()`), the dev mirror comparison as a test rather than a runtime hook, raw `ipc::Response` only on measured need, no stubborn sets; the only certificate is `NoOverflowPlace` (ADR 0017). Re-estimate after E1-E4; the earlier 6-8 weeks for slice 0 is the lower end.
- **Main risks:** E4 must measure end to end (pointerup to painted frame on WebKitGTK at 300 nodes, p95 < 50 ms, including rapid rename-blur and a 300-node MoveElements) and journal fsync on WSL2; `recheck::compose` drifting from `engine::flatten` is caught at every check by the encoding comparison, by the proptest and by the TAPAAL corpus.
- **What would change my mind:** measured end-to-end latency above ~30 ms would justify optimistic local application confirmed by `rev` (not moving the model); recurring ordering bugs outside the derive pipeline would justify the single-thread Session; per-child certificate reuse in stage 3 would justify a memoized lowering layer.

## 10. ADR conflicts
- **ADR 0004 is amended (ADR 0009):** `crates/net`, `crates/recheck` and `crates/interop` are added; `verify` depends only on `net`; `recheck` depends only on `net` and CI forbids `recheck -> verify` and `recheck -> engine`; std adapters live in `engine::adapters`. Everything else in 0004 holds.
- **ADR 0008 is amended (ADR 0010):** the second explorer composes `OpenNets` itself and checks all evidence against that composition; the cross-check covers composition, not Model-to-OpenNets lowering, which golden tests and the slice 2 model-level replay cover; Disproved evidence is per property kind.
- **ADR 0006 is amended (ADR 0012):** supervised threads unwind; the lock holders and the main thread abort.
- **ADR 0005 is amended (ADR 0013):** only Proved and Disproved are cached; the key covers the canonical encoding.
- **ADR 0011 (new)** records the session shape, the projection with revisions and the ordered journal, with the rejected alternatives. **ADR 0014 (new)** records the capacity semantics.
- **2026-11-02 revision (`docs/specs/decisions.md`):** ADR 0002 and 0003 are amended by ADR 0015 (nameable places, state machine ports) and ADR 0016 (binding pairs, sets, children); ADR 0008, 0010 and 0014 by ADR 0017 (overflow readings, certificate, Unknown reasons); ADR 0010 and 0013 by ADR 0018 (final predicate in `DeadlockFree`); ADR 0001 by ADR 0020 (project files); ADR 0012 by ADR 0021 (per-rule scan threads).
