# Panel review of the synthesized design

## software architect: 7/10, approve-with-changes

### Must fix

- §4 Edit + §5 UI store: the split Applied/currentKeys events open a window where an old verdict shows as current. Keys are recomputed off the lock after the reply. Between `Applied{rev: n}` and `currentKeys{rev: n}` the UI still holds the keys of rev n-1. A `verdict` event that arrives in that window (it carries no rev) passes `verdict.key === currentKeys[property]` and is shown as current on an edited model. That breaks the slice 0 criterion 'earlier verdicts are removed' and is the exact failure the design says it prevents. Two concurrent commands (UI apply plus watcher reconcile, or apply plus undo) can also emit currentKeys out of order, so rev 5 keys can overwrite rev 6 keys. Cancel decisions made on stale keys can kill checks whose key is current again. Fix: currentKeys always carries the complete key set (never a partial merge) and its rev. The UI drops currentKeys older than the last one it applied. A verdict renders as current only if `currentKeys.rev === projection.rev` and the keys match; otherwise it renders as 'pending'. Cancel decisions are made under the lock against the latest rev. Add a Session test: apply, then the verdict for the old key arrives before currentKeys, so it must not render as current.
- §4 Edit/Save + §5: the journal can lose or reorder gestures, which means data loss on recovery. (a) §4 appends 'off the lock' after the reply, while §5 says 'before the reply'. The two sections contradict each other. (b) After-images are idempotent but not commutative. If two commands touch the same entity (an apply racing an AdoptFromDisk from the watcher, or an apply racing an undo), an off-lock append can write B's image before A's, and recovery then restores the wrong state. (c) Save calls 'reset the journal to the new base' after SaveDone, off the lock. Gestures applied and journaled between the Save snapshot and the reset are deleted, so a crash afterwards loses them silently. Fix: every JournalRecord carries the rev assigned under the lock. Appends go through one ordered writer (under the lock in slice 1, or a single journal thread that rejects or reorders by rev). Reset becomes a rebase: the new base is the saved file hashes, and records with rev greater than the snapshot rev are kept. Add both cases to the kill-the-process crash test (an edit during Save; concurrent reconcile plus apply).
- §4 Save + File changed (slice 0): Save can overwrite hand-written nets. In slice 0 the user writes Petri nets in TOML in an external editor and uses manual Reload. The flow is: rename element A in the app (A is now dirty, holding the old net), edit A's net in the editor, forget Reload, press Save. `write_atomic` then replaces the hand edit with the stale in-memory net. `last_seen` exists but is used only to drop the watcher's own-write echoes. Fix: from slice 0, Save checks before each write that the on-disk hash still equals `last_seen`. On a mismatch it skips that file and reports a conflict ('changed on disk since load'). Reload's behavior for dirty entities is also unspecified in slice 0 and needs a defined rule (refuse, or the same conflict). Related: re-rendering a changed element file canonically drops the user's TOML comments and formatting inside a hand-written net. Either patch the retained `toml_edit::DocumentMut` per file, or record in ADR 0001/0011 that comments in app-edited files are not preserved.
- §2/§3 `net` crate + ADR 0010: the two explorers' independence is not enforced, and the net semantics are not specified. (a) If `net` contains semantic methods (`Net::fire`, `enabled`, `LinearPredicate::eval`, flatten helpers), a bug in them is shared by verify and recheck. ADR 0008 allows sharing only the net *types*. State it as a rule: `net` holds data plus canonical encoding only. The firing rule, predicate evaluation and fusion/channel interpretation are implemented separately in each explorer. Check this in review or CI (for example, no `impl` blocks outside `net::encode`). (b) Two independent implementations of an ambiguous spec agree on the wrong answer, so `net` needs a normative semantics document with golden examples. It must cover: capacity semantics, unbound ports, per-caller fusion copies (ADR 0002), and final markings. Capacity is concrete: research R1 compiles capacities to complement places, which makes `CapacityNeverExceeded` vacuous by construction. But slice 0 criterion 2 expects Disproved on an async place with capacity 3 and 'no back-pressure'. Decide and record whether capacity blocks firing or is a monitored bound whose overflow is a violation state. The decision changes deadlock verdicts and whether the state space is finite.
- §3 NetVerdict + §4 Check step (3) + §6 slice 4: Disproved evidence assumes every violation has a replayable trace. That is false for `NoDeadTransitions` (the witness is the absence of any enabling, so there is no finite trace) and for `AlwaysReachable` (a trace to a marking, plus a claim that no marking satisfying the predicate is reachable from it, which needs exhaustive sub-exploration). Under step (3), replay fails, giving Unknown 'internal error' every time, or worse, someone weakens replay to accept them. Fix now, while the type is cheap to change: make Disproved evidence per property kind, e.g. `Evidence::Trace(cx)` (replay-confirmed) | `Evidence::TraceThenExhaustive{cx, claim}` | `Evidence::Exhaustive{dead: Vec<TransitionId>}`. The kinds with an exhaustive part go through the same second-explorer agreement as an exhaustive Proved. Also state that `replay(o, cx, p)` must check that the final marking violates `p` (deadlock with no final marking matched, capacity exceeded, predicate true), not only that the steps can fire.

### Should fix

- §1/ADR 0010 overclaim: 'the second explorer on the unflattened OpenNets also cross-checks lowering' holds for flattening (OpenNets to Net) only. Model-to-OpenNets lowering, including port binding and, from slice 2, the state machine compilation, is shared by both explorers, so a lowering bug still produces an agreed wrong Proved. Reword ADR 0010. Add golden lowering tests per ADR 0002 rule. For slice 2, replay each counterexample's event sequence on the state machine's own semantics (a small interpreter in recheck); this cheaply cross-checks the SM-to-net compilation.
- §3 recheck design: running BFS on the fly over `OpenNets` (fusions plus channels) is not 'deliberately simple' (ADR 0008), and it grows with the nesting promised in §6. Simpler and stronger: recheck holds its own small `flatten_simple(OpenNets) -> Net`. It first compares its canonical flat net with engine's `flat` (any difference gives Unknown 'internal disagreement', a cheap check that does not depend on the property). It then runs plain BFS and replay on its own flat net. The explorer stays a 100-line BFS, flattening is still checked independently, and only one composition interpreter has to change when OpenNets grows.
- §4 Check step (2) budget: 'remaining budget' means a check where verify used 95% ends as 'budget exhausted' although the model was fully explored. Reserve the recheck share up front (for example, verify may use at most ~50% of the markings and time). Use distinct typed reasons ('re-check budget exhausted' vs 'budget exhausted'). State that verify's visited set is dropped before recheck starts; otherwise 'sequential' still doubles peak memory. `Budget.deadline: Instant` bypasses the Clock port, which makes budget tests timing-dependent: give the explorers an injectable time source or a step-count limit.
- §3 VerdictDto/Unknown: `Unknown(Reason)` with `reason: string` loses research R3 (reason category, what was tried, bound reached, suggested fix) and lets the UI mislabel reasons. Use a typed enum: BudgetExhausted{phase, markings, elapsed} | Cancelled | InternalError | InternalDisagreement | LoweringError{dangling}. Unknown 'internal error' must stay distinguishable as a bug (ADR 0006).
- §4 Replay + §5 cache: cache the net-level `NetVerdict`/Counterexample, not the `ReplayFrame[]`. Render frames at display time through the *current* OriginMap. A rename keeps the CheckKey but changes labels ('Billing fires take_lock'), and after an undo-restore the frames must use current names. Express Counterexample steps and `Marking`/`finals` by qualified IDs, with fused steps as sets of constituent part transitions. §3 promises 'means the same on either', but a positional `Marking` or a flat fused-transition index does not have that property.
- §4 Edit: build `ViewPatch` by diffing `project(old, view)` against `project(new, view)`, not from EntityChanges. Projections depend on more than the touched entity: cascaded relationship deletes, port handles derived from a behavior model, dangling markers, and from slice 3 implied relationships between children. At 300 elements the diff costs microseconds. The dev-build full comparison then becomes a cheap assertion rather than the only guard.
- §5 Panic hook: aborting on every non-`check-*` thread kills the app (no journal in slice 0) when a scan rule panics. The scan worker (and later the import and proof workers) also owns only an immutable `Arc<Model>`, the property ADR 0006 relies on. Allowlist `check-*`, `scan-*`, `import-*`, `proof-*`: a panic there gives Unknown 'internal error' or a failed scan, not an abort.
- §5 Tauri threading: in Tauri 2, non-async commands run on the main thread, so Save rendering, fsync and the std Mutex would freeze the window. Declare the commands `async` (or `#[tauri::command(async)]`) and move Save and journal IO to `spawn_blocking`. Save goes through the single promise queue, so a slow WSL2 fsync also blocks every gesture behind it: let `save` return after taking the snapshot and report completion through an event.
- §4 Save: record the expected file hashes (from SaveBegin) under the lock *before* writing. Otherwise the watcher can see our own write before `last_seen` is updated and raise a spurious conflict on an entity edited during the Save. `FileWrite` must also cover deletions (deleted elements) so that torn-Save recovery converges.
- §2 adapters: `StdDisk`, `FileJournal` and the notify adapter live in src-tauri, but the CLI (§6) needs the same std implementations. Put them in `engine::adapters` (std only, no tokio or Tauri) so the CLI and Tauri share them. ADR 0004 and stack.md 7.1 already put watching in engine. Only `TauriSink` and the command layer belong in src-tauri.
- §3 Session: it holds the document state (current/saved/undo/redo/rev), the journal, the verification state (keys/cache/registry) and disk sync (last_seen/reconcile), and §6 adds scan, import and proofs. It will become a god object. Keep the Session facade, but split it internally into `Document`, `Verification` and `DiskSync` modules with narrow interfaces, so each can be tested alone and the 'single thread actor' door stays cheap.
- §7 CheckKey fitness: add the converse invariance tests. Building the same model in a different insertion order, rebuilding it from files, or performing an undo-redo cycle must give the same key. Require canonical ordering inside `lower`/flatten (OrdMap helps, but generated fusion and channel IDs must be deterministic too). Otherwise you get spurious staleness and cache misses.
- ADR hygiene: ADR 0011 bundles three decisions (the session snapshot model, the projection UI, the journal format). Split the journal format into its own ADR: it is persisted data with a migration duty under ADR 0001, unlike the session shape. Consider whether 0012 and 0013 should be 'Supersedes' rather than 'amends' so each accepted ADR stays unedited.
- §8 effort: 6-8 weeks for slice 0 is optimistic. It includes the canvas, the TOML format, two explorers, OpenNets composition, replay UI, the panic hook, rev/gap refetch, the dev mirror check, JSON fixtures, proptests and a TAPAAL corpus. Publish an explicit slice 0 cut list: the `recheck` simplification above; the raw `ipc::Response` only when E4 measures a need; the dev mirror comparison as a test rather than a runtime hook. Re-estimate after E1-E4.
- Slice 0 acceptance criterion vs ADR 0005: the criterion says 'any edit removes earlier verdicts', but key semantics keep verdicts across renames and layout moves. Route this to the product-manager: either reword the criterion to 'any edit that changes the checked net', or accept the stricter UI behavior in slice 0.
- §6 slice 3: slice 3 explicitly excludes composition across levels, so do not add `OpenNets` nesting there. Keep recheck flat until cross-level composition is actually scheduled.
- §2 placement: the TAPAAL differential corpus (slice 0, CI) needs a PNML writer for `net::Net`, but no crate owns it. Add it as a dev-only module in `net` tests or as an `interop` crate (stack.md 7.1).
- Glossary discipline: `net::Channel` collides with Tauri's `Channel<EngineEvent>`; rename it (for example `AsyncLink`/`BufferPlace`). `CheckJob` uses 'job', which GLOSSARY lists under Avoid for Check; use `CheckRequest`. Add Entity/EntityKey to the glossary updates, or keep them internal.
- Optional: consider moving `lower` (Model to OpenNets/Net plus OriginMap) out of engine into `crates/lower` (deps: model, net). It is the largest trust-relevant code shared by both explorers. A crate of its own gives it golden tests and a clear owner, and keeps engine an orchestration shell. This would be a further ADR 0004 amendment.
- P3: bound the verdict cache (LRU by count or bytes); long Disproved counterexamples accumulate over a session. Re-submit a check automatically when undo restores a key whose check was cancelled and never cached.

### Lost ideas

- Progress throttled to 4/s (B2/A2, listed in the rationale) is missing from the design text. `checkProgress` shares the single Channel with `verdict`/`currentKeys`, so an unthrottled explorer can delay the events that decide what counts as current.
- Research R3 / verification §6 idea 4: explain the violation at the final state (deadlock: which transitions lack which token, held by which element; overflow: which place and its capacity). Slice 0 acceptance criterion 2 ('the last step names the generated place and its capacity') needs a `violation` field in the Disproved DTO, and the design has none.
- Research R3: a structured Unknown with category, what was tried, bound reached and suggested fix (add a capacity, split the model) has been reduced to a string reason.
- Verification §6 idea 6: shortest counterexample first. Once verify gains stubborn sets its traces are no longer shortest. recheck's plain BFS could supply the minimal trace for display.
- stack.md 7.1: an `interop` crate (PNML, later Structurizr/LikeC4/ITF trace export) as the home for PNML. The TAPAAL corpus in slice 0 already needs it.
- stack.md 1.5 / ADR 0004: notify-based watching in the Rust engine, not in the Tauri adapter, so a CLI `watch` mode and the Session tests can share it.
- Rationale lists the Clock port as taken from A1, but `Budget.deadline: Instant` bypasses it inside the explorers. That loses the 'no sleeps, deterministic' property of the Given/When/Then tests for budget exhaustion.

## senior backend developer: 7/10, approve-with-changes

### Must fix

- Section 3 (`net` crate) and ADR 0009 can share a bug between the two explorers. `net` is listed as holding `Marking`, `NetProperty(LinearPredicate)`, `Budget`, and probably `flatten` too, since the proptest in section 7 calls `flatten(o)` from net, verify and recheck tests. If `net` contains the firing rule (`enabled`/`fire`), capacity handling, predicate evaluation or `flatten`, then `verify` and `recheck` share that code. A bug there gives both explorers the same wrong answer, and the result is a wrong Proved. That breaks ADR 0008 ('no shared code beyond the net types'). Fix: write in ADR 0009 that `net` holds only data, constructors and structural validation, with no semantics. Each explorer implements its own firing rule, capacity check and predicate evaluation. `flatten` lives in `engine` or in its own crate that `recheck` cannot depend on, and CI checks that edge.
- Sections 3 and 4 never say what Capacity means in the checker. There are two incompatible options. In the first, capacity blocks the transition (complement places, as in verification.md R1). Then CapacityNeverExceeded is always Proved, and the slice 0 criterion 'producer/consumer with capacity 3 and no back-pressure -> Disproved, last step names the generated place' cannot pass. In the second, a firing that goes over capacity is enabled and leads to an error marking. That interacts with DeadlockFree (does overflow count as a deadlock, and is it expanded?). If verify and recheck pick different options, every such check ends Unknown 'internal disagreement'. If both pick the wrong one, users get wrong verdicts. Fix: write the semantics of `Net` and `OpenNets` in ADR 0010 before any code. That means capacity, sync fusion with one fused copy per caller (ADR 0002), async channel places with capacity, and final markings composed across parts. Add a golden E1 test for each rule.
- Section 4 (Edit): the work done after the lock is released is not ordered. After `unlock, reply`, the journal append, the CheckKey recompute, the cancel decisions and `currentKeys` all run on whichever command thread handled the apply. Two applies (UI, `AdoptFromDisk` from the watcher, or the CLI or import) can finish in reverse order. After-images are idempotent but not commutative. A journal containing [B(rev 6), A(rev 5)] for the same entity restores A's state, so a crash loses an edit with no sign. A key recompute from an older revision that finishes last cancels the check for the newest key and emits old `currentKeys`. Section 5 also contradicts section 4: it says the append happens before the reply. Fix: put `rev` in every journal record and in every key-recompute result. Write to the journal under the lock or through one writer that takes records in rev order. Ignore any key or cancel result whose rev is lower than the last one applied. The UI drops `currentKeys` events whose rev is older.
- Section 4 (Save) can lose edits made during a Save. Save takes a snapshot, releases the lock, writes, and then calls `Journal::reset(base)` with the new base. Edits applied while the write is running were appended to the journal, and the reset deletes them. If the app crashes after that, those edits are gone. Two Saves running at once, for example Ctrl+S together with save-on-quit or a CLI save, can write the same files over each other and set `saved` back to an older snapshot, which makes the dirty marker wrong. Fix: `reset(base, keep_after_rev = snapshot.rev)` keeps the records after the snapshot. Run Save single-flight with a save guard in Session. Also spell out recovery after a torn Save: each file's hash must match either the base hash or the new hash recorded in SaveBegin, and only then are the after-images replayed.
- Sections 4 and 5 (panic hook plus lowering on the command thread) can put the app in a crash loop. `lower` and `check_key` run on the command thread, both for `run_checks` and for the key recompute after every edit. Assertions stay on in release (ADR 0006), and every thread except `check-*` aborts on panic. One model that trips an assertion in `lower` therefore ends the app on every edit. It also ends the app on every Open, because Open queues all properties. With the journal (slice 1), restore re-applies the gesture that triggers it, so the project can never be opened again. Fix: run lowering and key computation inside an unwinding worker such as `lower-*` (or inside the check worker). A panic there becomes a key of 'internal error' or an Unknown, not an abort. The restore offer must have 'open without restoring' and must keep the journal aside. Name the scan worker so that it also unwinds into an 'internal error' for findings.
- Sections 3 and 4: `lower` has no rule for incomplete input, and that can produce a wrong Proved. The design says `lower` 'validates its input as untrusted' and returns `LowerError`, but never says what the user sees or what happens to: a dangling port reference, a relationship without a binding, or a child element in the scope that has no behavior model. If lowering silently leaves out a part or a binding, the explored net is smaller than the real system and deadlock-free can come out Proved. Fix: lowering either covers everything or fails. A `LowerError` becomes Unknown with a specific reason, such as 'model incomplete: Billing/take_lock not found'. Elements without behavior models are listed in the verdict as assumptions. Add a test that every `dangling_references` item makes lowering fail for the scopes it touches.
- Section 4 (Save) and format.md 4.4 lose content the user wrote. In slice 0 the user writes Petri nets by hand in the element's TOML, so comments are likely. Save 'renders the changed files canonically' from the Model, and the Model does not keep the `toml_edit` documents. The first rename or inspector edit of that element then deletes every comment in its `[behavior]` table. Fix: `format` keeps the parsed `toml_edit::DocumentMut` for each file, keyed by file hash, in the Session next to `saved`. Save edits those documents in place and renders canonically only for new files. Add a round-trip test: comment, edit, save, and the comment is still there. Related: in slice 0, a manual Reload with unsaved edits to the same element must ask the user or refuse. It must not silently overwrite in either direction, because conflict handling only arrives in slice 1.

### Should fix

- ADR 0010 claims too much. Exploring `OpenNets` cross-checks flattening only. The step from Model to `OpenNets` (port binding becomes fusion or channel, state machines are compiled) is shared by both explorers and is not checked. Say this plainly in the ADR so nobody relies on a guarantee that does not exist. Cover that step with golden tests for each binding kind. For state machines (slice 2), add a replay of the counterexample as a sequence of events on the state machine itself, inside `recheck`.
- Sections 3 and 4: the `Counterexample` must be stated in `OpenNets` terms. A fused transition does not exist as a single ID in the unflattened nets ('each caller gets its own fused transition'). Each step should therefore be a set of (part, transition) pairs plus channel effects. The mapping from flat steps to open steps comes from flatten, which is shared code. That is still sound, because replay checks firability on `OpenNets`, but it must be designed now and not discovered in week 5.
- Section 4 (Check): 'second explorer on the remaining budget' turns feasible proofs into Unknown. If verify uses 90 % of the budget, recheck almost always runs out. Once stubborn sets arrive (stage 2), recheck's plain BFS explores the full state space while verify does not. Fix: cap verify at about 50 % of the budget. Give the Unknown a distinct reason, 'budget exhausted while re-checking evidence'. Accept and document that a Proved by exhaustion is limited by the size of a plain BFS.
- Section 4 (Check) explores the same state space up to 4 times. Each property on a scope is a separate check, so deadlock-free and capacity-never-exceeded on one scope each run verify and then recheck on the same reachability graph. Group the properties by flat net and explore once while evaluating every safety predicate. Keep one verdict and one CheckKey per property. This also makes cancellation simpler.
- Section 4: CheckRegistry must deduplicate by CheckKey. Pressing Check twice, or undo/redo while a check runs, submits the same key again and starts a second identical worker. Attach the new request to the running check instead.
- Section 5: Tauri 2 runs non-async commands on the main thread (stack.md 1.2). All engine commands must be `async` or `#[tauri::command(async)]`. Lowering and the journal fsync should run through `spawn_blocking` so they do not block the tokio workers that Channels depend on.
- Sections 3 and 5 for slice 0: drop `ViewPatch`, the rev gap refetch and the dev-build mirror comparison. At 300 elements, return the full view projection from every apply (well under a millisecond to serialize). The reducer keeps object identity by comparing each node structurally. Bring in patches only if E4 measures a need. This removes the most fragile UI machinery from the 6-8 week slice.
- Section 5 (rev rules): 'every EngineEvent carries rev' does not match the TS types (`verdict`, `checkQueued` and `checkProgress` have no rev). Using `rev != local+1` on events delivered over the Channel conflicts with the `Applied` reply that comes through invoke, because the two paths have no ordering between them. Make the projection rev on `Applied`/`diskChanged` the only sequence used to detect gaps. `currentKeys` uses latest-wins by rev. Verdicts are matched by key only.
- Section 4 (disk changes): `AdoptFromDisk` must also update `saved` for the adopted entity. Otherwise the adopted entity shows as dirty and Save writes it back. Undoing an adoption must not restore `saved`.
- Section 5 (Memory): counting markings is a poor stand-in for bytes, because marking size grows with the number of places. A small global allocator that counts bytes per thread in a thread-local, read by `Budget`, gives an exact memory budget at little cost. If not, count bytes as markings x places x cell size.
- Section 3: `Budget.deadline: Instant` bypasses the `Clock` port. Use a deadline taken from `Clock`, or a ticks-based budget, so that tests for budget exhaustion are deterministic without sleeps.
- Section 6, code proofs: also state where `code_facts` and Kani/Verus outcomes live (memory only, keyed by hash, like verdicts per ADR 0005) and how they show up as stale. Otherwise code import will add a second store that bypasses persistence.
- Section 4: VerdictCache and the undo stack have no bound. Add an LRU cap on cached Disproved entries (each holds replay frames) and a configurable undo depth.

### Lost ideas

- The rationale adopts 'progress throttled to 4/s' from B2/A2, but the design text never mentions it. Section 4 has no throttle on `checkProgress`. Put it back in the worker or monitor.
- The B2/A2 actor was rejected as the backbone, but its single-writer ordering guarantee was lost along with it. That guarantee is exactly what the unordered post-apply journal append and key recompute in section 4 now break. Keep the guarantee without the actor: a rev-ordered journal writer and a latest-rev-wins rule for keys.
- A1's Composite gave a reason to put flatten out of recheck's reach. The synthesis keeps 'explore unflattened OpenNets' but never says where `flatten` lives or that recheck must not call it. A1's separation (flatten in the lowering layer, recheck interpreting composition natively) should be written into ADR 0009.

## senior frontend developer: 7/10, approve-with-changes

### Must fix

- §4 Edit + §5 Ordering: post-apply work runs after the lock is released and in no fixed order, so it can wrongly show a verdict as current and can corrupt recovery. The UI's promise queue releases the next `apply` as soon as `Applied` resolves, while the previous gesture's key recompute and journal append (§4 says after unlock, §5 says before the reply; the two contradict) may still be running on another tokio thread. Two failures follow. (a) `currentKeys(rev 5)` can arrive after `currentKeys(rev 6)`. If the UI keeps the last one it received, a verdict whose key matches the rev-5 net is rendered as current for the rev-6 model: a wrong current verdict. (b) Journal after-images from gesture 6 can be appended before those of gesture 5. Recovery then replays state-based images in file order, and entity X ends at its gesture-5 state, so the restore loses data. Fix: send all post-apply work (journal append, lower, check_key, cancel, emit) to ONE ordered derive thread in `rev` order, fed by a channel under the lock. This is B2's actor, applied only to the derived pipeline, and the Session API does not change. Stamp `rev` on every journal record and on `currentKeys`. The UI drops any `currentKeys` whose rev is lower than the highest it has seen.
- §3 TS types + §5 UI store: between `Applied(rev N)` and `currentKeys(rev N)`, the UI still holds rev N-1 keys while the canvas already shows rev N. In that window `verdict.key === currentKeys[p]` is true for a verdict about the previous model, which breaks the design's own rule 'never render a verdict as current unless its key equals the current key'. The window lasts as long as one lowering of the scope, which is not negligible at 300 elements. Fix: store `currentKeys.rev` and derive `keysFresh = currentKeys.rev === projection.rev`. While keys are not fresh, render every verdict as 'pending re-evaluation': not current and not success. Add a Vitest case that applies, holds back `currentKeys` and asserts that no verdict renders as current.
- §4 Save (slice 0): Save overwrites files the user changed outside the app. The primary slice-0 workflow is authoring nets in TOML in an external editor and pressing Reload (v1-slices). If the user edits `billing.toml` in their editor, forgets Reload, renames Billing on the canvas and saves, the app writes the stale in-memory behavior model over the hand-edited file. The ptr_eq diff against `saved` cannot see the disk change, and `last_seen` is only used for echo detection after the slice-1 watcher arrives. Fix (cheap, slice 0): record the file hashes at load and at every Save. Before `write_atomic`, re-hash each target file. On a mismatch, skip that file and report 'changed on disk; Reload first', the same as a partial failure. A slice-0 Reload while the model is dirty must also refuse or confirm, so it does not silently discard canvas edits.
- §4 Open/Check + §5 Panic hook: `lower` and `check_key` run on command threads, and the hook aborts on every non-`check-*` thread. Open queues every property, so a lowering panic (a bug triggered by one element's net) aborts the app at every open. After a crash, journal restore replays the same gestures, so the next open crashes again. The user is locked out of the project, and ADR 0006 explicitly wants a panicking computation to become Unknown 'internal error', not a dead app. Fix: run lowering and key computation on the derive thread from the first must-fix (named `derive-*`), let it unwind and join like `check-*`, and map a panic there to a per-property 'internal error' entry. Abort only on panics in `apply` or projection under the lock, where state could be half-applied.
- §4 Check step (2) + §6 Drill-down: a structural Proved 'has its certificate verified by recheck', but the certificate is about the flat net that `lower` produced. Once P-invariant or ILP certificates land (possibly before slice 3, per v1-slices 'Later'), a flattening bug plus a valid invariant of the wrong net gives a wrong Proved. That reopens exactly the route ADR 0010 closes for exhaustive proofs. Fix it in ADR 0010 now: `recheck` owns its own composition of `OpenNets` (`recheck::compose`, independent of engine's flatten) and checks certificates against that net, or certificates are stated over `OpenNets` and checked there. Otherwise the stage-2 techniques silently bypass the cross-check.

### Should fix

- §3/§5 IPC: add a `sync()` (or make `subscribe` return one) that registers the Channel and returns `{rev, view, currentKeys, verdicts, runningChecks, findings, dirty, canUndo}` atomically under the lock. Two reasons. (1) Events emitted before the subscription (the checks queued at open) and events lost on a webview reload or Vite HMR are otherwise never recovered, because `verdict` and `checkProgress` carry no rev, so a gap refetch through `view(id)` does not bring them back and the panel shows 'queued' forever. (2) `TauriSink` must replace the Channel rather than add another, or every event after an HMR reload is emitted to a dead channel. The gap rule `rev != local+1` should then call `sync()`, not only `view(id)`.
- §4 Edit/Undo ('a verdict cached under the restored key is current again with no extra code'): this is not true for the UI. The UI keeps one `{key, verdict}` per property. Sequence: Proved@K1, edit, check, Disproved@K2 (or Unknown 'cancelled'@K2), undo. The UI now holds Disproved@K2 rendered stale, while the engine cache has Proved@K1. That fails the slice-1 acceptance criterion. Fix: `currentKeys` carries `{key, cached?: VerdictDto}` per property, filled from `VerdictCache` during the key recompute.
- §3 `currentKeys`: give each property `{key} | {lowerError: LowerErrorDto}`. In slice 0, nets are hand-written TOML, so unbound ports and dangling `element/port` references will be common. Without this, the panel shows nothing, or an old verdict stays stale forever, and the user never learns why. This state is not a Verdict, so add a glossary term for it (do not reuse 'Not checkable', which the glossary reserves for rules).
- §4 Edit ('build the ViewPatch from the EntityChanges, not from a view diff'): reverse this. The projection is a pure function, so `diff(project(old, view), project(new, view))` with `Arc::ptr_eq` short-circuits is correct by construction and costs well under 1 ms at 300 elements. Mapping EntityChanges to projection items by hand is the drift source the dev-build comparison exists to catch. Cases it gets wrong: cascaded relationship deletes on DeleteElements; a MoveElements that changes the Layout entity and must upsert N nodes; port changes on element A that alter how relationship R into A renders; and in slice 3, child counts and badges in parent views.
- §4 Edit (drag, rename): define the ephemeral overlay lifecycle. Clear a drag or rename overlay when an `Applied` with rev >= the request's rev arrives, not on pointerup or Enter. Otherwise the node snaps back for one frame on every drop. On `Rejected`, clear the overlay and announce the reason in the polite live region.
- §2/§6 Slice 1 net editor and slice 2 state-machine editor: the design defines only C4 `ViewPatch` (CanvasElement/Relationship) and `Layout` per `ViewId`. It is silent on a behavior-editor projection (places, transitions, arcs, states, events), on where net-internal layout is stored (ADR 0001 requires a separate layout file, not the element TOML), and on how replay highlights inside the editor. Specify a `BehaviorView` projection and a `BehaviorLayout` entity now. `SetBehavior` with the whole model per gesture is fine for undo and journal, but the editor needs its own patch type.
- §4 Replay + §3 `ReplayFrame`: frames should carry IDs only (`transition: TransitionId`, not text). Display names and the aria-live sentence should be resolved from the current projection at render time. CheckKey ignores names, so a cached Disproved shown after a rename would otherwise show the old names. Also add a mapping from generated asynchronous places to their RelationshipId (`Origin::Channel(rel)`, with `edgeTokens: Record<RelationshipId,{count,capacity}>`). The slice-0 acceptance criterion requires the last step to name the generated place and its capacity on the relationship.
- §4 Replay, state machines (slice 2): `recheck` replays the compiled net, so a bug in compiling a state machine to a net agrees with itself in both explorers and in replay. Add a cheap model-level check in `engine` before frames reach the UI: every fired state-machine transition exists from `activeState` with that event. A failure becomes Unknown 'internal error'. This is closer to ADR 0008's 'replay on the original, unflattened model' than replay on OpenNets alone.
- §4 File changed on disk: filter echoes of the app's own writes with the hashes already written in `SaveBegin{files, hashes}`, registered before `write_atomic`, not with `last_seen` set after Save. On WSL2 /mnt with PollWatcher, a Save can take longer than the 500 ms debounce, so the app's own writes come back as external changes and produce spurious conflict dialogs. Reconcile should also treat 'disk equals render(current)' as a no-op.
- §3 projection: dangling references must be explicit in `ViewPatch` (for example `CanvasRelationship.danglingEnd`) and listed in a problems panel. React Flow drops edges whose source or target node is missing and logs an error. When the ports of a node change through a patch or Reload, call `useUpdateNodeInternals(id)`, or the edges attach to stale handle positions.
- §6 Code import + §1 'Batch for layout': elkjs lives in the UI, so neither the engine nor the CLI can lay out imported elements. Define `position: Option` in the projection, with an 'unplaced' rendering. In the app, the import flow returns the proposed Batch, the UI previews the diff, runs ELK on the preview view in `layout.worker.ts`, and applies `Batch(import ++ MoveElements)` as one gesture, so import plus layout is one undo step and one journal entry. In the CLI, imports stay unplaced until the app opens them.
- §8 Risks / E4: measure end to end, not only 'apply + patch < 10 ms in Rust'. Measure from pointerup to the frame painted on WebKitGTK: JSON parse, reducer, React Flow reconcile and paint at 300 nodes. Set a p95 target (for example < 50 ms commit-to-paint), and test both rapid rename-blur sequences and a 300-node MoveElements from ELK. The §8 'what would change my mind' threshold of about 30 ms should apply to this end-to-end number.
- §5 Ordering: only model-mutating commands (apply/undo/redo/reload/resolve_conflict) need the ordered queue. Put `save`, `run_checks`, `cancel_check` and `run_scan` on it too, and a slow Save on /mnt blocks every edit, while `cancel_check` can miss the 1 s acceptance criterion behind a queued apply. Have Save return `savedRev` and derive `dirty = savedRev !== rev` in the UI, so edits made during a Save stay dirty.
- §5 Scan: `scan-*` threads should unwind to join like `check-*` and report 'internal error'. With the current hook, a bug in one rule aborts the app on every scan. Also add the structural model hash to `currentKeys` (or `Applied`) so the UI can derive stale findings without a second protocol.
- Minor items: §4 Save should render through the last-read `toml_edit` Document so comments in hand-authored nets survive (research §4.4). Cap the undo stack. Global Ctrl+Z must not fire while focus is in a text input. CI should fail when the ts-rs bindings or Rust-written fixtures are out of date (`git diff --exit-code` after `cargo test`). §4 and §5 contradict each other on whether the journal append happens before or after the reply; resolve this in ADR 0011.

### Lost ideas

- C3's subscription protocol (inferred from the rationale; I did not see the candidates' texts): it was rejected together with the memo layer, but its useful core, a subscribe call that returns a consistent snapshot of derived state, is what the UI needs for HMR and webview reloads and for events missed before subscription. Keep the snapshot and drop the memo.
- B2/A2's single ordered actor, used only for the derived pipeline after apply (journal, lowering, keys, emit), not for the whole Session. It removes the out-of-order races in the first must-fix today, instead of waiting for 'recurring ordering bugs in slice 1', and it is the natural home for a `derive-*` thread that can unwind.
- B2/C2-style per-key memory in the UI (inferred): the engine's cache restores verdicts on undo, but the UI's one-verdict-per-property map does not. Sending the cached verdict with each current key keeps that idea without moving the model into the UI.
- Optimistic local application confirmed by `rev` (B3/C2): the design keeps this only as a 'change my mind' item. Rename and inspector edits (not only drag) should already use an overlay that the matching `Applied` revision clears, which is a cheap subset of this idea with no second domain model.
- ADR 0001's journal and loader assumptions applied to slice 0: B2/A2's base file hashes are kept for the journal but not reused as a compare-before-write guard on Save, which is the cheap protection against overwriting external TOML edits in slice 0.
