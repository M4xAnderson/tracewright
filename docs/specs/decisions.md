ADR 0017. ## B. Resolved contradictions and term alignments

- **D-22 `CapacityExceededFirst` payload.** NS §10.2 wins: the smallest-ID exceeded place of the first overflow marking in discovery order plus the run to it, replayed by recheck. PT §12.2(d) ("every overflow place, sorted") is withdrawn. ADR 0017. Owners: PT; PL §6 already follows NS.
- **D-23 V-DIS-NOFINAL copy.** The normative fact is NS §9.6: "no transition is enabled and no final predicate is defined". The panel never advises a loop back to the initial marking (PT T1: a reset transition hides real deadlocks); its next step is "Define done when" from slice 1 and, in slice 0, "done when comes with slice 1". ADR 0018. Owners: UX flows §5/§4.13 copy, PT T1, NS (done).
- **D-24 Failed counterexample replay is Unknown `InternalError`.** `recheck::replay` runs on recheck's own composition (ADR 0010); `engine::sm_replay` is the model-level check for state machines (SM §7.4, slice 2) and also runs on `CapacityExceededFirst.steps`. "Internal disagreement" is reserved for the two explorers, the two compositions and a rejected certificate. ADR 0017. Owners: GSS VER-2 (SM A6); NS §9.2/design §4 (done).
- **D-25 Predicate parser slice.** Slice 0 keeps every predicate and `[final]` string opaque: stored and written back verbatim, never parsed; a `[final]` table present in slice 0 is the warning `finalNotChecked` and lowers as `final none`; a `[[property]]` of kind `never`, `always_reachable` or `no_dead_transitions`, or with `template`, is Unknown `PropertyNotCheckable` ["user properties are checked from slice 4"] (list completed by D-54). Slice 1 ships `model::property` (NS §5.3 lexer, parser, normalization, resolution; E1xx/E2xx) and `Pred` evaluation in both explorers, used only by the final predicate; the slice 1 editor offers the minimal form of D-05, hand-written `[final]` text may be any §5.3 predicate (one grammar, no second parser). User properties and templates lower from slice 4. ADR 0018. Owners: FF §0, §3.3, §6.8 (E1xx from slice 1; add `finalNotChecked`); PL §5 step 1 and §12 slice tags; NS §5, §15, V57 (done).
- **D-26 Name clashes are model problems, never load failures.** A place and a transition of one element with the same name is `nameClash` (FF §6.4): the file loads, the editor rejects the gesture, every scope containing the element fails L10. A state/event clash is SM-E04 (L14), likewise. PL §4.1's "load error" becomes "model problem". ADR 0020. Owners: NS §2.2 (done); PL §4.1; FF unchanged.
- **D-27 Scan runs one supervised thread per rule** (`scan-<n>-<rule-id>`, within ADR 0012's `scan-*` prefix); `cancel_scan` is a command; findings carry the scan input hash of SR §3.9 (`scanHash`), not the model hash. ADR 0021. Owners: design §3/§4/§5 (done); SR unchanged.
- **D-28 Final predicate naming.** One concept, one name: **final predicate** (UI label "done when"; TOML `[final] own | combined`; one per behavior of a scope element, so two per element, not "one per scope"). "Final markings" as a list, "final condition", design `Net.finals` and NS `OpenNets.final` are withdrawn; a state machine's **final states** contribute to it. Owners: GSS GLOSSARY (Marking entry, new Final predicate entry), PT "Done when" entry, UX flows §4.13 copy ("Define done when"); NS/design (done).
- **D-29 Binding vocabulary.** Glossary term **Binding** (synchronous or asynchronous, with its own direction); `Fusion` and `AsyncLink` are the code names of a synchronous and an asynchronous binding and `OpenNets.links` keeps its field name; prose never says "link". Binding **mode** `sync | async` (file key) and relationship **interaction** `synchronous | asynchronous` (scan attribute) are different data; the glossary entries for Binding and Interaction each name the other. Owners: GSS GLOSSARY; NS §6.1/design (done).
- **D-30 "Assumption" has one meaning: a relationship of a scope that takes no part in a check.** The own-scope line "every port of `<element>` can fire at any time" is the **closed-port note**; a template's precondition is a **precondition**; the `[assumption]` document tag is unchanged. Owners: NS §6.2/§9.6 (done); PT T3 wording; SM §3.2 line name; GSS GLOSSARY Assumption.
- **D-31 Fused transition ID uses bare names** (`relationship/caller+callee`); ADR 0010's qualified form is amended by ADR 0016. Owners: ARCH (done); design §6 (done).
- **D-32 Scope is `Scope { element, behavior: Own | Combined }`** (PL A7); `lower(m, scope: Scope)`; the file key is `behavior = "own" | "combined"`; prose says own scope / combined scope. Owners: design §3 (done); NS §6.6 (done); PL unchanged.
- **D-33 Term alignments for GSS, PT and UX.** Step: drop "Firing" from the avoid list (firing is the formal act, Run depends on it). Replay: the glossary word is the canvas act; `recheck::replay` and `engine::sm_replay` are evidence checks and keep their names. Property kinds keep one spelling per layer (prose "no capacity exceeded", TOML `no_capacity_exceeded`, canonical `capacity-never-exceeded`, Rust `CapacityNeverExceeded`); PL §2 carries the mapping table. "Markings", never "states", in PL §1; E5 artifacts stay as they are. Preset = one fixed choice inside a template (sub-term of Property template). Timeout: relationship attribute; not the Budget; not the state machine's internal event. Disproved glossary entry and UX_STANDARDS VRD-2 gain the no-dead-transitions exception (PL A9). The merged glossary block of `consistency-review.md` is applied with these resolutions and with D-28 to D-32.

## E. Calls made after the integration check (2026-11-02, software architect)

The independent check after the integration pass found the items below. Each is decided here under the same rule as section D (the accepted recommendations first; otherwise the most conservative option that never risks a wrong Proved). PL revision 3 and the revised catalog are now in the repo (`docs/specs/property-language.md`, `docs/product/property-templates.md`); the cross-references of the other specs point at them.

- **D-47 A property or final-predicate error is Unknown `PropertyNotCheckable`; `ModelIncomplete` is reserved for the net.** ADR 0017 wins ("property cannot be checked (a property error …)"). NS L3 no longer lists property place references; NS L9 is a property-level rule whose failure ends only the property that names the place, or, for the final predicate, the deadlock-free and T7 "done" properties of that behavior, as `PropertyNotCheckable` with the E2xx line; it never fails the lowering of the scope's net. "`ModelIncomplete` first when both apply" (NS §10.2) means: when the net cannot be lowered, every property of the scope is `ModelIncomplete`, whatever its own errors. A final predicate with an error is never lowered as `final none` (PL §17 C3). The seven-reason list is unchanged. Owners: NS §6.6 L3/L9 (done); design §6 (done); FF §6.8, §10.3 `property` row, §16, §17.1 D-04 row (done). Affects slice 1 (`[final]`) and slice 4.
- **D-48 Editing done when stales deadlock-free and every T7 "done" property of that behavior, and nothing else.** ADR 0022 amends ADR 0018's "never stales … a user property": a T7 "done" property expands to `always reachable F`, so its key covers F and its staleness is not spurious. Owners: GLOSSARY Stale, CODING_STANDARDS VER-4, NS §2.1 note, §11, §14.4 (g), design §6, v1-slices slice 1 criterion (done); PL §7 and PT T1/T7 already say it. Slice 4 only; slice 1 behaves as ADR 0018 states.
- **D-49 Which slice parses which predicate string.** D-25 and the file format stand: slice 1 parses and resolves `[final]` only; `predicate` strings and template parameters are stored verbatim and parsed from slice 4, when they are first checked (one parser, used by the final predicate until slice 4; VER-5). E114 (a string over 4,096 bytes) is a length check that needs no parser and is reported in every slice, including slice 0, as FF §10.3 says; no other E1xx or E2xx is reported for a string that the slice does not parse. PL §10.1, §14.2 header, S-01 and the slice vectors are corrected to this. Owners: PL (done); FF unchanged.
- **D-50 L12 is checked on fused IDs.** "(caller name, callee name)" in ADR 0016 means the bare names in the fused ID `relationship/caller+callee`. For a Petri net port they are the port's transition name; for a state machine event they are the names of the state machine transitions of the cross product (SM §2.2, SM V-25).
