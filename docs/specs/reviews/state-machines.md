Author: senior backend developer. Final document: `docs/specs/state-machines.md`.

## software architect: approve-with-changes

### Must fix
- Draft header 'Dependency on the net semantics', §6.1, §6.4, §13 Q1: the draft was written without the final net-semantics spec, so it has to be reconciled with it before it can be accepted. Q1 no longer applies. The concrete conflicts: (a) Step.fired. Net-semantics §9.1 and its §16 item 5 make `Step.fired` one QualifiedId of the flattened net, with constituents taken from the origin map. The draft's §6.1 ('a fused step lists each constituent'), its §6.4 constituent sets `F_k` / `F_k = {E/τ, π}`, and replay vector R-01 ('wrong partner set') all assume the old BTreeSet form. Rewrite sm_replay to parse one fused ID `r/α+β` (bare names; the relationship gives source and target, per L11) or one own ID `E/τ`. (b) sm_replay input. The draft lists an 'initial marking M_0' as input, but the net-semantics Counterexample has no M_0 field, so M_0 must be derived from the model snapshot. (c) Port mapping. State that every net transition `E/τ` of an input or output event counts as a transition port for L4, L5, L7 and L11. (d) Slugs. SM-E05 must use the net-semantics §2.2 slug rule: `[A-Za-z_][A-Za-z0-9_-]*`, never `and`, `or`, `not`. The current message ('lowercase letters, digits, - and _') allows a state ID `2fa` or `not`. Such an ID makes the net fail §2.3, and the predicate lexer of §5.3 cannot name it.
- §4.1 and §12 P1 (set-valued `AsyncLink.from/to`) contradict the final net-semantics spec as it stands. That spec defines `AsyncLink { from: QualifiedId, to: QualifiedId }`, rule L8 allows one AsyncLink per relationship, and §15 says 'State machines (S2) lower to 1-safe parts of OpenNets ... nothing in this spec changes for them'. P1 is the right fix: restricting async-bound events to a single transition would make async state machines nearly useless. It must be written as a proposed amendment of net-semantics (revision 3), with replacement text for §6.1 AsyncLink, §6.4 (arcs per set member), §6.5 steps 1 and 3, L7, L8, L11 (every member belongs to the source or target), and the generated-ID uniqueness argument in §2.2. It also needs new composition vectors in §14.3: an SM async input event with 2 transitions, and an SM-to-SM async binding with sets on both ends, each with its exact canonical encoding. Add replacement sentences for ADR 0010 §Semantics ('a generated place between the two port transitions') and design §3 `AsyncLink`. It must land before slice 0 code, as the draft already says.
- §3.6, §12 P3 and vectors V-06 and V-07 [S4] conflict with net-semantics L9. P3 says a state machine offers no place ports. L9 says a property or final predicate of a combined scope may name only place ports and generated places. So V-06 and V-07 'always reachable `breaker/closed = 1`' in a combined scope end as Unknown ModelIncomplete ('breaker/closed is not a port'), not Proved or Disproved. The same holds for the §3.5 proposal that the editor prefills a combined-scope final predicate from children's states. Pick one: (i) make every state place an implicit, read-only place port that can never be bound (recommended; it matches F3 and the state-atom meaning), and amend P3 and ADR 0003 accordingly; or (ii) keep P3 and change these vectors to ModelIncomplete. Do not leave the outcome hanging on Q3.

These vectors give 'no dead transitions' results without an [S4] tag: V-01, V-04, V-05, V-06, V-07, V-08, V-09, V-10, V-11, V-13 and V-15. The theorem's 'No dead transitions' bullet, the V-16 rationale and the SM-W01 note ('that is what no dead transitions finds') also present it as available in slice 2. Tag these [S4], or explicitly propose moving §8.5 forward.

As written, the machine fails validation and every property is Unknown 'model incomplete', not the stated Proved or Disproved. Rename the events (for example `fail` and `cool`). I recomputed with distinct IDs: the sizes and results are unchanged (V-06: 3 places, 3 transitions, |R| = 2; V-07: 3 places, 2 transitions, |R| = 2, Disproved in 1 step).

The four postconditions only check the premises of Lemma 1. A compiler that swaps `from` and `to`, puts the initial token on the wrong state, or leaves out an SM transition or a fusion still passes them. sm_replay only ever sees Disproved evidence, so such a bug produces a wrong Proved at runtime and is caught only by tests. Add a runtime `check_lowering(model, open)`, written from §3 and the model and never calling `lower::state_machine` (the same module-boundary test as sm_replay). It should assert: for each τ, exactly the net transitions expected by §4.2, each with pre `{E/τ.from: 1}` and post `{E/τ.to: 1}` on S_E; `M0` is the indicator of the initial state; for each sync relationship, the fusions are exactly port(a) × port(b); for each async relationship, the arc sets match. Failure → Unknown InternalError. If you do not add it, remove the claim.
- §10 test vectors must follow net-semantics §12 and §14 conventions. Drop 'Among equally short ones the order of steps is not normative': §12 fixes the order, and golden tests compare exactly. V-12 is `consumer/halt`, then `producer/send`. ### Should fix
- §4.1 'Why overflow for state places': state the cost. Net-semantics §8.2 gives a structural Proved for 'no capacity exceeded' only when no place is `overflow`. Every scope that contains a state machine therefore loses the structural Proved and its 'every place blocks or drops' text, and always explores (V-11 and V-11b are Proved by exhaustion, 6 markings). Also, sm_replay must run on `UnknownReason::CapacityExceededFirst.steps` too, which the draft leaves out, and must map any Overflow or capacity-exceeded-first result that names a state place to InternalError. Otherwise a compiler bug reaches the user as 'set Breaker: closed to block or drop', which the user cannot do.
- V-16 rationale is wrong under net-semantics §6.3. An empty cross product creates no Fusion, so `caller/admin` is not removed. It stays as its own transition and fires alone; the net has 2 places and 2 transitions (`caller/admin`, `calls/call+accept`), not 1. L4 already fails lowering for it. Keep SM-E11 as the clearer message, but correct the stated failure mode and the net size, and say which detail line wins (SM-E11 or L4) and in what order.
- §4.2 size formula double-counts in state-machine-to-state-machine bindings. Summed per SM transition, V-13 gives 4 fused transitions, but the net has 2. State it per scope: own and internal transitions, plus async-bound transitions, plus the sum over sync relationships of |P_a| × |P_b|.
- LIM-1/LIM-2: sync fusion is a cross product. Two machines at SM_TRANSITIONS_MAX = 4,096 on one event can produce about 16.7 million fused transitions. Add a named limit on fused transitions per scope (or per relationship), checked in `lower` before allocation, with a model-incomplete or limit message.
- SM-B05 rationale is outdated. Net-semantics L7 does define async fan-in for Petri net ports: a transition that is the endpoint of several AsyncLinks gets a pre arc from each generated place, so it waits for a message in all of them (an AND-join). Say that SM-B05 deliberately avoids this join semantics for events, and that it also forbids output broadcast. Consider raising the same AND-join surprise for Petri net ports with the net-semantics owner.
- §2.1 binding table: the Petri net place port cells say 'net semantics'. Net-semantics §6.2 says place ports are never bound in v1, so write 'never (net semantics §6.2)', and decide whether SM-B03 is still needed or simply follows from that.
- §7 and V-18: net-semantics §6.6 requires `ModelIncomplete.details` lines in qualified IDs, ordered by rule number and then ID. The draft's SM messages use display names. Define SM causes as typed details (code plus state, event and transition IDs) that the UI renders with names, give their sort position relative to L1–L13, and remove duplicates: V-18 would currently show SM-B07 for `request` plus L4 lines for `breaker/accept` and `caller/call`. Golden tests need the exact list, as net-semantics V28 gives.
- §6.4 step 3 deadlock check is incomplete. Also reject a claimed deadlock when an SM transition from `active_n` has an async-bound output event to a non-block generated place (always enabled), or an async input event with `M_n(r) ≥ 1`. Simplest: recompute §3 enabledness for every SM transition from `active_n` and `M_n`. Also say what happens when sm_replay fails on a cache hit (evict the entry and show Unknown internal error?).
- §9.1 F1 reserves `@` for per-leaf copies (`E/τ@leaf`), but net-semantics §2.2 slugs and the §5.3 predicate lexer do not allow `@`, so these would be invalid qualified IDs. Either note that nesting will need a net-semantics §2.2 amendment and a `petrinet-net` version bump, or pick a scheme that fits the current grammar.
- Verdict text: net-semantics §9.6 attaches 'every port of `<element>` can fire at any time' to every own-scope verdict. Give the state machine wording, for example 'every input and output event of Breaker can happen whenever its state allows it'.
- V-19 / SM-E10: say what the Model holds for an element whose file failed to load. If the element is left out of the Model, a combined scope could be checked without its behavior. Require that it stays as a placeholder that fails lowering (an L1-like cause), so the scope is Unknown rather than checked without it.
- Glossary: propose entries for Event, the event directions (input, output, internal), Initial state, Final state (and how it relates to final markings) and Active state. In §5, 'reference state (σ, m)' covers Petri net places as well, which breaks the flows/glossary rule that 'state' never refers to a Petri net; rename it (for example 'reference configuration').
- §8: restate the fitness rule as 'a mutation changes the key iff it changes `canonical(flat)` or the property', not 'the compiled OpenNets'. The order of parts and fusions in OpenNets can change without the key changing.
- §5 theorem, deadlock-free bullet: point out that deadlock is global (net-semantics §7, V43). One state machine that keeps looping, for example on a self-loop, masks other elements that are stuck forever. Add an SM vector for this.

### Questions for the user
- Should states of a child state machine be nameable in properties and final predicates of the parent scope? This decides between making state places implicit read-only place ports (my recommendation) and keeping net-semantics L9 strict, in which case V-06/V-07-style combined-scope state properties are Unknown 'model incomplete'. It affects ADR 0003, net-semantics L9 and draft P2/P3.
- Accept set-valued asynchronous bindings (AsyncLink.from/to as transition sets) as an amendment to net-semantics, to land before slice 0 code? The alternative is to allow only one transition per async-bound event, which in practice rules out async state machines.
- State places with `overflow` (a compiler bug becomes visible, but no structural Proved for 'no capacity exceeded' in any scope with a state machine) or with `block` (structural Proved is available, but a compiler bug could hide as an extra constraint)? It affects §4.1 and the cost of capacity checks.
- CODING_STANDARDS VER-2 says a failed replay is 'internal disagreement'; the design, net-semantics §9.2 and this draft say 'internal error'. Which should change? (draft Q6)

### Questions for the user
- Do you accept P1 as an amendment to the final net semantics spec (AsyncLink from/to become non-empty sets of transitions, landed before slice 0 code)? ## Decisions

- Rebased the spec on net-semantics revision 2; removed the 'net semantics not provided' header and old Q1. — Both reviewers: the final upstream spec now overrides several things the draft relied on.
- Step.fired is one qualified ID; sm_replay parses `E/τ` or `r/a+c` (bare names) and resolves elements through the relationship's source and target (L11). It takes M_0 from Lowered.flat. — NS 9.1 and NS 16 item 5 make fired a single flat ID, and a Counterexample has no M_0.
- Every member of port(E/e) counts as a transition port for L4, L5, L7 and L11. L4–L8, L11 and L12 are evaluated per event for state machines, so one unbound event gives one detail line. — Makes the port mapping explicit and keeps golden detail lists deterministic, with no duplicates (V-18a).
- SM-E05 enforces the NS 2.2 slug rule and also reserves `__`. — Every compiled ID must be a valid qualified ID that the predicate lexer can read, and nesting later needs a naming scheme inside the current grammar without an NS amendment.
- Set-valued AsyncLink.from/to is written as amendment A1 to net-semantics revision 3, with replacement text for every affected section, new vectors C17–C20, and ADR 0010 and design sentences. It must land before slice 0 code. The encoding is unchanged. — Without it an async event used in more than one state cannot be compiled, and net/verify/recheck would change in slice 2.
- States are implicit place ports that are never bound (A2/A3), so parent-scope properties and finals may name them under L9 unchanged. The user is still asked to confirm. — The architect asked for a pick instead of leaving it hanging. This choice matches F3, the slice 4 prefill and ADR 0003's literal wording.
- Added the runtime `engine::check_lowering` (checks C1–C5, written from the Model and §3, never importing the compiler), which runs on lower-<rev> for every scope with a state machine. — The postconditions alone let swapped from/to, wrong initial or omitted transitions through as a wrong Proved. The recomputed LC-01 and LC-03 show this.
- sm_replay also runs on CapacityExceededFirst.steps and maps any overflow on a state place to InternalError. Its deadlock check now also covers async in and out transitions. On a cache hit it reruns on a supervised check-<key8> thread and evicts the entry on failure. — Otherwise a compiler bug reaches the user as 'set Breaker: closed to block or drop'. The extra checks catch more bugs at no cost.
- Kept `overflow` for state places and stated the cost: no structural Proved for 'no capacity exceeded' in any scope with a state machine. Escalated the choice to the user. — Defense in depth against lowering bugs. The cost is real, but small scopes explore cheaply, and P-invariant certificates could recover it later.
- Added `SCOPE_TRANSITIONS_MAX = 65,536`. lower checks it with checked arithmetic before allocating any Fusion (L16, vector V-24). — LIM-1/LIM-2: a synchronous cross product can reach about 16.7M transitions.
- Size formula is per scope, counting Σ over sync pairs |P_a|×|P_b|. — Per-transition counting double-counts SM-to-SM bindings (V-13).
- Kept SM-B05 with a new rationale (an NS AND-join or broadcast is not what fan-in means). Raised PN parity as a team question. — The old rationale claimed the net semantics had no fan-in rule, which is wrong.
- Removed SM-B03; place ports are never bound under NS 6.2, and the table says so. — The rule follows from NS 6.2, and a hand-written file fails L5.
- L4 counts a port as bound when a contributing relationship binds it, even with an empty cross product (A4). SM-E11 is L14 and is the only detail line for V-16. — The V-16 rationale was wrong: caller/admin stays in the net and L4 would give a misleading line. SM-E11 is a clearer message, not a soundness guard.
- ModelIncomplete details use qualified IDs ordered by rule number, with state machine causes at L1 (extended), L4–L6 (per event) and new L14–L16. Display-name copy goes through a typed ProblemDto. — NS 6.6 requires ID-based, ordered detail lines for golden tests.
- Elements whose behavior fails to load stay in the Model as BehaviorModel::Unloaded and fail L1. — A combined scope must never be checked without an element's behavior.
- Test vectors use NS §12/§14 conventions: #R, #O, stored, technique, full waiting payloads and fixed step order. Slice tags were corrected ([S4] for no dead transitions, never, always reachable). Event IDs that collided in V-06/V-07 were renamed (fail, cool). Added V-21 (masking), V-22/V-23 (set-valued async), V-24 (limit), LC and R vectors. Every value was recomputed with a throwaway reference implementation. — Golden tests compare exactly. The earlier draft had wrong slice tags and SM-E04 collisions.
- Own-scope assumption wording for state machines: 'every input and output event of <element> can happen whenever its active state has a transition on it'. — NS 9.6 requires an assumption line on every own-scope verdict.
- Renamed 'reference state' to 'reference tuple', 'firing sequences' to 'runs', and avoided 'link' and 'endpoint' in prose. — Glossary avoid words.
- Closed Q6 (internal error vs internal disagreement for a failed replay). A follow-up edit to CODING_STANDARDS VER-2 is listed as A6. — NS 9.2 step 3 already maps a failed replay to InternalError.

## Proposed glossary changes

- **Port**: A place or transition that a behavior model offers to the outside; for a state machine, an input or output event (standing for its transitions on that event) or a state. Relationships connect to ports, never to the inside of another element's behavior model. _Avoid_: Interface, pin, endpoint, hook
- **Event**: Something that makes a state machine take a transition. Every event has a direction: input, output or internal. _Avoid_: Signal, message (for the event itself), trigger
- **Input event**: An event that something outside the element causes: a call the element accepts or a message it receives. A port. _Avoid_: Inbound port, receive event
- **Output event**: An event by which the element calls something or sends a message. A port. _Avoid_: Outbound port, send event
- **Internal event**: An event that happens inside the element without a partner, for example a timeout or a failure. Not a port. _Avoid_: Private event, spontaneous transition
- **Initial state**: The one state a state machine is in before anything happens. _Avoid_: Start state, default state
- **Final state**: A state in which stopping counts as proper termination; it becomes part of the scope's final predicate from slice 4. _Avoid_: End state, accepting state
- **Active state**: The state a state machine is in at one moment; replay shows it per step. _Avoid_: Current state, mode
- **State machine transition**: A step from one state to another on one event. It becomes one or more net transitions when the state machine is compiled (one per partner in a synchronous binding). _Avoid_: Edge, arc
