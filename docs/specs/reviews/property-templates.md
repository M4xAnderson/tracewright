# Reviews and disposition: Property template catalog

Author: product manager. Final document: `docs/product/property-templates.md`.

## software architect: approve-with-changes

### Must fix
- §9 AC1 fails as written, and so do the §1/§5 T1 claims for any slice before 'done when' exists. I ran E5's explorer on case1_ebs_timeout with the final predicate removed (python3 -I explore.py on a copy). deadlock_free comes out Disproved: the system dead-ends once api_b/done=2 and api_a has failed. It is Proved only with final 'api_b/done = 2'. Fix: the AC must set done when api_b/done = 2 and name the slice it applies from. The T1 text 'E5 case 1 with a timeout: Proved' needs the same qualifier.
- §5 T1 makes 'done when' an optional template parameter. That contradicts ADR 0003 ('Initial and final markings are model data') and design.md, where finals sit on the Net (`Net { finals: Option<FinalPredicate> }`). It is one predicate per scope, shared by every deadlock-free check and by T7's 'done' preset. If it were a T1 parameter, two T1 properties on one scope could disagree about what 'done' means. Fix: make 'done when' scope data, edited on the scope element; T1 has no parameters and its Covers line shows the scope's predicate. Moving it to slice 1 (§11.3) also changes ADR 0010's normative text ('Final markings ... (slice 4; before that there are none)'), so tag it [ADR change], not [proposal]. Its cost also includes final-marking evaluation written twice (verify and recheck) plus E1 golden tests, not just 'FinalPredicate already exists in net'.
- 'Templates are outside the trust path' (§2.1, Decisions claimed) is false. Expansion runs in engine lowering. ADR 0010 says both explorers share lowering and do not cross-check it. A wrong expansion (wrong capacity, wrong K, a missing held place) yields a correctly re-checked Proved of a different property, shown under the user's sentence. To the user that is a wrong Proved. Required: (a) render the 'Checks:' line from the canonical NetProperty that the worker explored and hashed into the CheckKey, never re-derived from the template parameters in engine or UI; (b) add a lowering golden test per template, next to the binding-rule golden tests ADR 0010 requires; (c) state that each template's expansion rule is part of the file format's meaning (§2.4 stores templates by name). Changing a rule (for example T5's default K) then needs a format version bump and migration under ADR 0001. Otherwise a project reopened months later (J6) silently asks a different question.
- §5 T4: '"Never fills up" Proved: ... it never blocks a sender' is false when an arc into a block place has weight w > 1. Under ADR 0010 firing, such a sender is blocked as soon as p > capacity − w, without p ever reaching its capacity. E5 already uses weight-2 arcs (case 1 fix), so this is not hypothetical. A Proved that claims more than it checks breaks the draft's own misread-Proved guardrail. Fix: lowering knows the arc weights. Either make the claim only when every transition adds at most 1 net token to p, or expand to N = capacity − (largest net token gain of any transition on p). Otherwise word it only as 'never reaches its capacity'. The drop half of the claim holds, because a drop leaves p at its capacity.
- §5 T4's resize claim ('setting its capacity to N would change no reachable marking and no other verdict') is wrong as stated, and §11.6 would turn it into a golden test. The reachable markings are identical only within the scope where T4 was proved, with the same initial marking and the same other capacities. An internal place also belongs to its element's own scope, where ports are closed and port transitions fire alone (ADR 0010), so the reachable markings there differ. Under the follow-edits rule of §2.4, any template that reads that capacity also changes its question. For example, T4 'never fills up' on the same place now asks p ≤ N−1 and is typically Disproved. Fix: 'In this scope, with these starting tokens, setting the capacity to N leaves every reachable marking unchanged; verdicts in other scopes and properties that read this capacity become stale and are checked again.' Write the golden test to that statement.
- §5 T2: 'If no place in the scope overflows when full, the panel says so: "Proved: nothing here can overflow..."' reads as a structural shortcut. A Proved that skips the check pipeline violates ADR 0008/0010, which require evidence re-checked by independent code. State that this Proved comes from the normal check: exploration confirmed by recheck, or a trivial certificate that recheck verifies on its own composition (no overflow places). The note is appended text, not a separate path. The headline must also follow the W2 rule, not replace the sentence.

### Should fix
- T7/T8 when an overflow marking is reachable (§5, §6). ADR 0014's rule 'a violation reached without passing through an overflow marking is Disproved' fits counterexample-shaped violations. It does not fit T7, whose Disproved needs an exhaustive search from the last marking, or T8, which is exhaustive. Overflow markings are dead ends in both searches. T7's 'No continuation from here reaches it' can therefore be false when the only way back passes through an overflow, and T8 can list a transition that is enabled only after an overflow. E5's explorer returns Unknown in both situations (explore.py check(): undecided). I recomputed T7 on the overflow-truncated graph for case3_dynamodb_bad, case2_kinesis_bad and case3_dynamodb_pmfix: 0 markings violate it, so AC4 holds either way. Pin the rule down: T8 is Unknown 'capacity exceeded first' whenever an overflow is reachable; T7 is Disproved only if no overflow marking is reachable from the counterexample's last marking, otherwise Unknown. Add E1 golden tests and add 'capacity exceeded first' to T8's typical Unknown.
- T5 needs K ≥ 1. With K = 0, 'never Σ held ≥ 0' holds in the initial marking, giving a 0-step Disproved that means nothing. The default K (all tokens the pool starts with) is 0 for a pool that starts empty, so validate K ≥ 1 or reject the property in the picker. Also add to 'Proved does not mean': 'tokens in places you did not mark as held by are not counted'. The headline uses the display-only holder label, so the Covers line must name the held-by places.
- W2 conflicts with W6 and the example headlines. W2 says the headline is the verdict plus the sentence exactly as asked, but T1/T2/T7 Disproved and the T2 'nothing can overflow' case show other headlines. Define the headline per verdict: Proved/Unknown = verdict + sentence; Disproved = verdict + sentence, then a 'can' line.
- W9 only covers T3, but T4 can also be vacuous. N ≥ capacity on a single block or drop place, or N ≥ the sum of the capacities when every summed place blocks or drops, gives a Proved decided by 'when full' alone. Warn about these or don't offer them.
- T7 preset 'its start' is defined as 'the initial marking of the whole scope, generated places at 0'. That is self-contradictory if a generated place can carry initial tokens. Define it as the initial marking, exactly.
- T1 Disproved help ('the model needs a way back to the start') teaches users to add reset transitions. A carelessly enabled reset transition can hide real deadlocks. Drop the advice, or limit it to pointing at 'done when' and the slice it arrives in.
- §11.4 understates the cost. design.md says only the NetProperty types exist ("`NetProperty::Never/AlwaysReachable` and `FinalPredicate` already exist; model-side parsing lands in `model`"). Slice 0 has only deadlock-free and no capacity exceeded. Pulling 'never' sums into slice 1 also means predicate evaluation in both verify and recheck, the canonical predicate encoding, CheckKey fitness tests and E1 golden tests.
- ADR change 1 also needs design.md amended ('Properties refer to places through qualified `element/port` IDs (ADR 0003)'). Say how rename/delete of a referenced internal place or state works: like a relationship reference, a dangling reference gives model incomplete with that line, and delete warns. Record the trade-off against ADR 0002's encapsulation reason: parent properties now depend on child internals, which constrains later contract abstraction. Consider an explicit 'observable' flag on places as the alternative.
- Glossary drift (CLAUDE.md: domain terms follow GLOSSARY.md exactly). The UI copy uses 'done when', 'step', 'starting tokens', 'the start', 'holder' and 'held by', none of which are glossary terms; the glossary has initial marking and final markings. Add Done when (the UI name for the final-marking predicate), Step and Held by to §11.7, or use the glossary terms.
- The ACs use E5 files as fixtures, but under ADR 0014 the loader reports them as 'model incomplete' because their internal places have no when_full. Specify that the fixtures are ported to the product format: overflow on every internal place to match E5's semantics, and bags as generated places on relationships.
- The AC1 quote ('A loop such as a timeout or a retry can keep running without finishing work') does not match the T1 text ('...can keep running forever without finishing work and still counts as not stuck'). Make the one-line 'does not mean' text a single canonical string that both use.
- W4: the Covers line should also show the scope's 'done when' predicate. For T2/T3 it should list the places that block or drop, because they are why those places 'cannot go over' their capacity.
- W10 ('capacity 50 then, 30 now') needs the expansion values kept with the displayed verdict. The CheckKey cache holds only a hash plus the NetVerdict (ADR 0013), so say where these values live; it is display-only and in memory, never persisted (ADR 0005).

### Questions for the user
- ADR change 1: should a property be allowed to reference any internal place or state of a child in a combined scope, as the draft proposes? Or only places the child marks as observable? This decides whether parent properties depend on child internals (ADR 0002's encapsulation reason) and what later contract abstraction must preserve.
- Templates stored by name and parameters, with values that follow edits (§2.4, a new ADR plus a file format change): do you accept that a property's question changes when a capacity or the pool's initial tokens change, with the old verdict shown stale? The alternative is storing the expanded predicate, which never changes on its own.
- Move 'done when' (the final-marking predicate) from slice 4 to slice 1? This amends ADR 0010's text and adds final-marking evaluation to both explorers in slice 1. Without it, the E5 case 1 and case 2 deadlock checks are Disproved at their intended end.
- T7/T8 when an overflow marking is reachable: always Unknown 'capacity exceeded first' (conservative, matches E5's explorer), or the literal ADR 0014 rule, which can Disprove 'can always get back to' from a marking whose only way back passes through an overflow? Either choice needs a one-line ADR 0010/0014 clarification and an E1 golden test.

## senior backend developer: approve-with-changes

### Must fix
- §2.1 / §4 T1 / §5 T1 'Parameters: optional done when' / T7 'done' preset: making 'done when' a parameter of the T1 property contradicts ADR 0003 ('Initial and final markings are model data') and design.md §4 (`Net { finals: Option<FinalPredicate> }`, one `lower(m, scope)` flat Net per scope; ADR 0013 puts the final predicate in the net part of the CheckKey). Two T1 instances with different 'done when' would need two flat nets per scope. Fix: 'done when' is model data on the scope element (one per scope), T1 has no parameters, and T7 'done' reads the scope's final predicate. docs/ux/flows.md §4.13 already treats it this way ('Define a final marking').
- §9 criterion 1 (case1_ebs_timeout, T1 Proved) gives a wrong verdict as written. E5 P1 is Proved only with `final = "api_b/done = 2"`. Without it, the marking where every call is done or failed enables nothing, so the check is Disproved. State the final predicate and the slice it needs (4, or 1 under §11.3). Also, the quoted line ('…keep running without finishing work') does not match §5 T1 ('…keep running forever without finishing work'); one exact string is needed for a test. More generally, every §9 'Given E5 caseX' must name a fixture ported to the v1 format with an explicit when_full on every internal place (ADR 0014: no default inside a behavior model). E5's files have none, and for case3_dynamodb_bad the choice changes which place overflows first.
- W2 ('verdict plus the template sentence … with current names and values') breaks for a stale verdict. After a resize from 50 to 30, the headline would read 'Proved: … never go over the capacity (30)' for a check that ran at 50. That is a Proved the user reads as covering something it never checked, which W10 cannot fix. Fix: names are current (ADR 0013), but values in the headline and the §2.3 'Checks:' line always come from the expansion the verdict was computed for. So the verdict DTO / cached NetVerdict must carry the canonical expanded property, and W10 derives 'then vs now' from it. Add this to the §2.4 proposal and to design.md's VerdictDto.
- §2.4 together with W9 leaves out what happens when a stored template's preconditions stop holding after an edit, because the expansion happens at lowering: (a) T3 on a place the user later switches to block or drop expands to a vacuous never p > cap and gives exactly the Proved that W9 forbids; (b) T5 with a pool that starts with 0 tokens gives default K = 0, which is Disproved at step 0; (c) T4 'never fills up' on capacity 0 gives N = −1. Specify per-template preconditions that are checked at lowering. When one fails, the result is a KeyState::Unknown with a reason line ('model incomplete: T3 needs a place that overflows when full; Billing / inflight now blocks'), never a vacuous verdict. Add a §9 criterion for (a).
- T3 depends on a rule that ADR 0014 and ADR 0010 do not state normatively: is a never-predicate evaluated on an overflow marking before that marking is discarded? ADR 0014 says 'when an overflow marking is reachable but no violation was found → Unknown', which two implementers can read either way. If both explorers skip the evaluation, T3 is never Disproved, only Unknown 'capacity exceeded first at <this place>'. §11.6 proposes only a golden test, but ADR 0009 requires each rule to be written once as text and then twice as code. Fix: propose an ADR 0014/0010 text amendment ('a property is evaluated on an overflow marking; a never-p violation there, reached without passing an earlier overflow marking, is Disproved'). In the same amendment, make the place named by CapacityExceededFirst deterministic (for example, the first overflow marking in BFS layer order, tie-break by qualified ID, or list them all). Otherwise verify, recheck and the §9 case3_bad criterion can name different places.
- §5 T4 'never fills up' Proved says the place 'never blocks a sender and never drops a message'. That is false when an input arc has weight > 1: at capacity − 1, a weight-2 arc into a block place is disabled (the sender waits), and into a drop place it discards a token, even though p never reaches the capacity. This is a Proved that claims more than it says, which the §1 guardrail forbids. Fix: offer the preset only when every input arc of the place has weight 1 (always true for generated places), or set N = capacity − (largest input weight) and word the claim to match.
- §3 table, 'Never' Proved: 'Holds for every order of steps, so no timing can break it, as long as the model's abstractions hold ("slow" = never responds …)'. Modeling slow as never responds removes behavior (the late response) instead of adding it, so a 'never' Proved on that model is not preserved for the real system where the response arrives late. The caveat as written invites the very misread it is meant to prevent. Fix: 'Proved covers every order of the steps the model has. A step the model leaves out (for example a slow service modeled as never responding) is not covered.' Add a wording or help rule that recommends modeling slow as 'may respond at any time' when asking never-questions.
- Decisions claimed, 'templates are outside the trust path', is wrong. The expansion maps the sentence the user reads to the NetProperty that is checked. Like lowering (ADR 0010: shared by both explorers, covered only by golden tests), a bug in the expansion, such as the wrong capacity in T3, a place missing from T7 'its start', or a wrong default K in T5, produces a Proved for a different sentence, and both explorers will agree on it. Fix: state that template expansion is shared code in the trust path. Require an engine golden test for each template and preset (including 'its start' and 'never fills up'). Require the §2.3 'Checks:' line to be rendered from the canonical NetProperty the worker hashed, never from the template parameters. Put all of this in the proposed new ADR (§11.2).

### Should fix
- §11.1 ADR 0003 change is incomplete. (a) design.md §4 ('Properties refer to places through qualified element/port IDs') and §6 (lowering reports a 'dangling … port reference in a property') also need to change to place and state references. (b) Weigh the change against ADR 0002's rejected option: renaming an internal place now breaks properties stored in another element's file and blocks later contract abstraction. Either propose rename propagation as part of the same Command, or say that a dangling reference is reported. (c) Define the qualified ID of a state machine state's place (ADR 0010 defines none, and a state could collide with an event name). §4 slice 2 depends on it.
- §9 last criterion ('a hand-written predicate with the same expansion has the same CheckKey') needs a canonical LinearPredicate form, or the test is underdetermined: T3's 'p > 50' against a hand-written 'p >= 51', term order, merged duplicate terms, explicit weight 1. Specify the normalization (sorted qualified IDs, merged terms, integer comparisons normalized to a single form) and add it to ADR 0013's fitness and invariance tests.
- §2.4: store a stable template kind ID plus a template version, not the user-facing name, so that rewording the UI never breaks files and a change to an expansion rule is a format migration (ADR 0001). §2.3 'Edit as predicate' freezes values read from the model (capacity, K, 'its start'), so the dialog should say that the property stops following edits.
- §5 T4 resize claim ('would change … no other verdict'): changing a capacity changes every CheckKey of the scope (capacity is in the key, ADR 0013), so every verdict goes stale and is checked again. Properties that read this capacity (T3, 'never fills up' on that place) change meaning. Narrow the claim to: no reachable marking changes, so re-checks give the same outcome for properties that do not read this capacity.
- Wording is inconsistent with the draft's own rules. W3 allows only 'never …' and 'can always get back to / can still …', but T2 ('Nothing in Order system goes over its capacity') and T8 ('Every transition … can fire at least once') follow neither form. T7 is named 'Can always get back to', its sentence says 'can still get back to', and §9 checks for 'can still get back to'; pick one, preferably E5 implication 5's 'can always get back to'. The T4 preset 'Order API → Billing never fills up' breaks W8 ('messages in transit on <A> → <B>').
- Glossary conflict: Disproved is defined as having a counterexample, and the Relationships section says 'Only a Disproved verdict has a counterexample'. T8's Disproved, like ADR 0010's no-dead-transitions evidence, has none. Add a glossary change to §11 next to the VRD-2 exception (for example 'a counterexample or, for no dead transitions, an exhaustive exploration confirmed by the second explorer').
- T8: define how dead transitions are named. One port transition becomes one fused transition per caller (ADR 0010: relationship/caller+callee). Say whether an element's transition is listed as dead only when every fused copy is dead, and how a dead fused copy is shown ('Billing / accept, when called by Order API').
- T2 'Proved: nothing here can overflow' must still come from evidence that independent code checked (ADR 0008): both explorers, or a structural check in recheck. The engine or UI must not short-circuit it because no place overflows. Say so explicitly.
- T1 Disproved help ('the model needs a way back to the start until done when is available') pushes the user to add a reset transition. That changes the reachable markings for every other property in the scope and can hide real deadlocks. Drop the advice, or limit it to a transition whose inputs are exactly the done tokens, and prefer §11.3.
- §11.3 and §11.4 cost: 'FinalPredicate / Never already exist in net' is true only of the types. net holds no semantics (ADR 0009), so final-predicate and linear-predicate evaluation must be written twice (verify and recheck) with E1 golden tests, plus format, migration and editor support. Restate the cost honestly before asking the product owner to move them to slice 1.
- T5: if the user leaves a held place out (for example ret_a), the result is a Proved about a smaller sum. Add a lowering-time hint (each transition that takes a pool token for this holder must put it into a held place; warn otherwise, outside the trust path), and say how the default K counts held places that start with tokens (pool initial tokens only, or pool + held).
- Align docs/ux/flows.md §4.13 (three templates, a combobox over element/port places, final marking as model data, previews using 'reachable marking') with this catalog once the ADR 0003 change is decided. Section 10's template ID in the slice 1 check log only makes sense if §11.4 is accepted.

## Decisions

- Template expansion is in the trust path. Each template and each preset gets a lowering golden test, and the 'Checks:' line is rendered from the canonical NetProperty that the worker hashed. — A wrong expansion gives a correctly re-checked Proved of a different property, shown under the user's sentence. Both explorers share lowering (ADR 0010), so only golden tests catch it. This replaces the earlier claim that templates are outside the trust path.
- 'Done when' is model data on the scope element, one per scope. T1 has no parameters, and T7 'done' reads the scope's predicate. — ADR 0003 says that final markings are model data, and design.md has Net.finals. A T1 parameter would let two T1 properties disagree about what done means.
- T4 'never fills up' expands to N = capacity minus g, where g is the most tokens any single step adds to the place. — With a weight-2 step, the place blocks or drops at capacity − 1. N = capacity − 1 would then give a Proved that claims more than was checked. With N = capacity − g, the 'never waits or loses a message' claim always holds.
- Every template has preconditions that are checked at lowering and in the picker. When one fails, the result is Unknown 'property does not apply' and never a vacuous verdict. — Templates follow edits, so T3 on a place later switched to block, T5 with K = 0, or 'never fills up' with a negative N would otherwise give a vacuous Proved or a meaningless 0-step Disproved.
- Headline values come from the expansion that the verdict was computed for. Names are current. — A stale Proved at capacity 50 must not read as covering 30.
- Each template has one canonical 'does not mean' string (at most 75 characters). The UI and the acceptance criteria use the same string. — Testability, and AC1 had drifted from the T1 text.
- T7 is named 'Can always get back to' everywhere, and every sentence form is fixed per template in W3. — The name, the sentence and the acceptance criterion were inconsistent. E5 implication 5 uses 'can always get back to'.
- T6 is held back from the slice 4 catalog. The custom predicate covers lock questions until the journal shows two of them. — E5 has no evidence for it. Slice 4 already expresses the question as a custom predicate, so holding it back costs the user nothing and saves a template and its golden tests.
- T1 Disproved help no longer suggests adding a way back to the start. — A reset transition changes every property in the scope and can hide real deadlocks.
- The T4 resize claim is narrowed to: in this scope, with this initial marking, every reachable marking is unchanged. Other scopes and properties that read the capacity go stale. — The broad claim was false in the element's own scope and for templates that read the capacity. The golden test follows the narrow statement.

## Proposed glossary changes

- **Property template**: A named sentence with blanks that the user fills in to state a property without writing a predicate. It expands to one built-in property or to one 'never' or 'always reachable' predicate, and adds no meaning of its own. _Avoid_: Preset, snippet, macro, pattern, rule
- **Pool**: A place whose tokens stand for interchangeable resources that steps take and give back, such as threads, connections or permits. It usually starts full. _Avoid_: Semaphore, resource place, free list
- **Held by**: The places that count as one holder's share of a pool in a 'never holds the whole pool' property. Tokens in other places are not counted. _Avoid_: Owned by, allocated to, in use by
- **Done when**: The UI name for a scope's final markings: a condition on places or states that marks proper termination, so that a run ending there is not a deadlock. It is model data, one per scope. _Avoid_: End state, terminal state, goal, exit condition
- **Step**: One firing of one transition. A counterexample is a sequence of steps from the initial marking. _Avoid_: Firing, move, tick
