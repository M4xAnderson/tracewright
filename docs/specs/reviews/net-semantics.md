# Reviews and disposition: Net semantics spec

Author: software architect. Final document: `docs/specs/net-semantics.md`.

## senior backend developer: approve-with-changes

### Must fix
- §6.1/§6.5 step 6: `OpenNets = { parts, fusions, links }` has no field for the scope's final predicate, and parts carry F = none. So `recheck::compose(O)` cannot produce the `final <pred>` line that `engine::flatten` emits (§11). From S4 on, every deadlock-free check with a final predicate becomes Unknown InternalDisagreement at step 0. If an implementer 'fixes' this by having recheck ignore F, recheck replays deadlocks against a different definition. Fix: add `final: Option<Pred>` to `OpenNets` (also for own scopes), make step 6 read it, and add it to design §3.
- §14 budget vectors are wrong. PC(block) deadlock-free with N = 20: verify gets ⌊20/2⌋ = 10 stored markings and needs 18, so the result is Unknown BudgetExhausted{Main, 10}, not {Recheck, 10}. A Disproved also never runs `recheck::explore`, only replay, which stores nothing (§9.2 step 3, §10.1), so 'recheck has 10' cannot happen. Separately, in PC(overflow) the overflow marking (1,4,0) is the 9th stored marking, not the 7th, because `c/consume` sorts before `p/produce`. I checked all of this with an independent reference implementation. A structural point: because recheck explores the same net with N−⌊N/2⌋ ≥ ⌊N/2⌋ markings, BudgetExhausted{Recheck} can never come from the marking budget while verify has no reductions. Say so, and test the Recheck phase with an injected deadline or Clock instead.
- §10.1 vs Appendix A: the budget accounting is ambiguous, and the conformance vectors depend on it. §10.1 says stored = |R ∪ O| and 'exhausts when it would store one more'. The pseudocode checks the limit only when inserting into R (overflow markings are stored unchecked), and it runs `test(M')` after the store. Make these rules normative: (a) M₀ counts as 1; (b) every insertion into R or O is checked against the limit; (c) a marking that does not fit is neither stored nor tested, and the result is Unknown BudgetExhausted; (d) the exact boundary, so that budget = |R∪O| completes and budget = |R∪O|−1 does not, plus one vector for each side.
- §5.3: the predicate grammar is ambiguous for legal IDs, so the user's text can silently become a different property. IDs may contain `-` (§2.2 charset `[A-Za-z0-9_-]+`, example `rel-7`), and generated-place IDs have no `/`. So `p/in-flight - r >= 1` and `a/x-b` each tokenize two ways, and a relationship ID such as `not`, `or` or `and` collides with a keyword. Fix: tokenize an ID as the maximal `[A-Za-z0-9_/-]+` run, require whitespace around a binary `-`, and reserve `and`, `or` and `not` as element and relationship IDs in the format spec. Alternatively, quote IDs. Add parser vectors for each case.
- §6.6: the lowering rules do not say which relationships count in a combined scope. They also do not say what happens when a child's transition port is bound only by a relationship whose other end is not a child of the scope (an external person or system drawn in the slice 0 Container view, or from slice 3 an element in another view). If engine treats that port as closed (§6.2 own-scope rule), the port fires freely, which adds behavior that can hide a deadlock or let a predicate hold. That is a wrong Proved, and both explorers share it because lowering is shared. Specify: only relationships with both endpoints among the scope's children contribute; L4 fails otherwise; ignored relationships are listed as assumptions. Also require caller ∈ source(r) and callee ∈ target(r) (and the same for async from/to). Without that, two fusions on one relationship in opposite directions, (A/x, B/y) and (B/x, A/y), both get the ID `r/x+y`.
- §16 claims 'No ADR is contradicted' but changes settled text, and the brief requires deviations to be stated as proposed ADR changes. These are changes, not clarifications: item 1 (ADR 0010 says 'every port of every child must be bound'; the spec binds transition ports only), item 3 (ADR 0010's always-reachable confirmation gains 'and no overflow marking'), item 5 (L9 narrows ADR 0003), and item 6 (design §3 `Step.fired: BTreeSet` becomes a single ID; also `Violation::Predicate { value: i64 }` becomes i128 in §9.1). Write each one as 'Proposed amendment to ADR 00xx / design §3' with the replacement sentence, so both crates are built against one agreed text.
- §14 has no composition vectors. Every vector is a hand-flattened net, but `recheck::compose` and `engine::flatten` take `OpenNets`, and ADR 0010 Consequences requires a golden test for every rule in both crates. Only the proptest (encoding vector e) touches composition, and it checks equality, not correctness: two implementations that both forget to remove a bound callee agree. Add OpenNets-form vectors with the expected canonical encoding for at least: sync fusion with removal of both bound transitions; a callee with 2 callers (LOCKS); a caller with 2 callees; an async link with its default `overflow` and with `block`; an own scope with a closed port as a free source; a duplicate fused ID rejected; and the L6/L7/L8 ComposeError cases.

## researcher: approve-with-changes

### Must fix
- Integer overflow can produce a wrong verdict (sections 2.3 rule 6, 3.2, 4.2, 9.1). Capacities, weights and counts only have to 'fit in u32', but an overflow marking can reach cap(p) + max W+(t,p), which can exceed u32::MAX. Example: cap 4294967295 with an overflow output of weight 2. Cargo's default release profile sets `overflow-checks = false` (https://doc.rust-lang.org/cargo/reference/profiles.html), so the count wraps to a small number. The marking then looks in bounds and no capacity exceeded can be Proved by both explorers in the same way. ADR 0006 keeps `assert!` on, but that does not cover arithmetic. Fix: add a validation rule cap(p) + max_t W+(t,p) <= u32::MAX (and M0 + weights similarly), or store counts as u64 and say so. Also widen `Violation::Overflow.count` to match.
- The final predicate F has no carrier in OpenNets (sections 6.1, 6.5 step 6, 11). `OpenNets = {parts, fusions, links}` (also design section 3) has no final predicate. Yet flatten step 6 sets F from 'model data of the scope element', and the canonical encoding includes a `final none | final <pred>` line. `recheck::compose(O)` therefore cannot rebuild F. From slice 4 on, either every check with a final predicate ends as InternalDisagreement at step 0, or recheck quietly takes F from engine's flat net, which brings back the shared path that ADR 0010 forbids. Fix: add `final: Option<Pred>` to OpenNets (amend design section 3) and have both compositions copy it.
- Budget vectors and budget rules are wrong or ambiguous (sections 10.1, 14 budget vectors, Appendix A). I re-ran them with a reference implementation of sections 2-8 and 12. (a) Deadlock-free on PC(block) with N = 20: main gets floor(20/2) = 10 markings, but the deadlock is the 18th marking stored, so the result is BudgetExhausted { Main, 10 }, not 'verify finishes (18) but recheck has 10 -> BudgetExhausted { Recheck }'. Recheck would not explore at all after a Disproved; it only replays. (b) The recheck phase can never run out of markings when verify has finished: N - floor(N/2) >= floor(N/2), and without reductions both store the same set of R and O markings. A BudgetExhausted { Recheck } vector therefore needs a fake-clock deadline. (c) In PC(overflow) the overflow marking is the 9th marking stored, not the 7th (the outcome for N = 10 is still right). (d) Section 10.1 counts stored markings as R and O together, but in the Appendix A pseudocode O insertions skip the budget check. (e) 'Poll ... before reporting any result' contradicts 'Early stop ... proceeds to replay even if the budget would have run out'. Pick one rule, put it in both the text and the pseudocode, and fix the vectors.
- The predicate grammar is ambiguous (sections 2.2 and 5.3), which can parse a predicate wrongly and so give a wrong verdict. Slugs match `[A-Za-z0-9_-]+`, so they may contain `-`, start with a digit, or equal `and`, `or` or `not`. Generated-place IDs are bare relationship slugs with no `/`. As a result, `rel-7 - 2 >= 0` (the draft itself uses `rel-7` in L8), a relationship slug `3`, or one named `not` can each be read in two ways. Fix: require slugs to start with a letter and reserve the keywords, and/or require whitespace around binary `-` in the lexer (or quote IDs). Also state the normalized form exactly as sum((a_i - b_i) * p_i) cmp (d - c), allow atoms with no terms, make i32 overflow while merging a parse error, and either add unary minus / negative constants or exclude them explicitly.
- A settled decision is changed while section 16 says 'No ADR is contradicted' (sections 6.2 / L4 and 16 items 1, 3, 5). ADR 0010 ('every port of every child must be bound') and design section 6 ('any port of a child ... that no relationship binds' fails lowering) both cover place ports. L4 narrows this to transition ports. Item 3 changes the ADR 0010 confirmation rule for always reachable. Item 5 (L9) adds a restriction that ADR 0003 does not state. The brief requires deviations to be named as proposed ADR changes. List items 1, 3 and 5 as proposed amendments to ADR 0010 and 0003 (and design section 6), with the 'Amended by' lines, and do not leave it to the reader to decide whether they are changes.
- The default for asynchronous bindings is missing (part of the brief and of ADR 0014). Section 2.1 says defaults are 'a lowering concern, section 6.5', but neither 6.5 nor 6.6 says that `AsyncLink.when_full` is the relationship's `when_full` and defaults to `overflow`. Nor do they say what happens when an asynchronous relationship has no capacity (a ModelIncomplete line?). Add both rules to 6.4/6.6 and fix the cross-reference.
- Fused-transition IDs can collide (sections 2.2, 6.3, L6-L8). Bare names are unique only if 'the relationship fixes both elements' as caller and callee in a fixed direction, and no L rule requires that. One relationship between A and C with fusions (A/x caller, C/y callee) and (C/x caller, A/y callee) gives `r/x+y` twice. A repeated (caller, callee) pair does the same. Add an L rule: the caller belongs to the relationship's source element, the callee to its target, and each (caller, callee) pair appears at most once per relationship. Also replace the garbled collision argument in 2.2.

## Decisions

- OpenNets carries `final: Option<Pred>`; both compositions copy it (6.1, 6.5 step 6; design §3 amendment 16.6). — Without it recheck::compose cannot rebuild the `final` encoding line, so every S4 deadlock-free check with a final predicate would end as InternalDisagreement or force recheck to read engine's net, which ADR 0010 forbids.
- Budget accounting is normative: stored = |R ∪ O| with M₀ = 1; every insertion into R or O is checked; a marking that does not fit is neither stored nor tested; a phase with max m completes iff m ≥ |R ∪ O|; violations found between polls are still Disproved; replay never exhausts (10.1, 12, Appendix A). — Three reviewers found the draft's pseudocode, text and budget vectors inconsistent; the vectors B1–B12 now pin both sides of every boundary and were recomputed (PC(overflow) overflow marking is the 9th stored marking, PC(block) deadlock the 18th).
- Recheck can never run out of markings while verify has no reductions; BudgetExhausted { Recheck } is tested with a fake Clock (B9). — N − ⌊N/2⌋ ≥ ⌊N/2⌋ ≥ |R ∪ O| and both explorers store the same set; the draft's 'recheck has 10' vector was impossible.
- Predicate lexer: IDs are maximal runs of [A-Za-z_][A-Za-z0-9_/-]*, so a `-` directly after an ID character is part of the ID; `and`/`or`/`not` are reserved; slugs start with a letter or `_`; no unary minus; i32 overflow while merging is a parse error; atoms with no terms are allowed; the normalized form is Σ(aᵢ − bᵢ)·pᵢ cmp (d − c) (5.3, 2.2). — The draft's grammar tokenized legal IDs two ways, which could silently turn the user's text into a different property; maximal munch plus an unknown-place error is deterministic and loud.
- A relationship contributes to a combined scope only if both its elements are children; a transition port bound only from outside fails L4 instead of being closed; ignored relationships are listed in `Lowered.assumptions`, shown with every verdict and excluded from the CheckKey (6.6). — Closing such a port would add free behavior and could hide a deadlock or satisfy a predicate: a wrong Proved shared by both explorers because lowering is shared.
- New lowering rules: L11 (caller in the relationship's source element, callee in its target; same for async from/to), L12 (a (caller, callee) pair at most once per relationship), L13 (asynchronous binding needs a capacity); AsyncLink.when_full defaults to overflow and lowering fills it in (6.4, 6.6). — Without L11/L12 two fusions in opposite directions on one relationship produce the same fused ID `r/x+y`; the default and the missing-capacity rule were required by the brief and ADR 0014 but absent from the draft.
- Places and transitions of one element share one namespace; every part is validated (2.2, 2.3, L10); E5 case 1's transitions `ret_a`/`ret_b` are renamed `return_a`/`return_b` in the worked example, and the correct place counts are 17 (bad) and 20 (fixed). — E5 had a place and a transition both named `control_plane/ret_a`, which passed only because the transition was fused away; one namespace keeps replay text unambiguous.
- Validation rule 7: cap(p) + max_t W⁺(t, p) ≤ u32::MAX; explorers use checked arithmetic and map None to InternalError; vectors V51–V54 sit at the limit. — A tentative count can reach cap + W⁺; a wrapped count would look in bounds and both explorers could agree on a wrong Proved for 'no capacity exceeded'.
- `Violation::Deadlock.waiting` carries a WaitReason per place (NeedsTokens or OutputFull); replay compares entry for entry; CapacityExceededFirst names the smallest-ID exceeded place of the first overflow marking in discovery order and carries the run to it, replayed by recheck. — Without the reason V24's `c/fail ← c/idle` reads like a missing token; without a deterministic place and a replayable run the Unknown is neither testable nor actionable (I3).
- 'No capacity exceeded' on a net with no `overflow` place is Proved structurally (Technique::Structural, markings 0) with the drop places named in the verdict text; recheck confirms by inspecting its own composition. — The property holds by construction (3.2); exploring it could only yield a spurious 'budget exhausted', and naming the drop places makes the vacuity ADR 0014 worried about visible. Reversible; open question 8.
- Agreement is symmetric for Disproved evidence (`markings` compared for Exhaustive and CounterexampleThenExhaustive, the latter defined as |Reach(last marking)|); a recheck Unknown CapacityExceededFirst or Disproved against a verify Proved is InternalDisagreement; an evidence kind that does not match the property kind is InternalError (9.1, 9.4). — The draft's '(budget, cancel)' parenthetical read as if every recheck Unknown were exempt, which would let verify miss an overflow silently.
- Unknown precedence: the reason is the event that ended the pipeline; InternalDisagreement and InternalError win the moment they are detected; Cancelled beats BudgetExhausted at the same poll (10.2). — A failed replay followed by the deadline passing must not be logged as 'budget exhausted'; the bug signal of ADR 0008/0010 depends on it.
- Every property has a normative 'Proved means' line; deadlock-free is explicitly global ('never a complete stop; parts can still be stuck, which always reachable catches'); 'always reachable' is worded 'can always get back to', never 'recovers'; own-scope verdicts state 'every port can fire at any time' (8, 9.6; vectors V43, V44). — A masked deadlock (LOCKS(yx) plus a heartbeat) is Proved deadlock-free by ADR 0010's definition; the user must read the verdict correctly (north-star non-goal, E5 implication 5).
- Section 16 lists every deviation as a proposed amendment with its replacement sentence (ADR 0010 ×3, ADR 0003, design §3 ×3, design §6), plus two decisions that need no ADR; the draft's 'No ADR is contradicted' is withdrawn. — The brief requires deviations to be stated as proposed ADR changes so both crates are built against one agreed text.
- Composition vectors C1–C16 with exact canonical encodings (from the reference implementation) and ComposeError cases for L6, L7, L8, L12, L13, L4, a relationship that binds nothing, and the final predicate. — ADR 0010 requires a golden test per composition rule in both crates; the draft's proptest only checked that the two implementations agree, not that either is right.
- Certificates (9.5): 'Proved if' (sufficient conditions); the exact never-p atom shapes a certificate may prove (single atom, coefficients ≥ 1, ge/gt only); Proved by certificate carries the certificate and reports markings 0. — 'Derived in the obvious way' cannot be implemented twice identically; the shapes must be enumerated before verify may emit a certificate.
- Canonical encoding: every line including the last ends in LF; pre lines precede post lines; a transition without arcs is its header line alone; no indentation; zero-term atoms encode as `(atom <cmp> <constant>)`. — Otherwise `canonical(flat) ++ canonical_property(p)` could glue `final none` onto `property …` and two correct implementations could differ by bytes.
- Cross-references fixed (V17/V25 for 'Disproved despite O ≠ ∅', V34 for 'not evaluated on overflow markings', V46 for the Dead ≠ ∅ with O ≠ ∅ case, V10/V47 for zero-step counterexamples); V13 and V24 give full waiting payloads; V28 expects exactly two detail lines in a fixed order using IDs. — Replay compares `waiting` against waits(M, t) for every t, so partial payloads are not a test; the old references pointed at vectors that did not exercise the rule.
- Slice-0 verdicts of the E5 fixes are stated: case 1 fixed P1 is Disproved in 13 steps and case 2 fixed P3 in 9 steps with F = none (V49, V50); every worked result carries its slice tag; the question whether a minimal final predicate moves into slice 0 is escalated. — Recomputed under the spec; slice 0 can show the defects but not that the fixes work, which breaks J3 unless finals come forward. The decision is a product scope question.
- Glossary hygiene: 'run' replaces 'firing sequence', 'reachable markings' and 'marking count' replace 'state space' and 'state count', 'violation marking' replaces 'terminal violation state', 'asynchronous binding' is used in prose for AsyncLink; the glossary's Unknown example 'no counterexample up to depth 40' is replaced; section 17 lists the additions as GLOSSARY.md edits. — The draft used several words on GLOSSARY.md avoid lists and pointed to a workflow artifact instead of the repo.

## Proposed glossary changes

- **Reachable marking**: A marking the net can reach from its initial marking by firing transitions without passing through an overflow marking. The count of reachable markings is what a Proved by exhaustion reports. _Avoid_: state, state space, state count
- **Overflow marking**: A marking in which a place holds more tokens than its capacity. It is reached by exactly one firing into an overflow place from an in-bounds marking, violates 'no capacity exceeded', and nothing happens after it: it is neither a deadlock nor final. _Avoid_: error state, bad marking, terminal state
- **Run**: A sequence of firings from one marking to another; the formal object inside a counterexample. _Avoid_: firing sequence, trace, path
- **Qualified ID**: The string that names one place or transition of a flattened net: element/name for an element's own, relationship/caller+callee for a fused transition, relationship for a generated place. Places and transitions of one element share one namespace. _Avoid_: path, key, address
- **Fused transition**: The one transition a synchronous binding makes from a caller transition and a callee transition; the two bound ports no longer fire on their own. _Avoid_: merged transition, joint step, synchronized transition
- **Transition port / place port**: A transition port is bound by relationships; a place port is never bound in v1 and exists so that a property of the parent scope can name it. _Avoid_: input/output port, event port
- **Final predicate**: The linear marking predicate of a scope that says which markings count as proper termination. _Avoid_: final state, goal, accept condition
- **Dead transition**: A transition that is enabled in no reachable marking. _Avoid_: unreachable transition, unused transition
- **Unknown**: The tool could not decide the property. An Unknown verdict always carries a reason, for example 'budget exhausted', 'capacity exceeded first', 'model incomplete', 'cancelled' or 'internal error'. (Replaces the example 'no counterexample up to depth 40', which is not a reason this tool produces.) _Avoid_: inconclusive, open, partial, bounded-proved
- **Assumption**: A relationship of a scope that takes no part in a check because it binds no ports or leads outside the scope; every verdict of the scope lists them. _Avoid_: ignored relationship, exclusion
- **Canonical encoding**: The sorted text form of a flattened net and a property from which the CheckKey is computed; two nets with the same behavior-relevant data encode to the same bytes. _Avoid_: serialization, hash input, fingerprint
- **CheckKey**: The hash of the canonical encoding of a net plus a property; the identity of a check for caching and for deciding whether a verdict is current. _Avoid_: check hash, cache key, verdict ID
- **Step**: One fired transition of the flattened net together with the marking after it; a counterexample is a list of steps. _Avoid_: frame (reserved for the rendered replay), move, event
