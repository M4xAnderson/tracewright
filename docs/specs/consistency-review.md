## Glossary changes (merged)

- **Reachable marking**: A marking the net can reach from its initial marking by firing transitions without passing through an overflow marking. The count of reachable markings is what a Proved by exhaustion reports. _Avoid_: state, state space, state count
- **Overflow marking**: A marking in which a place holds more tokens than its capacity. It is reached by exactly one firing into an overflow place from an in-bounds marking, violates 'no capacity exceeded', and nothing happens after it: it is neither a deadlock nor final. _Avoid_: error state, bad marking, terminal state CONFLICT: NS adds 'no property other than no capacity exceeded looks at its counts'; PL A4 (if OQ2 = evaluate) adds 'and never p'. Fix the sentence after OQ2.
- **Run**: A sequence of firings from one marking to another; the formal object inside a counterexample. Not every run is a counterexample. _Avoid_: firing sequence, trace, path CONFLICT: The catalog's Step entry lists 'Firing' under Avoid; this entry and NS §1 use 'firing' as the formal act. Drop 'Firing' from the Step avoid list.
- **Qualified ID**: The string that names one place or transition of a flattened net: element/name for an element's own place, transition or state, relationship/caller+callee (bare names) for a fused transition, relationship for a generated place. Places, transitions, states and events of one element share one namespace. _Avoid_: path, key, address CONFLICT: Catalog §12.1 proposes element/state:<name>; rejected by PL, SM and the file format (one namespace, ':' is not in the slug alphabet).
- **Fused transition**: The one transition a synchronous binding makes from a caller transition and a callee transition; the two bound ports no longer fire on their own. _Avoid_: merged transition, joint step, synchronized transition
- **Port**: A place or transition that a behavior model offers to the outside. A transition port is what relationships bind; a place port is never bound in v1 and exists so that a property of the parent scope can name it. For a state machine, an input or output event is a transition port standing for every transition on it, and every state is a place port; internal events are not ports. Relationships connect to ports, never to the inside of another element's behavior model. _Avoid_: interface, pin, endpoint, hook, input/output port, event port CONFLICT: Merges NS 'Transition port / place port' and SM 'Port (sharpened)'. States as place ports depend on SM OQ2 / the L9 decision.
- **Binding**: One pair of ports that a relationship connects: synchronous (the two transitions fire as one fused transition) or asynchronous (messages wait in the relationship's generated place). A relationship holds zero or more bindings, at most one of them asynchronous. _Avoid_: link, wire, connection, port mapping CONFLICT: Code and NS keep the names links and AsyncLink (design §3); the glossary avoids 'link'. Either rename the field or state that AsyncLink is the code name of an asynchronous binding.
- **Final predicate**: The linear marking predicate of a scope (one for its own behavior, one for its combined behavior) that says which markings count as proper termination; a marking without enabled transitions that satisfies it is not a deadlock. The UI calls it 'done when'; a state machine's final states contribute to it. Overflow markings are never final. _Avoid_: final state, final markings (as a list), final condition, end state, goal, accept condition, exit condition, done condition CONFLICT: Merges NS 'Final predicate', PL 'Final predicate', catalog 'Done when' (which says 'one per scope'; PL and the file format store own and combined) and the glossary's existing 'final markings' under Marking. Where it lives (net vs deadlock-free property) is OQ7.
- **Dead transition**: A transition that is enabled in no reachable marking. _Avoid_: unreachable transition, unused transition
- **Linear marking predicate**: A statement about one marking: sums of token counts with whole-number weights (negative allowed), compared with whole numbers and combined with and, or and not, for example billing/inflight + shipping/inflight > 2. Short form: predicate. User properties and final predicates are written as predicates. _Avoid_: condition, formula, query, expression, constraint, guard
- **Own scope / combined scope**: The two kinds of behavior a property of a scope element can be about. Own scope: the element's own behavior model, with its ports firing freely. Combined scope: the behavior of the children in its view (the elements whose parent it is), combined through their bindings. The file stores this as behavior = "own" | "combined". _Avoid_: scope kind, local scope, system scope, level scope
- **Step**: One fired transition of the flattened net together with the marking after it; a counterexample is a list of steps from the initial marking. _Avoid_: frame (reserved for the rendered replay), move, tick, event CONFLICT: NS and catalog definitions merged; the catalog's 'Firing' avoid word is dropped because Run and NS use 'firing' as the formal act.
- **Event**: Something that makes a state machine take a transition. Every event has a direction: input, output or internal. _Avoid_: signal, message (for the event itself), trigger
- **Input event**: An event that something outside the element causes: a call the element accepts or a message it receives. A transition port. _Avoid_: inbound port, receive event
- **Output event**: An event by which the element calls something or sends a message. A transition port. _Avoid_: outbound port, send event
- **Internal event**: An event that happens inside the element without a partner, for example a timeout or a failure. Not a port. _Avoid_: private event, spontaneous transition
- **Initial state**: The one state a state machine is in before anything happens. _Avoid_: start state, default state
- **Final state**: A state in which stopping counts as proper termination; it becomes part of the scope's final predicate once final predicates exist. _Avoid_: end state, accepting state
- **Active state**: The state a state machine is in at one moment; replay shows it per step. _Avoid_: current state, mode
- **State machine transition**: A step from one state to another on one event. It becomes one or more net transitions when the state machine is compiled (one per partner in a synchronous binding). _Avoid_: edge, arc
- **Unknown**: The tool could not decide the property. An Unknown verdict always carries a reason from a closed list: budget exhausted, budget exhausted while re-checking, capacity exceeded first, model incomplete, property cannot be checked, cancelled, internal error or internal disagreement. _Avoid_: inconclusive, open, partial, bounded-proved CONFLICT: Replaces the example 'no counterexample up to depth 40', which CODING_STANDARDS VER-3 and catalog W7 still allow; 'property cannot be checked' depends on PL OQ6.
- **Disproved**: The property does not hold. The tool has either a counterexample that shows it or, for no dead transitions, an exhaustive exploration that the second explorer confirmed. _Avoid_: refuted, failed, violated CONFLICT: Also changes the Relationships line 'Only a Disproved verdict has a counterexample' and UX_STANDARDS VRD-2.
- **Assumption**: A relationship of a scope that takes no part in a check because it binds no ports or leads outside the scope; every verdict of the scope lists them. _Avoid_: ignored relationship, exclusion CONFLICT: The catalog uses 'assumption' for a template precondition (T3) and NS §9.6 for the own-scope 'every port can fire' line; the [assumption] document tag is a third sense. Rename the own-scope line to 'closed-port note' or similar, or widen this entry.
- **Canonical encoding**: The sorted text form of a flattened net and a property from which the CheckKey is computed; two nets with the same behavior-relevant data encode to the same bytes. _Avoid_: serialization, hash input, fingerprint
- **CheckKey**: The hash of the canonical encoding of a net plus a property; the identity of a check for caching and for deciding whether a verdict is current. _Avoid_: check hash, cache key, verdict ID
- **Property template**: A named sentence with blanks that the user fills in to state a property without writing a predicate, for example 'Never holds the whole pool'. Filled in, it expands to exactly one property and adds no meaning of its own; the tool expands it again from the current model at every check, so values such as a capacity follow edits. A preset is one fixed choice inside a template. _Avoid_: pattern, query, formula, macro, snippet, rule CONFLICT: Research §6.1 defines a template as one or more properties with a display summary; the catalog avoids 'Preset' while the catalog and PL define presets. This merged entry follows catalog/PL cardinality and keeps 'preset' as a sub-term.
- **Pool**: A place whose tokens stand for interchangeable resources that steps take and give back, such as threads, connections or permits. It usually starts full. _Avoid_: semaphore, resource place, free list
- **Held by**: The places that count as one holder's share of a pool in a 'never holds the whole pool' property. Tokens in other places are not counted. _Avoid_: owned by, allocated to, in use by
- **Entity**: One stored thing that the tool saves, journals and compares as a whole: an element, its behavior model, a relationship with its bindings, a property, a final predicate, a layout entry or a suppression. Reload conflicts are reported per entity. _Avoid_: record, object, item, row
- **Format version**: The integer format at the top of every project file. It says which version of the file format the file follows; older files are migrated when they are read and upgraded when they are saved. _Avoid_: schema version, file version, project version CONFLICT: design §3 has one Model.version; the file format makes it per file (A5).
- **Recovery journal**: The app's own log of unsaved changes, kept in the app data folder and never in the project, from which those changes can be restored after a crash. _Avoid_: autosave, backup, undo log, history
- **Not checkable**: Said of a rule that could not be applied to a subject (an element, a relationship, a set of elements or the whole model) because the model lacks the data it needs, for example a timeout that is not stated. Each case is a Not checkable entry that names the missing data. _Avoid_: Unknown (reserved for verdicts), n/a, skipped, open
- **Suppression**: The user's decision about a finding, with a written reason and a disposition: accepted (the finding is real and the user accepts it) or not real (the rule is wrong here). A suppressed finding stays visible as suppressed. _Avoid_: ignore, waiver, exception, baseline
- **Not stated**: The value of an attribute that the model does not give. A rule never treats it as yes, no or a number; it leads to Not checkable when stating it could change the outcome. _Avoid_: unknown, null, default, n/a CONFLICT: v1-slices slice 5 and the current 'Not checkable' example say 'unknown'.
- **Interaction**: Whether the dependent end of a relationship waits for the other end's answer before it goes on: synchronous or asynchronous. Stated by the user; port bindings never set it. _Avoid_: sync flag, call type, mode CONFLICT: Binding mode uses the words sync/async for a different concept (file format §6.7); note both in the entry.
- **Timeout**: A relationship attribute: the dependent end gives up waiting after a set time, on both connection and request. It is not the Budget of a check and not a state machine's internal 'timeout' event. _Avoid_: deadline, Budget
- **Runtime unit**: An element that runs or stores data on its own: a Container, Database, Queue, or a Software System without children. Components and code elements run inside their container. _Avoid_: process, deployable, node, service
- **Example cycle**: The one shortest cycle that a cycle finding shows, step by step, with the relationship behind each step. _Avoid_: witness, trace, path
- **Severity**: How serious a finding is: High or Medium. _Avoid_: level (a C4 level), priority, error/warning
- **Service (attribute)**: The name of the service a Container belongs to; containers of one Software System with the same service count as one service. _Avoid_: owner, team
- **Observer place (after v1, not for the v1 glossary)**: A place the tool adds to a checked net to record history for one property, for example how often a transition fired. It never blocks a transition and discards tokens when full. _Avoid_: monitor, ghost place, history variable, spec machine CONFLICT: Research only; add when F6 is scheduled.
- **Example (only if a 'can reach' kind is adopted after v1)**: A sequence of steps from the start that ends in a marking a 'can reach' property asks for. _Avoid_: witness, trace, scenario, run CONFLICT: Research F4 (iii) only; it would also change Proved, Disproved, Evidence, Replay and the counterexample Relationships line. Do not add for v1.
