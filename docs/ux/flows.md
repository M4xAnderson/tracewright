# UX flows

As of 2026-11-02. Owner: senior UX designer. Status: revision 2, after review by the product manager and the senior frontend developer; for the product owner. Copy aligned with `docs/specs/decisions.md` D-08, D-23, D-34, D-56 and D-57 on 2026-11-02. Inputs: the UX scope brief for slices 0–2 (revision 2), `GLOSSARY.md`, `UX_STANDARDS.md`, `docs/design/design.md`, ADRs 0001, 0002, 0005–0014, `docs/product/v1-slices.md`, `north-star.md`, `opportunity-solution-tree.md`, `experiments/e5-paper-test.md` and `docs/research/stack.md` §6.

This file says how the UI works: regions, flows, states, copy, commands, keys and accessibility acceptance criteria. `UX_STANDARDS.md` is still the review rulebook, `GLOSSARY.md` decides the terms, and the scope brief decides what is in each slice. Where this file differs from the brief, §11 lists the difference and the reason, and the product owner decides. §9 lists what the UI needs from the IPC contract. Items marked **blocking** must be answered before slice 0 starts.

**Tags**
- **[S0]**, **[S1]** … **[S5]**: the slice that ships the element. An untagged item takes the tag of its section.
- Slices 0–2 are specified in full, ready to build. Slices 3–5 are **outlines with draft copy**: they fix only what keeps today's regions, keys and copy compatible, and they get a full pass before their slice starts. A surface tagged S3 or later (Model tree, breadcrumb, Findings tab, Add property) is **not rendered at all** before its slice, not even disabled.
- **[proposal]**, **[assumption]** and **[route: X]** mean what they mean in the brief. **[contract Rn]** points to §9.
- Copy IDs such as `V-DIS-1` point to the copy catalog in §5. Strings tagged S0–S2 are final US English. Strings tagged S3–S5 are **draft** and are excluded from the S0–S2 copy lint. Placeholders are in angle brackets: `<path>`, `<n>`, `<cause>`.

**Naming rules for copy**
- A relationship is always written "From → To (meaning)", for example "Order API → Billing (calls)".
- A place or transition inside another element's behavior model is written "Element: name", for example "Billing: lock_b".
- A generated place is written as its relationship, and its tokens are "messages".
- Names are resolved from the projection at render time. The UI never shows an ID such as `Billing/take_lock`.
- Numbers use thousands separators ("1,970"). Durations use "0.4 s" under a minute and "1:12" from one minute up.
- The word "state" never refers to a Petri net. Say "marking" (GLOSSARY). "State" is only for state machines [S2].

**What we take:** a model-first approach with a right-hand inspector; replay on the architecture with a full step list, random access, arrow keys and a scrubber; a per-step "what changed" in text; names, never IDs; a read-only replay.

**What we reject:** presentation-style playback, information available only on hover, color-only state, and any motion during replay.

**Not verified:** how IcePanel's zoom between levels behaves in detail. Its docs do not describe it, so slice 3 does not copy it.

### 2.3 Sizes and how the window adapts

All sizes are CSS px. UI zoom (§6.2) divides the window size: 1440 × 900 at 125 % is 1152 × 720 CSS px, which is above the minimum.

| Region | 1440 × 900 (default) | 1024 × 640 (min) | Rules |
|---|---|---|---|
| Header | 44 | 44 | One row. Collapse order in §2.5. |
| Status bar | 24 | 24 | Always visible. Never overlays content. |
| Right column | 360 (resizable 300–480) | 320 | Collapses to 0 with a visible "Show inspector" button at the right edge of the canvas, and Ctrl+Alt+B. The width is remembered. |
| Canvas | the rest | ≥ 512 wide, ≥ 240 tall | Never below 50 % of the window width (WIN-1). Dragging a pane edge stops at the canvas minimum. |
| Bottom pane | 280 (min 160) | Starts collapsed to its 32 px tab strip when the window is under 700 tall. When opened: 240 | The strip stays one action away: a tab click or Ctrl+J opens it. **Replay always opens it**, whatever the height. |
| Model tree [S3] | 260, docked when the window is ≥ 1280 wide | Overlay drawer over the canvas; closes on Escape or after choosing an element | Docked tree plus right column would leave the canvas below 50 % at 1024. |
| Replay bar | 36 above the canvas, only during replay | 36 | Holds the step controls next to the highlights. |

**Height check at 1024 × 640 during replay:** 640 − 44 − 24 = 572 of working height. The bottom pane takes 240 and the replay bar 36, which leaves 296 of canvas. The step list gets the full 572 of the right column. So the canvas, the step list and the behavior model pane are visible together without scrolling the window. Capture `replay__min` shows this.

**Below the minimum** (only reachable with UI zoom above 125 % or a smaller window): no layout is specified for S0. The rule is: no clipped text, and every command reachable through the palette (AC-14b). A dedicated below-min layout is an open question (§13).

### 2.4 Regions and focus order

- Every region is a labeled landmark (`role=region`, `aria-label`): "Header", "Model tree" [S3], "Canvas", "Bottom pane: Behavior model" (the label names the open tab), "Inspector" or "Verdicts", "Messages".
- **F6** and **Shift+F6** cycle focus through the regions in visual order: Header → Model tree [S3] → Canvas → Bottom pane → Right column → Messages. Messages is in the cycle only while it holds an action such as "Copy details". Focus lands on the region's last-focused item, or on its first item.
- **Canvas tab ring (app-managed):** Tab and Shift+Tab move between elements in reading order, computed from committed positions (not drag overlays): rows top to bottom, left to right within a row. The app moves focus by element ID, so elements outside the viewport are reachable even when React Flow renders only visible nodes, and the canvas pans to the focused element instantly. Relationships are not tab stops: they are reached through the element inspector's Relationships list or "Go to relationship…" (Ctrl+Shift+O). Tab after the last element leaves the canvas. F6 is the way out of a view with 300 elements.

### 2.5 Header [S0 unless marked]

Left to right:
1. **Project name and save state.**
   - Clean: no marker.
   - `savedRev ≠ rev`: a dot icon plus "Unsaved changes" (at widths under 1280: "Unsaved"). There is always text, never a dot alone.
   - While a Save runs: "Saving…" instead. It appears if the Save takes longer than 200 ms and then stays for at least 500 ms.
2. **View title and level.** "Order platform · Level: Container". The view title is the scope element's name, the same name the verdict rows use. From S3 the breadcrumb (§4.12) replaces it.
3. **Undo and Redo [S1].** Icon buttons with the accessible names "Undo" and "Redo" and a tooltip with the shortcut on hover and focus. Disabled when `canUndo`/`canRedo` is false. If [contract R14] lands, the names become "Undo rename Billing".
4. **Save** (Ctrl+S), **Reload** (Ctrl+R), **Check** (Ctrl+Enter). Check is the only primary button in the header. While checks run it reads "Checking…" with a spinner and stays focusable; [S1] adds an icon button "Cancel all checks" next to it.
5. **Collapsed-region summary.** Visible only while the right column or the bottom pane is collapsed. It uses the same selector as every other verdict surface (§3.1) and **counts only current verdicts**:
   - Counts in a fixed order, each with its icon: Disproved, Unknown, Stale [S1], Proved. Example: "1 Disproved, 1 Stale, 1 Proved".
   - A stale verdict is never counted as Proved, Disproved or Unknown. It counts only as "Stale".
   - While any verdict is pending for longer than 1 s: "Updating checks…". Before that, the chip keeps its space and shows a neutral placeholder.
   - While a check runs: "Checking…".
   - With nothing to check: no verdict chip.
   - Problems: "2 problems" with an icon.
   - Choosing a chip opens the region and its tab.
6. **Commands.** A button "Commands" with "Ctrl+K", which opens the command palette.

**Collapse order when the header is too narrow** (applied in this order, at 1024 and at UI zoom):
1. "Commands" becomes an icon button (accessible name "Commands", tooltip "Commands (Ctrl+K)").
2. Save and Reload become icon buttons (lucide `save`, `refresh-cw`) with accessible names and tooltips on hover and focus. The palette lists both (WIN-3 holds).
3. Summary chips become icon plus count, with the full text as the accessible name and the tooltip ("1 Disproved, 1 Proved").
4. The view title truncates (minimum 80), then the project name (minimum 96). The full text is the accessible name and is in the window title.
5. **Never collapsed:** Check (with its text), the unsaved text, the level.

Width estimate for the full S1 content at 1024: about 960, so it fits after steps 1–3. Capture `header__summary__min` with the right column collapsed, and [S3] `header__long-breadcrumb__min`.

### 2.6 Status bar [S0]

- **Left: the latest message**, with an icon by kind (info, success of an action, error). It stays until the next message replaces it, so reading it never depends on timing. Inline actions sit with the message: "Copy details", "Open log folder", "Show problems". An identical message that repeats is announced again (the region is cleared, then set).
- **Right: background activity.** "Checking 2 properties…" [S0], "Restoring changes…" [S1], "Scanning…" [S5]. This part is not live: activity is never announced.
- **Announced (polite):** Save and Reload outcomes, final current verdicts, replay closed, internal errors, rejected edits, disk adoptions [S1], undo and redo [S1].
- **Never announced:** pending re-evaluation, progress ticks, "Laying out…", a verdict becoming stale.
- If several final verdicts arrive within 500 ms, they are combined: "Checks finished: Deadlock-free Disproved, No capacity exceeded Proved."

### 2.7 Command palette [S0]

- Opens with Ctrl+K or Ctrl+Shift+P, built on shadcn `<Command>` (cmdk).
- Groups: Project, Edit, Navigate, Check, Replay, View.
- Each row shows the command name (verb + object), its shortcut, and nothing else.
- Commands that do not apply in the current mode are hidden. Exception: during replay, the edit commands (including Undo and Redo [S1]) are listed, disabled, under the group "Exit replay to edit".
- The full command catalog is §6.1; the keyboard map is §6.2.

## 3. Global rules

### 3.1 One verdict selector [S0]

Every surface that shows a verdict uses one selector: the Verdict panel, the header summary, the nothing-selected inspector, the "Replay counterexample" palette commands and the status announcements.

```
verdictView(p) =
  !keysFresh  (currentKeys.rev !== projection.rev)       → pending
  keys[p] is { nothingToCheck }                          → no-behavior        [contract R9]
  keys[p] is { unknown }                                 → unknown(reason)    (no check runs)
  running[keys[p].key]                                   → running
  verdicts[p]?.key === keys[p].key                       → proved | disproved | unknown
  keys[p].cached                                         → proved | disproved (cache hit; S1: undo restore, ADR 0013)
  verdicts[p] exists, key differs                        → S0: no-verdict ("Behavior changed since the last check.")
                                                           S1+: stale(previous verdict)
  otherwise                                              → no-verdict ("Not checked yet.")
```

- `pending` comes first, so no other branch, including no-behavior, can render from keys that belong to another revision.
- A verdict is never rendered as current while keys are not fresh (design §4). Unknown is never rendered with a success color or a check mark (VRD-1).
- Stale is a separate result. Every consumer (summary counts, announcements, the inspector) treats it as "not current": it is never counted, announced or styled as a current verdict.

### 3.2 Modes

| Mode | Entered by | What changes | Left by |
|---|---|---|---|
| Edit | default | Everything is editable | — |
| Replay [S0] | "Replay counterexample" | Canvas, inspector and [S1] the net editor are read-only. Undo and Redo [S1] are disabled. Arrow keys step the replay. The replay bar is shown. | "Exit replay", Escape, or any model change that did not come from the user in replay (Reload, disk adoption [S1]) |
| Modal dialog | Quit, close project, delete, conflicts, restore [S1] | Focus is trapped in the dialog. The rest of the window is inert. | A dialog button, or Escape, where Escape is the safe option |

### 3.3 Timing

| Event | Feedback |
|---|---|
| Any click or key | Visible within 100 ms. Drag and rename keep a local overlay until `Applied` arrives (design §4). |
| A pending verdict | The verdict slot shows a neutral placeholder from 150 ms on (not before, so a fast layout-only edit does not blink). "Updating checks…" after 1 s. |
| Behavior layout longer than 300 ms | "Laying out…" in the behavior model pane |
| Save longer than 200 ms | "Saving…" in the header, shown for at least 500 ms |
| Check progress | At most 4 updates per second (design §5). The text updates; nothing is announced. |
| Opening a project longer than 500 ms | A loading screen with an indeterminate progress bar |

## 4. Flows

Each flow lists the job, the steps with their branches, and its states. Every branch ends in success or in an error the user can recover from.

### 4.1 Create, open, switch and close a project [S0]

**Job.** When I start modeling a design or come back to one, I want to get to its canvas in one or two actions, so I can work instead of setting up.

**From the start screen:**
1. The start screen shows the app name and two actions: **Open project** (primary, Ctrl+O), because opening is the daily action, and **New project** (Ctrl+N). Nothing else.
2. **New project** opens the native folder dialog ("Choose an empty folder for the new project").
   - Empty folder: the app writes `arch.toml` and the software system file at once **[contract R16]**, so the folder is a project immediately and the state is clean. The software system is named after the folder ("order-platform" → "order-platform"; rename it in the nothing-selected inspector, §4.3). The canvas opens empty. Status `P-NEW-OK`.
   - Folder not empty: `P-NEW-ERR-NOTEMPTY` inline on the start screen. The folder dialog does not reopen by itself.
   - Write fails: `P-NEW-ERR`.
   - Folder dialog cancelled: back where the user was, no message.
3. **Open project** opens the folder dialog.
   - Loading: the full window shows the project name, "Opening <name>…" and an indeterminate progress bar. The canvas never shows a half-loaded model.
   - Success: the canvas opens on the Container view. Every property is queued for a check (ADR 0005); rows go from pending to running to verdicts.
   - Loads with problems: the project opens, the bottom pane opens on Problems, status `P-OPEN-PROBLEMS`.
   - Errors: `P-OPEN-ERR-NOTPROJECT`, `P-OPEN-ERR-NEWER`, `P-OPEN-ERR-PERM`, `P-OPEN-ERR`, inline on the start screen. The project does not open.
   - The chosen folder is the project that is already open: nothing reloads, status `P-OPEN-SAME`.
4. **Restore offer [S1]** runs between step 3 and the canvas (§4.2).

**With a project already open** (one window; multiple windows are a non-goal):
- "Open project…", "New project…" and "Close project" are in the palette (§6.1); Ctrl+O and Ctrl+N work everywhere.
- The folder dialog comes first, so cancelling it costs nothing. Then, if `savedRev ≠ rev`, the dialog `D-CLOSE` asks before the current project closes:
  - "Save and close" (primary): Save runs. On success the other project opens (or the start screen shows, for Close project). On a conflict, the conflict dialog opens and the switch stops; on a failure, `D-CLOSE-FAIL` shows inline and the switch stops. The current project stays open in both cases.
  - "Close without saving" (destructive style, set apart from the primary button).
  - "Cancel" (Escape, default focus): nothing changes.
- A clean project closes without a prompt.
- An error opening the other project happens after the current project closed: the start screen shows the error inline, and Open project there offers the folder again.

| State | Content | Actions |
|---|---|---|
| empty | App name, two actions | Open project, New project |
| loading | Project name, "Opening <name>…", indeterminate bar | none |
| error | Error text from §5 above the actions; the path middle-truncated, full path selectable | Open project, New project |
| long text | A long path is middle-truncated ("~/designs/…/order-platform"). The full path is the accessible name and can be copied. | — |

### 4.2 Restore unsaved changes [S1]

**Job.** When the app died with unsaved work, I want it back without risking my files on disk, so I lose nothing.

1. On open, if the journal has records past its base and the base hashes match the disk (design §4), a modal dialog appears before the canvas: `D-RESTORE`.
   - "Restore <n> unsaved changes" (primary): the changes are applied. Status "Restored <n> unsaved changes." The unsaved marker is visible. (`<n>` needs [contract R13]; without it the button reads "Restore unsaved changes".)
   - "Open without restoring": the journal is set aside and the project opens as it is on disk. Status `D-RESTORE-ASIDE`.
2. **The app died during a restore:** the journal has the `.restoring` name, so only "Open without restoring" is offered, with `D-RESTORE-CRASHED`.
3. **Base hashes do not match** (the files changed since the crash): no offer. The journal is set aside and the status bar shows `D-RESTORE-MISMATCH`.

Escape means "Open without restoring", which is safe because the journal is kept, not deleted.

### 4.3 Edit the architecture on the canvas, and the inspector [S0]

**Job.** When I sketch a design of about 10 elements, I want to add, connect, rename and arrange them as fast as I think, by mouse or keyboard, so modeling stays under 45 min (E6).

S0–S2 support a single selection: one element or one relationship.

**Create an element:**
- Press N with the canvas focused, choose "Add element…" in the palette, or use the empty-state button.
- A kind combobox opens: Container (default), Database, Queue.
- The element goes to the next free grid slot near the viewport center. Its name is in rename mode with "New container" selected. Enter commits; Escape keeps the default name.

**Elements that arrive through Reload** without a layout entry are placed by ELK. Only unplaced elements are placed; nothing that already has a position moves. Because the new position is written at the next Save, the unsaved marker appears. Status `S-RELOAD-OK` names them.

**Connect two elements:**
- With the source selected, press R, choose "Add relationship…" in the palette, or "Add relationship…" in the inspector.
- A target combobox lists the elements in the view; then a meaning combobox with suggestions ("calls", "publishes to", "reads from", "writes to") or free text.
- The new relationship is selected, so the inspector shows port binding next (§4.4).
- Mouse: drag from the element's border handle to another element.

**Rename:** F2, or the name field in the inspector. The canvas truncates long names after two lines with an ellipsis. The inspector, the accessible name and the step texts always show the full name.

**Move:** arrow keys move the selected element one grid step; Shift+arrow moves four. The app handles the keys itself and sends `apply(MoveElements)`; React Flow's built-in keyboard move is off. Mouse drag works too. A move is layout-only, so verdicts stay current (see §3.3 and [contract R12]).

**Delete:**
- Delete or Backspace with an element or relationship selected.
- An element with a behavior model asks first (`D-DELETE`), because S0 has no undo. Other elements and relationships are deleted at once; status `S-DELETED`.
- **[S1]:** no confirmation; status `S-DELETED-UNDO`.

**Several relationships between the same pair** are drawn with an offset, each with its own label. The element inspector lists all of them.

**Port handles:** each port is a visible handle on the element border: 12 px drawn, with a 24 × 24 px hit area at canvas zoom 100 %. Port names show next to the handles when the element is selected or the canvas zoom is ≥ 100 % (one class on the canvas wrapper, not a per-element zoom subscription). A relationship bound to a port attaches to its handle; an unbound one attaches to the border.

**Badges on an element** (icon plus text, never color alone): "No behavior model"; "File has an error"; [S2] the active state during replay.

**Relationship labels:** synchronous: the meaning. Asynchronous: the meaning plus a chip "capacity 3 · overflow". A dangling relationship has an open, dashed end and an error badge.

| Canvas state | Trigger | Content | Actions |
|---|---|---|---|
| empty | No elements in the view | Centered: "Add the first container" (button), "Shortcut: N" | Add the first container |

**Last frame of a deadlock: highlight rule (decided: yes, NS §6.7 default kept for S0; D-34).** The UI renders `ReplayFrame.highlight` as sent and never computes it. The set is every element that owns a transition that waits and already holds a token in one of its pre places, plus the owners of the places those transitions wait for (a generated place's owner is its relationship). ## 8. Cross-cutting state rules

- **Long text:** names: 2 lines on the canvas, 24 characters in the net pane, full everywhere else. Paths: middle-truncated, selectable, with a copy action. Step texts and violation sentences: wrap, never truncated. Deadlock lists: scroll inside the row after 12 lines.
- **Large model:** 300 elements per view in S0–S2 (capture and U10); ≥ 1,000 elements per project from S3 (capture and U10), with lists virtualized and sized for 2,000. "Go to element…" is the main way to navigate. A layout-only edit shows no placeholder at all if keys arrive within 150 ms (§3.3, R12).
- **Theme:** follows the OS **[assumption, E3]**. If WebKitGTK under WSLg does not report it, the Theme commands appear (§6.1).
- **Motion:** none in S0–S2 apart from spinners, which are static with reduced motion. Pans are instant.

## 12. Validation plan

- **E6, U6 and U7 (one timed session):** model one real design of about 10 elements from New project to its first decisive verdict. Log I1 in minutes, Reload conflicts, parse errors, the time spent writing TOML, and the time from saving a TOML file to the net showing after Reload (U8 ≤ 1 s). Decision rule: I1 ≤ 45 min (U7). If TOML writing dominates, the first lever is "Copy behavior model template", then the slice 1 place form; the pattern library follows OST E6.
- **E7 and U5 (three Disproved verdicts on real designs, at least one with a full `block` place):** think aloud into the journal; name the root cause from the replay alone within 10 min, without opening TOML. Note which surface gave the answer (step list, canvas, pane) and whether the deadlock lines were right. Success: ≥ 2 of 3. If it fails, add the per-step explanation (OST E7).
- **First-use learnability (optional):** 2–3 developer peers, 20 min each, think aloud, tasks without hints: "Find out whether these two services can block each other." "Why is this Unknown, and what would you change?" "Make the queue between them apply back-pressure." Measure task success and errors; this finds problems, it does not produce metrics.
- **Accessibility:** AC-1 to AC-21 in CI where automatable (axe, keyboard runs, token contrast, the copy lint); a manual Orca pass per slice, NVDA from S1.
- **Guardrail:** FC-1 (U2) and AC-7 on every PR that touches verdict rendering.
