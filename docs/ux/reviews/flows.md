# Reviews and disposition: Flows and states spec

Author: senior UX designer.

## product manager: approve-with-changes

### Must fix
- Deadlock waiting lines can misstate the cause (§5 V-DIS-DL-W1..W4, §10 row 6). Under ADR 0014 a `block` place no longer uses complement places, so a transition held back by a full block post-place has no 'token it waits for'. E5 case 2 P3 (Cognito buffer) is exactly this pattern, and it is a core E7 case. As written, either V-DIS-DL-W4 depends on a backend change that is not confirmed, or the generic W1 form says 'waits for a token in <place>' when the transition is really waiting for room. That misleads the user about a Disproved. Fix: make the route to senior-backend-dev blocking for S0 (Violation::Deadlock must say whether each blocker is an empty pre-place or a full block post-place, design §3 line 79). Also specify fallback copy that never names the wrong cause, e.g. 'Billing cannot take step take_lock: it needs a token in lock_b or room in Order API → Billing (publishes to).'
- Model-incomplete causes are not feasible as specified (§4.9 U-INC-*, §5 U-INC-NOPORT and others, AC-8). Design §3 gives `ModelIncomplete(Vec<String>)` and `UnknownDto.details: string[]`, with example strings like 'Billing/take_lock not found'. Those are IDs, not names, and they cannot select an element. Brief §3.4 needs one line per cause that selects its element or relationship. Add a blocking [route: senior-backend-dev]: causes must be typed (kind plus ElementId, RelationshipId or QualifiedId) or must reference the `validate` Problems by ID, with names resolved at render time. Until then, U-INC-* copy is not buildable.
- Glossary violation in final copy (TXT-1 must). GLOSSARY lists 'State (when talking about Petri nets)' as an Avoid word. V-DIS-NOFINAL ('There are no end states yet…') is S0 copy, and §4.13's 'From every state, the system can get back to…' uses the same word. The S0 string came from my brief, which I will fix too. Suggested copy: 'There are no final markings yet, so a run that stops also counts as a deadlock. To model a run that finishes, loop back to the initial marking.' For §4.13: 'From every reachable marking, …'. Also extend AC-20 so the lint flags 'state' in Petri-net copy keys, not only the plain Avoid list.
- Stale verdicts can be read as current on secondary surfaces (S1; guardrail: never claim a verdict the tool did not get). §2.5 header-summary counts ('1 Disproved, 1 Proved') and §2.6 status announcements do not say how stale verdicts are counted. The §4.8 stale row renders 'the old verdict word', which a screen reader may read before 'Stale'. Specify three things. (a) Stale verdicts are never counted under Proved or Disproved in the summary; they show as 'N stale' or as 'Updating checks…'. (b) The accessible name of a stale row starts with 'Stale:' ('Stale: Proved, checked before your last behavior change'). (c) The grayscale capture (AC-6) includes `stale`.
- The draft misses parts of the brief. (1) Header: brief §2 lists the view title next to the project name and 'Level: Container'. §2.5 has no view title, and the S0 view title is the scope name that verdict rows refer to. (2) Inspector anatomy: brief §2.1 specifies the element inspector (name, element kind, description, the ports it offers, Copy file path, Open file) and the nothing-selected inspector (the renamable scope element and its properties through the keysFresh selector). The draft never specifies either one as a state table. Renaming the software system created from the folder name (brief §2.1 start screen) is therefore unspecified. (3) Placement of elements that arrive through Reload without a layout entry (ELK, only unplaced elements, saved at the next Save) is missing from §4.3 and §4.5.
- Keyboard map contradicts itself. §4.4 binds 'Go to relationship…' to Ctrl+Shift+P, but §2.7 and §6 use Ctrl+Shift+P for the command palette, and §6 binds 'Go to relationship…' to Ctrl+Shift+O. Choose Ctrl+Shift+O and fix §4.4.

### Should fix

- AC-14 (200 % UI zoom at 1440 × 900) adds scope. The effective viewport is 720 × 450, below the declared minimum of 1024 × 640 (WIN-1), and UX_STANDARDS does not require it for this solo tool. Keep Ctrl+= / Ctrl+- / Ctrl+0. Either cap AC-14 at 125 % at 1440 × 900 or make it a should rather than an S0 gate (see the question below).
- §4.5 'Copy behavior model template' [proposal] steps into the E6 decision. §11 itself calls the template the fallback if TOML writing dominates, and OST E6's response is the pattern library. If it ships in S0, U6 no longer measures the baseline that the brief says S0 provides. Hold it as the first lever after U6, or log in the journal whether it was used.

(Applied has only canUndo/canRedo). D-RESTORE 'the last at 14:32' (JournalRecord carries rev, not time). §3.3 and §4.1 'Reading 12 of 42 files' (Disk::read_tree returns all files at once, with no progress events). Either route each to senior-backend-dev with a [route] tag, or use copy that does not need the data: 'You have unsaved changes.', 'Undo', an indeterminate open progress indicator.
- Re-check progress 'Re-checking… 48,100 of 120,400 markings' (§4.7, V-RUN) assumes both explorers count the same state space. The recheck explorer is a plain BFS on its own composition, and once verify adds reductions (stubborn sets, pulled forward if E9 fails) the denominator is wrong and the bar can pass 100 %. Use an indeterminate bar with the count ('Re-checking… 48,100 markings') unless backend confirms that the counts are identical by design.
- PR-NOBM (§5, §10) produces noise. In a scope where no element has a behavior model yet, the Verdict panel says 'Nothing to check yet' (V-NOB) while the Problems list shows N 'has no behavior model' problems. That is two contradictory signals, and it is noisy during the first E6 minutes. List PR-NOBM only when at least one sibling has a behavior model, which is when it actually makes the scope Unknown under ADR 0010.
- D-CONF-DISK ('Your changes to Billing are discarded') hides scope. Relationships are stored in their source element's file (stack.md §4), so 'Use the file on disk' also discards in-app changes to Billing's outgoing relationships and port bindings. Say so: 'Your changes to Billing and its outgoing relationships are discarded, and the file on disk is loaded.'
- S3–S5 copy is marked final. §5 says 'All strings are final', but the header says S3–S5 get a full pass before their slice. Tag the S3–S5 copy (§4.12–4.14, E-INT 'Scan', the findings states) as draft, so no S0–S2 build or lint treats it as committed. Also state that the Findings tab and the Model tree are not rendered at all before their slice.
- Align the large-model target. §8 and §4.12 use 2,000 elements per project in S3, but brief §6 and UX_STANDARDS use ≥ 1,000. Use one number (≥ 1,000 for the capture, with virtualization sized for 2,000 if you want headroom) and say which one gates U10.
- Command catalog is missing. §2.7 says 'The full list is in §6', but §6 is the keyboard map and leaves out commands that have no shortcut: Copy file path, Open file, 'Replay counterexample: <property>', Exit replay, Cancel all checks [S1], 'Turn on local check log' [S1], Theme commands (conditional on E3). Brief §2 requires the palette to list every command. Add a table of commands with group, slice and shortcut.
- WebKitGTK and WebView2 default shortcuts. Besides Ctrl+R and F5, list the webview defaults that must be disabled or claimed: Ctrl+P (print, which collides with 'Go to element…'), Ctrl+F, Ctrl+Shift+I in release builds, and Ctrl+O and Ctrl+N if the webview binds them. Route to senior-frontend-dev.
- Pick one `--verdict-unknown` token: neutral, not 'neutral or amber'. Amber reads as a warning, and leaving it open invites drift at review time.
- AC-1 is not runnable as written in S0. Ports exist only after a behavior model is written in TOML, outside the app. Specify the fixture: three seed TOML files with nets, adopted through Reload, so the keyboard run binds ports and reaches a Disproved without a pointer and without leaving the app.
- U-DIS asks the user to 'Please report it'. In a solo tool the user is the developer, so make the copy actionable: 'Copy details and add this model to the differential corpus.' (E1 corpus).

## Decisions

- Deadlock waiting lines: R1 (typed blocker kind: empty pre-place vs full block post-place) is a blocking backend route for S0; until it lands the UI ships V-DIS-DL-FALLBACK, which states counts and when full but never a cause. — Under ADR 0014 a block place has no complement place, so 'waits for a token' can name the wrong cause in E5 case 2, which is a core E7 case. Inferring the cause in the UI would put domain logic in the UI, which design.md rejects.
- Model-incomplete causes and the Problems list need a typed ProblemDto (R2), and capacityExceededFirst needs a target (R4). Both are blocking for S0 with no shippable fallback; if refused, escalate to the product owner. — VRD-3 and brief §3.4 require per-cause next steps that select the element. Free strings such as 'Billing/take_lock not found' carry IDs and cannot select anything.
- Renamed the behavior model pane's 'Pin' toggle to 'Follow steps' (aria-pressed, on by default); choosing an element button in the step header turns it off. — 'pin' is a GLOSSARY Avoid word for Port and sits next to port markers (TXT-1 must). The exact label is copy, which I own, so I am not escalating it.
- The replay step list is a listbox with no interactive children and selection that follows focus. Element buttons move to a 'Current step' area in the step list header. Exactly one announcement per step: option name, scrubber aria-valuetext (full step text), or the live region for other controls. — Interactive chips inside options are presentational (WCAG 4.1.2). The draft would have announced each step two or three times, so AC-9 could not pass.
- Added D-CLOSE and a 'Close project' command. Open and New with a project open first show the folder dialog, then the save guard, then replace the project in the same window. — This closes a lost-work path (U9, CNV-5). Multiple windows are a non-goal. Folder-dialog-first means cancelling costs nothing (H3).
- Header collapse order at 1024: Commands to icon, then Save/Reload to icon buttons, then summary chips to icon+count, then truncate the view title and project name. Check, the unsaved text and the level never collapse. — WIN-1 must: the S1 header content was about 1,250 px. It fits in about 960 px after the collapse, and every collapsed control stays in the palette and has a tooltip (WIN-3).
- Stale verdicts are a separate selector result. They are counted as 'N stale' in the summary, never as current. The accessible name starts with 'Stale:' and stale is never announced. — This protects the guardrail (never claim a verdict the tool did not get) on secondary surfaces.
- The selector puts pending first, then nothingToCheck (backend key state R9), then { unknown }, running, matching verdict, and cached (undo restore). — Without cached, U12 fails. Putting pending first keeps every other branch from rendering keys that belong to another revision.
- Layout-only edits: request a behavior-neutral fast path (R12). The fallback delays the neutral placeholder by 150 ms with a reserved slot and never shows the old verdict. — Without it, every arrow-key move would blink every verdict to pending.
- Replay opens on 'Start: initial marking' only if the backend adds frame 0 (R5); otherwise it opens on step 1 as the brief says. The scrubber has n+1 positions and no copy ever says 'Step 0'. — Comparing a step with the marking before it helps E7, but the current ReplayFrame has no initial frame.
- Copy that needed data no event carries was rewritten or routed: 'You have unsaved changes.', 'Undo', an indeterminate open progress bar, 'Saved.' as a fallback, Reload names the changed elements, no restore timestamp, no budget line while running, indeterminate re-check with no denominator. — Both reviewers found that these copy strings rest on fields that do not exist. Re-check counts are not comparable across the two explorers' compositions.
- Viewport pans are always instant, and there is no motion in replay at all. — The brief has no animation in slices 0–2. This also removes a reduced-motion branch.
- AC-14 is split: 125% UI zoom at 1440×900 is an S0 gate (1152×720 CSS px, above the minimum). 200% is a should: no clipped text and every command reachable through the palette. There is no below-min layout in S0. — At 200% the viewport is 720×450 CSS px, below the declared minimum, and the §2.3 rules cannot hold there. This is a solo tool. The final call goes to the user.
- 'Copy behavior model template' is held as the first lever after the E6 baseline, not shipped in S0. — Shipping it would contaminate U6, the baseline that S0 is meant to provide.
- PR-NOBM is listed only when another element in the scope has a behavior model. — This avoids two contradictory signals (V-NOB and N problems) during the first E6 minutes, and the missing model only makes the scope Unknown in that case.
- --verdict-unknown is a neutral gray. There is a new --verdict-stale token. — Amber reads as a warning, and leaving the choice open invites drift.
- Added the missing brief parts: the view title in the header, element and nothing-selected inspector anatomy with state tables (including renaming the folder-named system), and ELK placement for elements that arrive through Reload (they mark the project unsaved). — The PM review found these omissions from brief §2 and §2.1.
- S3–S5 copy and surfaces are marked draft and are not rendered before their slice. The large-model target is 300 per view in S0–S2 and ≥1,000 per project from S3, with virtualization sized for 2,000. — This keeps S0–S2 builds and the copy lint from treating future copy as committed, and aligns with UX_STANDARDS.
- Added a full command catalog (§6.1) and a list of webview default shortcuts to claim, with the frontend's implementation answer (capture-phase handler, prevent-default plugin on WebView2, setZoom-based UI zoom). — The brief requires every command in the palette, and Ctrl+P (print) and Alt+← (history navigation) would break the app.
- AC-20 becomes a curated deny-list lint with word-sense exceptions and a 'state' check for Petri-net copy. The landmark is renamed 'Messages', and the S5 example rule is renamed to avoid 'timeout'. — A literal Avoid-word lint fails on 'Open file' and 'Status', so CI could never pass it.
- V-PRO-ASM assumptions are derived from the projection, shown only when the verdict is current. — A current verdict means the keys are fresh for this revision, so the projection is the model that was checked. The backend may move the list into the DTO later (R17).
- Added an S0 AC-1 fixture (seed TOML nets adopted at open and by Reload) and flow guardrails FC-1 to FC-6. — Ports only exist after TOML is written outside the app, so AC-1 could not run as written. Lost-work and honesty rules need testable statements too.
