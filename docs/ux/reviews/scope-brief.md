# Reviews and disposition: UX scope brief

Author: product manager.

## senior UX designer: approve-with-changes

### Must fix
- §6 last bullet and §2.1 Canvas states: the brief changes the UX_STANDARDS Capture state `large-model` from at least 1,000 elements to 300 elements in one view. Only the drill-down half of that change is tagged. UX_STANDARDS is binding, and a scope brief cannot quietly redefine one of its states. The reason is sound: slices 0–2 have one view and CLAUDE.md sets a target of 300 elements per view. Fix: tag the whole change **[proposal]**, state that it amends UX_STANDARDS Capture for slices 0–2, and name who edits UX_STANDARDS.md. Also add UX_STANDARDS' required `error` state to the canvas, which §2.1 leaves out. Describe how a relationship with a dangling end (`danglingEnd`, design §5) looks on the canvas, and what the canvas keeps showing after a Reload hits a parse error (design §4: the in-memory Model is kept).
- §6 does not cover CNV-5 (a must rule). Slice 0 has no file watcher (design §10, v1-slices Out), so a hand edit to a TOML file is not announced until Save or Reload. Hand-editing TOML is the main E6 loop in slice 0. Fix: add a CNV-5 line to §6. Either (a) state a tagged exception for slice 0, 'announced at Save and at Reload, never overwritten (Save re-hashes; design §4)', or (b) propose a cheap re-hash when the window regains focus that shows a non-blocking bar, '<file> changed on disk. Reload to see it.' Option (b) needs the software architect's agreement, because slice 0 is designed without a watcher.
- §2.1 Header and Save and the §2 Dialogs row: the slice 0 conflict branch has no exit. Save reports '<file> changed on disk since it was loaded. Reload first.' Reload with a dirty entity then opens a dialog that 'lists every conflict', but its choices are not specified. Design §4 says slice 0 uses a confirm dialog over all conflicts with keep mine / take disk, and the draft only gives those choices in slice 1. Fix: specify the slice 0 dialog with a per-file choice and button labels, for example 'Keep my changes' and 'Use the file on disk'. State that choosing 'Keep my changes' lets the next Save write the file. Also specify the quit path: 'Save and quit' followed by a conflict must not quit, and must show the conflict.
- §2.1 Inspector, Element copy: 'No behavior model. Add it in elements/<id>.toml, then Reload.' does not work for an element created since the last Save, because its file does not exist on disk yet. Editing the file of an element with unsaved changes also produces exactly the Reload conflict above. Fix: when the element is unsaved, the copy reads 'Save, then add a behavior model in elements/<id>.toml and choose Reload.' When the element is saved and clean, it reads as now. Add a 'Copy file path' action here and on Problems list lines. Recognition over recall: this is the E6 loop.
- §3.3 'Overflow place present' is in the wrong section, and that placement misleads about verdicts. Under ADR 0014 and design §6, an overflow marking is never expanded, so a Disproved deadlock-free is always reached before any overflow. A Proved deadlock-free requires that no overflow marking is reachable, so it covers all behavior. The 'covers only the behavior before the first overflow' sentence therefore belongs only to Unknown 'capacity exceeded first'. On a Proved row it would understate the verdict and suggest that overflow is possible. On a Disproved row it is wrong. Fix: move the sentence into the §3.4 'capacity exceeded first' row, for example: 'Deadlock-free was decided only up to the first time <relationship> exceeds capacity 3. Set when full to block or drop, or raise the capacity.' State explicitly that Proved and Disproved rows carry no overflow caveat.

### Should fix
- §3.2 Pending re-evaluation: keysFresh compares revisions (design §4), so every gesture, including a layout-only move, makes every row pending until `currentKeys` arrives. Specify the row so it never flickers and never shows the old verdict: fixed row height, the property and scope stay, a neutral placeholder takes the place of the verdict icon and text, and nothing is sent to an aria-live region. Add a long-pending variant (for example, after about 1 s show 'Updating checks…'). This stops an implementer from 'fixing' the flicker by showing the old verdict, which would break U2.
- §3.2 No verdict yet: when a behavior edit removes a verdict, the row says nothing about why it disappeared, and slice 0 cannot show it as stale. Add a neutral line that is not a verdict, for example 'Behavior changed since the last check.', next to the Check action. This keeps J2 understandable without breaking `v1-slices.md:24`.
- §3.4 lists 'cancelled' under 'reasons that slice 0 can produce', but slice 0 has no Cancel. A system cancellation on a key change belongs to an old key and is never rendered as current (design §4). Move the row to slice 1. Also make the 'model incomplete' next step depend on the cause: an unbound port is fixed in the relationship inspector, a dangling relationship on the canvas, and a missing when full in the file. Say where 'block or drop' is set in slice 0: the relationship inspector for generated places, the TOML file for places inside a behavior model. Say which local log 'internal error' points to (the crash log from ADR 0006/0012, not the slice 1 check log), and add 'Copy details'.
- §3.2 Proved copy: add the scope of the claim, as E5 implication 5 warns: 'Holds for every order of steps with the capacities and initial tokens in this model. Time and rates are not modeled.' Case 3 in E5 shows that verdicts change with fleet size, which is the initial marking.
- §2.1 Replay and E7: step text such as 'Billing fires take_lock' uses net terms. Write text patterns in architecture terms for each step kind: own transition, fused synchronous step (for example 'Order API → Billing (calls): reserve'), asynchronous send or receive with the count ('Order API → Billing: 2 of 3 messages'), and the last step. Name relationships as 'From → To (meaning)'. Also specify: (1) which element the behavior model pane shows during replay; (2) how arrow keys are split between canvas navigation (A11Y-3) and replay stepping; (3) what happens when an edit removes the verdict during replay (exit, with the message 'Replay closed: behavior changed'); (4) highlights that are not color-only and reach 3:1 contrast (A11Y-1).
- §2 layout at 1024 × 640: four regions compete for space (inspector, Verdict panel, behavior model pane, Problems list), and the Problems list and the replay step list have no defined place. Specify which regions collapse and how they reopen (a visible button plus a shortcut). Specify the pane height at a height of 640, and a summary in the header while panels are collapsed, for example 'Deadlock-free: Disproved' with its icon and a Problems count. Add a polite announcement when a verdict arrives. Port handles must be visible without hover (WIN-3).
- Non-ideal states for Open, Save and Reload are missing. Open: a folder that is not a project, a project with a newer format version, a project that loads with problems (it opens and shows the Problems list, per ADR 0001), and a loading state. New project: a folder that is not empty, and where the software system's name comes from and where it is renamed. Save: in progress (the unsaved marker stays until the `saved` event), a specific success message ('Saved 3 files'), and partial failure. Slice 1: the restore state after a crash during restore, which offers only 'Open without restoring' (design §4).
- Copy: 'Restore N gestures' and 'keep mine / take disk' are internal terms. Use 'Restore 3 unsaved changes' / 'Open without restoring' and 'Keep my changes' / 'Use the file on disk'. Show the level label as 'Level: Container' so it is not confused with the element kind Container. CNV-1 in §6: say that the level part applies from slice 0 and the breadcrumb and go up start in slice 3, rather than 'starts with slice 3'.
- §2.1 Inspector, port binding: specify these states: an element without ports ('Billing has no behavior model yet'), incompatible port kinds, and an unbound port (which turns every property in the scope into Unknown 'model incomplete'). Without them, E6 users meet Unknown with no explanation at the point where they bind ports.
- §7 U1: Playwright with mocked IPC cannot show engine behavior such as the independent replay or the budget. Measure U1 with Rust-written fixtures for the UI, plus the WebdriverIO end-to-end smoke test per slice (design §8). Add a capture matrix with the extra state names (`pending`, `no-verdict`, `stale`, `replay`, conflict dialogs) so U11 can be checked against UX_STANDARDS file naming. Map 'Checking' to the capture state `running`.
- §4 and §9, checks only on Check: from slice 1, ADR 0013 and design §4 resubmit an undo-restored key that has no cached verdict automatically. State this exception so the slice 0 proposal does not get applied beyond slice 0.
- §8 non-goals: tag the items that come from no settled doc as **[proposal]**: recent projects, reopening the last project, element search, and minimap. Consider a cheap 'Go to element' command in cmdk instead of search. At 300 elements, moving between elements with the keyboard alone (A11Y-3) is slow without it.
- §2.1 Theme: tag 'follows the OS' as **[assumption]**. prefers-color-scheme in WebKitGTK under WSLg depends on the GTK theme. If E3 shows that it does not follow the OS, add a palette command for the theme as a fallback.

## senior frontend developer: approve-with-changes

### Must fix
- Empty or behavior-less scope produces a wrong-looking verdict (§2.1 Start screen, §3.2). A new project creates a system with zero children, and 'Opening a project queues every property' (design §4). ADR 0010 defines a combined scope as needing every child to have a behavior model, and an empty child set passes that vacuously. Deadlock is 'no transition enabled and the marking is not final', and there are no finals before slice 4. So the empty net is Disproved deadlock-free with a 0-step counterexample as the first thing a new user sees, and the I1 clock starts on it. Fix: add a Verdict panel state 'Nothing to check yet: no element in this view has a behavior model' (no verdict icon). Ask senior-backend-dev to make lowering of a scope with no behavior return a typed reason rather than an empty net. Add the matching seed to U3.
- Replay has no lifecycle once its verdict stops being current (§2.1 Replay, §3.2). In slice 0, a canvas edit, an inspector edit or a Reload during replay either makes keys non-fresh (pending re-evaluation) or removes the verdict (v1-slices:24). The brief does not say what the open replay does then, so it would keep showing highlights and a violation sentence for a verdict that is no longer current, which breaks the §1 guardrail. Fix: pick one. (a) Replay mode makes the canvas and inspector read-only and shows 'Exit replay to edit'. (b) Any apply ends replay with the polite announcement 'Replay closed: the model changed'. Also scope the arrow keys: React Flow 12 moves selected nodes with the arrow keys by default, and the brief binds the same keys to replay steps. Inside replay, the arrows step and node moving is disabled.
- The 'held by Shipping' part of the deadlock sentence (§3.3) has no source in the contract and can mislead. Violation::Deadlock carries only waiting transitions and the places they lack (design §3, `waiting: Vec<(QualifiedId, Vec<QualifiedId>)>`). 'Held by' is not defined for P/T nets, and inferring it on the UI side (for example from which element owns a marked place) would be a heuristic inside a verdict sentence, the exact place E7 relies on for root cause. Fix: in slice 0 say only 'Billing waits at take_lock for a token in lock_b', and show the marked places in the behavior model pane. If 'held by' is wanted, senior-backend-dev must add it to ViolationDto with a defined rule (for example a P-semiflow that covers the missing place), and it must be re-checked like other evidence.
- A Reload parse error leaves verdicts looking current for a model that no longer matches the files (§2.1 Problems list, U8). Design §4 says 'A parse error is reported and the in-memory Model is kept'. In the E6 TOML-edit and Reload loop, a user who breaks billing.toml still sees the old Proved as current and reads it as the verdict for their edit, which is a wrong Proved in the user's mind. Fix: define a 'files not loaded' state. While any parse error is outstanding, the Verdict panel shows a banner above the rows: 'Verdicts are for the last version that loaded. elements/billing.toml has an error (line 12: …). Fix it and choose Reload.' The Problems line links to the same file.
- §6 rewrites binding UX_STANDARDS rules inside a PM brief. It changes the Capture state `large-model` from ≥ 1,000 to 300 elements and defers CNV-1/CNV-2. It also does not mention that without a watcher, slice 0 can announce a disk change (CNV-5) only at Save or Reload time. UX_STANDARDS 'How to review' gives the reviewer a fresh context and only UX_STANDARDS, so every slice 0 review would raise CNV-1 must and capture a 1,000-element view that cannot exist. I agree with 300: it is the E4 per-view target and the only view in slices 0–2. Fix: tag all of §6 [proposal] and route it as an amendment to UX_STANDARDS (a per-slice applicability table plus `large-model` = 300 per view until slice 3) for the product owner to approve.
- VRD-3 next steps cannot be acted on in this slice (§3.4). 'Split the scope' needs drill-down, which arrives in slice 3, and budgets cannot be changed (§8 non-goal). 'cancelled' sits in a table headed 'reasons that slice 0 can produce', but slice 0 has no cancel, and a key-change cancel drops the verdict rather than showing it. Fix: the budget-exhausted next step becomes 'Lower capacities or initial tokens, or remove elements from this view'. Move 'cancelled' to slice 1. For internal error, name the panic log path, which is different from the opt-in 'local check log' in §4.
- The A11Y-3 (must) keyboard path and element placement are unspecified, and the §8 non-goal blocks the obvious fix. (1) 'Keyboard-only path' (§2.1 Canvas) needs concrete surfaces. Connect: select the source element, then 'Add relationship…' in the palette or inspector, then pick the target in a combobox. Move: arrow keys with a grid step. Navigate: a palette command 'Select element…', because tabbing through 300 nodes does not work, so 'element search' must not be a non-goal in this form. (2) An element created from the keyboard or palette has no pointer position, and an element that arrives through Reload or hand-written TOML without a layout entry has none either (stack.md §4.4: a missing entry means 'needs layout'). Fix: state a placement rule (the next free grid slot near the viewport center, or ELK for unplaced elements only). Reword the non-goal to 'no whole-view auto-layout command'.
- U1 cannot be measured as written. UX_STANDARDS Capture runs Playwright against Vite with Tauri IPC mocked from fixtures, which can show that fixtures render but cannot show that the engine yields Disproved or Proved for the acceptance criteria, or that Save and reopen round-trips. Design §8 already plans a real-app WebdriverIO smoke test. Fix: split U1 into (a) a Playwright run per criterion on Rust-written fixtures, covering states and copy, and (b) a tauri-driver/WebdriverIO scenario per v1-slices acceptance criterion on Linux, run against the seed projects.

### Should fix
- 'Pending re-evaluation' will flash on every edit (§3.2). Every apply, including a move or rename, advances the projection rev before currentKeys arrives (design §4), so both rows switch to pending and back on each pointerup. Pending cannot be debounced, because the verdict must not render as current in the meantime. Specify that pending keeps the row height and position, swaps only the icon and badge in place, and is never sent to aria-live. Only final verdicts are announced politely ('Deadlock-free: Disproved'). Add a criterion: a layout-only edit is pending for < 100 ms p95 at 300 elements. Also require that every surface that shows a verdict (the nothing-selected inspector, any canvas badge) uses the same keysFresh selector, and extend U2 to cover those surfaces.
- The layout at 1024 × 640 is not specified (§2, WIN-1 must). The brief has two side regions, a behavior model pane below the canvas and a replay step list with no placement. E7 needs the canvas, the step list and the pane's tokens visible at once. Proposal: one right-hand region with tabs (Inspector | Verdicts) where the replay step list replaces the Verdict panel content during replay, and a resizable pane with a minimum height that collapses to a header strip below about 700 px of window height. The pane takes height, not width, so the half-width rule of WIN-1 still holds.
- Parallel and antiparallel relationships are missing from the canvas states. BindPorts binds one port pair per relationship (design §3), and E5 case 1 needs 8 sync bindings among 5 elements, including control_plane→cluster_a and back. React Flow draws such edges exactly on top of each other. Add the canvas state 'several relationships between the same two elements' (custom edge with an offset and its own label). Also define how a relationship is named in copy ('Order API → Billing'), the step text for fused steps (both sides) and async steps ('Order API sends to Billing: 2 of 3'), and the 'capacity exceeded' sentence for a place inside a behavior model, not only for generated places. Avoid 'fires' unless it gets a plain-language explanation (TXT-3), and do the same for 'markings' in the Proved row.
- The behavior model pane needs replay and layout rules (§2.1). During replay of a two-element deadlock, it is unclear which net the pane shows. Proposal: by default it follows the element that fired in the current step, with a 'Pin' toggle. With no saved layout in slice 0, elkjs recomputes on every Reload, so nodes jump around and slow the E6 edit loop. Require stable output (ELK model-order options, previous positions as seeds), a worker-side layout cached per net hash, and a 'Laying out…' loading state so a selection change never blocks the canvas.
- Place the ADR 0014 overflow caveat precisely (§3.3). A Proved deadlock-free already means no overflow marking is reachable, so the caveat belongs on Unknown 'capacity exceeded first' and on Disproved deadlock-free, not on every row of a model that has an overflow place. Also state on Disproved deadlock-free that until slice 4 there are no final markings, so a design that finishes counts as a deadlock, and suggest 'loop back to the start' as the workaround. This directly affects E7's 10-minute root cause.
- There is no surface for transient messages. The design emits `saved` (with conflicts and failed files), `internalError` (including a lost derive record) and, from slice 1, disk adoptions ('the user is told', §4). Add a status or toast region with role=status (polite), placed so it never covers a focus stop (A11Y-2), plus a 'Saving…' state in the header, because Save completes asynchronously and coalesces.
- Elements without a behavior model block the whole scope (ADR 0010: in a combined scope every child must have one, otherwise model incomplete). Offering Database and Queue kinds (§2.1) invites drawing elements without nets, which turns both checks Unknown and costs E6 minutes. Show a 'No behavior model' badge (icon plus text) on such elements, and make each model-incomplete line select its element. See the question below on whether the ADR should change.
- Keep checks queued automatically where they already are. The 'checks only on Check' proposal (§2.1, §9) must keep two automatic queues: the open-project queue (ADR 0005) and the ADR 0013 rule that a key restored by undo with no cached verdict is resubmitted (slice 1). Otherwise U12 and the slice 1 acceptance criterion conflict with the proposal.
- The E6 loop has a Reload trap. If an inspector edit (port binding, capacity) dirties an element whose TOML the user then edits by hand, Reload opens the conflict dialog every time (design §4: a dirty entity whose file changed is a conflict). Ask senior-backend-dev whether conflicts can be detected per entity table rather than per file. In the UX, offer 'Save, then Reload' as the primary dialog action, and add an 'Open file' action (tauri-plugin-opener) in the inspector and the Problems list.
- Theme: with no picker, WebKitGTK under WSLg may never report dark through prefers-color-scheme or the Tauri theme, which is unverified per stack.md §1.10. Add palette commands 'Theme: System / Light / Dark'. This is not a settings screen.
- Make U10 measurable. Replace 'without visible stutter' with a number from the E4 harness on WebKitGTK, for example p95 frame time < 33 ms during a scripted pan and zoom over the 300-element seed. Add seed fixtures for each Unknown reason so U3 can actually reach 100 %. Cover long content: long element names truncate on nodes and appear in full in the inspector (WIN-3, no hover-only text), and a deadlock with 10 or more waiting lines scrolls inside the row.

### Questions for the user
- Side regions: one right-hand column with Inspector and Verdicts tabs (my recommendation for 1024 × 640 and for E7 replay), or the inspector on the left and the Verdict panel on the right?
- An empty scope, or one with no behavior models: should the engine return a typed non-verdict ('Nothing to check yet') or Unknown 'model incomplete: no element has a behavior model'? This needs senior-backend-dev, because today an empty net is Disproved deadlock-free.
- Should elements with no behavior model and no bound ports (a typical Database) stay a hard 'model incomplete' as ADR 0010 says, or be left out of the combined scope and listed as an assumption? The second option needs an ADR change through software-architect, and it decides whether the Database and Queue kinds help or hurt E6.
- Do you approve amending UX_STANDARDS so that `large-model` is 300 elements per view until slice 3 and CNV-1/CNV-2 apply from slice 3, instead of keeping these per-slice exceptions only in this brief?
- Deadlock sentence: drop 'held by <element>' in slice 0, or ask the backend to compute it with a defined, re-checked rule?

## Decisions

- Tag the whole per-slice application of UX_STANDARDS (large-model = 300 per view, CNV-1/CNV-2, CNV-5, VRD-4/5/6, A11Y-3) as a proposed amendment to UX_STANDARDS.md: the product owner approves it and the senior UX designer writes it in. The brief no longer redefines binding rules. — Both reviewers flagged it as a must-fix. UX_STANDARDS is binding, and a reviewer who reads only that file would raise false must findings in every slice 0 review.
- CNV-5 in slice 0: disk changes are announced at Save and at Reload and are never overwritten. There is no re-hash when the window regains focus. — Slice 0 has no watcher, which is settled in design §10 and v1-slices Out. Save already re-hashes every file, so nothing can be lost silently. Adding the focus re-hash would reopen a settled decision for little gain.
- Specify the slice 0 conflict dialog with a choice per file, 'Keep my changes' or 'Use the file on disk', and state the consequence of each. 'Save and quit' does not quit on a conflict. — Design §4 already requires a confirm dialog in slice 0. Without specified choices, the conflict branch has no exit, and U9 (no lost work) cannot be tested.
- Do not offer 'Save, then Reload' as the primary conflict action. Instead, prevent the conflict: the inspector warns before the user edits the file of a dirty element, and per-table conflict detection is routed to senior-backend-dev. — Save skips a file that changed on disk (design §4), so 'Save, then Reload' would not resolve the conflict. Relationships live in the source element's file (stack.md §4), so the trap is on the main E6 path.
- A scope with no behavior model shows a neutral 'Nothing to check yet' row, driven by a typed reason from lowering (routed to senior-backend-dev). — Today an empty net is Disproved deadlock-free with a 0-step counterexample. That is a wrong-looking verdict on the very first screen a new user sees, and it breaks the guardrail.
- Replay is read-only. A Reload or any other change to the model closes the replay with the message 'Replay closed: the model changed'. In replay, the arrow keys step through the replay and never move elements. — A replay that stays open after its verdict stops being current would show a non-current verdict as current. Read-only mode also resolves the arrow-key clash with React Flow.
- Drop 'held by <element>' from deadlock sentences in slices 0–2. — Violation::Deadlock carries no holder. Inferring one in the UI would put a heuristic inside a verdict sentence, which is exactly what E7 relies on for root cause.
- The overflow caveat appears only on Unknown 'capacity exceeded first'. Proved and Disproved rows carry none. — Under ADR 0014, a Disproved is reached before any overflow, and a Proved means no overflow marking is reachable. On those rows the caveat would understate or misstate the verdict. ADR 0014 line 13's 'verdict panel says so' is met by the Unknown row.
- Add a 'files not loaded' banner while a parse error is outstanding. — Design §4 keeps the in-memory model after a parse error. In the E6 Reload loop, the old Proved would otherwise be read as the verdict for the user's latest edit.
- Split U1 into Playwright on fixtures (states and copy) and one WebdriverIO scenario per acceptance criterion. Make U10 numeric and add U13 (pending < 100 ms). — Mocked IPC cannot show engine behavior. Design §8 already plans the WebdriverIO smoke test. 'Without visible stutter' cannot be tested.
- Proposed layout: one right-hand column with Inspector and Verdicts tabs, a bottom pane with Behavior model and Problems tabs, and a header summary while regions are collapsed. Tagged as a proposal for the senior UX designer to confirm. — WIN-1 is a must rule, and E7 needs the canvas, the step list and the tokens visible at 1024 × 640. Layout is UX-owned, so the PM sets the requirement and proposes the shape.
- Theme: follow the OS [assumption]. Palette theme commands are added only if E3 shows that WebKitGTK does not follow the OS. — This keeps scope minimal. The fallback is cheap and ready if the assumption fails.
- Keep 'Open file' (tauri-plugin-opener) as a proposal and adopt 'Copy file path' outright. — Both serve the E6 loop. The opener is a new plugin dependency, although stack.md already lists it as relevant.
